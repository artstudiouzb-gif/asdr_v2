# ArtStudio CMS — заметки для Claude

Цель файла: быстрый старт без перечитывания всей ветки. Здесь — карта проекта,
договорённости и команды. Обновляй при заметных изменениях архитектуры.

## Что это
Госсайт «Агентство стратегического развития…». Боевой адрес — **asdr.uz**,
тестовый — **artstudio.uz** (прежний asr.artstudio.uz больше не существует).
Из облачного контейнера оба закрыты сетевой политикой окружения.
Собственная CMS: **чистый PHP 8.4+ без runtime-зависимостей Composer**,
MySQL/MariaDB. Composer/PHPStan и npm/Playwright нужны только разработке и CI. Свой
автозагрузчик (`app/Core/bootstrap.php`), свой роутер (`public/index.php`),
свой тест-раннер. Деплой — shared-хостинг (cPanel), поэтому: никаких внешних
зависимостей времени выполнения, всё работает на голом PHP+cURL.

## Режим экономии (по умолчанию)
Владелец бережёт лимиты. Работать максимально экономно по токенам:
- Минимум лишних чтений: сначала `CLAUDE.md`, потом точечно нужный файл (Grep/Read
  диапазона), не «осматривать» всю ветку. Не перечитывать то, что уже видел.
- Не проверять то, что не менял. Верификация — соразмерно правке (мелкая CSS-правка
  не требует полного smoke). Для проверки сайта — `scripts/smoke.php`, а не ручные скрины.
- Ответы короткие и по делу, без длинных пересказов и списков опций. Не гонять
  тесты/сборки без причины. Батчить независимые вызовы инструментов в один шаг.

## Договорённости с владельцем (важно)
- Работать **автономно**, не переспрашивать по мелочам; решения объяснять кратко.
- **Не всё делать буквально**: если просьба спорна — сначала коротко объяснить,
  почему стоит/не стоит, потом делать.
- Перед изменениями синхронизировать `main`, работать в отдельной тематической
  ветке и доводить работу до `main` **только через PR — всегда, без
  исключений**. Прямой push в `main` запрещён: на репозитории включено правило
  «Changes must be made through a pull request», и push его обходит (GitHub
  пишет в журнал `Bypassed rule violations`).
  Полный цикл — не «создать PR и остановиться», а довести до конца:
  ветка → PR → **подписка на события PR** (`subscribe_pr_activity`) →
  чинить падения CI и отвечать на комментарии ревью → мерж по зелёному CI.
  Оставлять висящий PR и ждать, что его вольёт владелец, не нужно.
- Влитый PR закрыт и новые коммиты не отслеживает. Если работа продолжается
  после мержа — это новая ветка от свежего `main` и новый PR, а не push в
  старую ветку (иначе коммит уходит «в никуда»: именно так потерялся фикс
  контраста после PR #129).
- **Не переводить админку** (интерфейс админки — по-русски). Переводится только
  публичная часть (RU=ключ, UZ-словарь) и контент (per-language в БД).
- Коммиты — короткие и осмысленные; не добавлять служебные идентификаторы
  модели или сессии в коммиты, PR, код и артефакты.
- **Не хардкодить бренд-акцент** `--gov-teal` (он настраивается в админке через
  `--color-accent`). Для затемнений использовать `color-mix`, не фикс-цвет.

## Как запустить локально

Нужны PHP 8.4+ и MySQL/MariaDB. В Linux-контейнере БД при необходимости
поднимается отдельно; встроенный PHP-сервер запускается с router-файлом,
поскольку он не читает `.htaccess`.
```bash
sudo service mariadb start                     # или: mysqld_safe &
php -S 127.0.0.1:8000 -t public public/router.php
```
Базы: `asdr_cms` (демо-контент), `asdr_test` (для тестов — имя жёстко ждут
тесты и CI, `tests/load_schema.php asdr_test` заливает схему). Доступ
root@127.0.0.1 без пароля. Если админ-пароль неизвестен — сбросить в БД
(`users.password_hash`, `password_hash()`), логин `admin`.

## Проверки (вместо ручного клика)
```bash
# Полный прогон всего набора (число сценариев объявлено в README — второй
# копии здесь не держим). Сценарии, которым нужна база, без доступа к ней
# помечаются пропущенными — именно пропущенными, а не молча пройденными
TEST_DB_HOST=127.0.0.1 TEST_DB_DATABASE=asdr_test TEST_DB_USERNAME=root TEST_DB_PASSWORD= php tests/run.php

# Smoke-обход всего сайта (HTTP+PHP-фаталы), RU+UZ, публичка и вся админка.
# --totp обязателен, когда у админа включено приложение-аутентификатор:
# без него обход не проходит второй фактор и админку просто пропускает.
php scripts/smoke.php http://127.0.0.1:8000 --admin admin:ПАРОЛЬ --totp СЕКРЕТ
```
На боевом сервере к этому добавляются `scripts/release_check.php` (в т.ч. DNS
почты SPF/DKIM/DMARC, свежесть репетиции восстановления, наличие эталона
целостности) и `app/Console/integrity_check.php` — почасовая сверка SHA-256
файлов кода с эталоном, алерт в Telegram при подмене (`App\Core\Integrity`,
эталон пересобирает `scripts/release.php`).

После правок PHP: `php -l <файл>`. Сброс кэша страниц: `rm -rf storage/cache/page/*`
(в админке — кнопка «Сброс кэша» в шапке).

## Навык impeccable (дизайн-ревью)
Установлен в `.claude/skills/impeccable` (Apache 2.0, pbakaus/impeccable) — вызов
`/impeccable`, полезен как второй взгляд на публичную часть. В релизный архив не
попадает (`/.claude export-ignore`). Его предложения принимаются только в рамках
проекта: акцент берётся из админки (`--color-accent`), инлайн-стили в блоках
запрещены тестами (scoped CSS через `$templateCss`), анимации уважают
`prefers-reduced-motion` и настройку «остановка анимаций», контраст текста не
ниже 4.5:1, после правок CSS/JS — `npm run build:assets`. Админку не трогаем.

## Бюджеты качества (`tests/budgets.php`, навык `quality-budgets`)
Одиннадцать с лишним величин **могут только уменьшаться** (`!important`, классы
без правил, жёсткие радиусы, эталон PHPStan, вес бандлов и т.д.). Величина
объявляется **один раз** в `quality_budgets()`; сторожа читают
`quality_budget('<id>')`, отчёт — `php .claude/skills/quality-budgets/report.php`.
Своих чисел в тестах не держим; новый бюджет ставится по факту, без запаса.

## Карта кода
- **Блоки**: реестр `BlockTypeRegistry`, рендер `BlockRenderer` (`enrichData()` —
  блоки-обёртки с данными из БД), шаблоны `templates/blocks/*.php`, форма
  `app/Views/admin/pages/block_form.php`, сохранение
  `Admin/BlockController::collectData()`. Контейнеры `columns`/`tabs` —
  вложенные блоки (`parent_block_id` + `column_index`), рендер программный.
- **Модели** `app/Models/*` (Page, News, Project = страница с
  `entity_type=project`, PhotoAlbum, TeamMember, Goal, …); статусы
  published/draft, мягкое удаление. Любой список по `pages` фильтрует тип.
- **Обложки**: тип контента `hero` (`/admin/heroes`, `App\Core\Hero\*`) и блок
  `hero_v2` (`HeroV2` → тот же `HeroRenderer`, `blocks/hero.css`, `blocks/hero.js`).
- **Фронт**: `frontend.css` (база) → `gov-theme.css` (тема) → `public-layout-polish.css`
  → `public-editorial-pages.css`; JS — `frontend.js`. Собираются в
  `public.min.css/js` командой `npm run build:assets`, CI проверяет
  `npm run check:assets`. Блочные ассеты — `AssetCollector`.
- **Админка**: `admin.css` + `admin-shell-v2.css`, `admin.js` (крупные два
  собираются в `admin.min.*` той же `build:assets` и встают на место исходника —
  `FrontendAssets::adminAsset`; общие слои-патчи вместе с ними склеены в
  `admin.bundle.min.*` — `FrontendAssets::adminBundle`, без сборки их грузит
  `admin-media-loader.js`; новый глобальный слой — строка в `adminBundles`); UI-помощники
  `AdminUi` (`imageField`, `colorField`, `navigationIcon`).
- **Шапка/подвал**: `HeaderConfig`/`FooterConfig`, вьюхи `site/_header.php`,
  `_footer.php`. **Иконки**: `Icon::render()` + `Icon::injectSprite()`;
  иконки из JS — в `Icon::RUNTIME_ICONS`.
- **Миграции**: `database/migrations/*.sql` + `database/migrate.php`.
- **CI** (`.github/workflows/ci.yml`): php -l и тесты на PHP 8.4/8.5 с MariaDB;
  PHPStan **блокирующий** (`composer analyse`, уровень 7) + `composer audit`;
  `node --check`; browser smoke на Chromium. `Deprecated` в журналах роняет сборку.

## Ключевые правила (нарушить легко, тест упадёт)
**Блоки и контент**
- Настройка блока объявляется **один раз** — в `BlockFieldSchema` (`Field::*`);
  шаблон читает `$data` как есть. Вне схемы — `text`, `html`, `form`, `hero`
  (бюджет `blocks_off_schema`). Тесты «настройка доступна» читают
  `block_editor_markup()` (т. 275). Зависимое поле — `Field::onlyWhen`.
- Каждая настройка обложки обязана менять вывод (т. 269); новая — получает пробу.
- Ключи блоков в фикстурах совпадают с `BlockTypeRegistry::DEFAULTS` (т. 227).
- Первый блок страницы и вложенные блоки — без появления при скролле (т. 289, 107).
- Инлайн-стили в шаблонах блоков запрещены — только scoped CSS (`$templateCss`).
  Атрибут `style` в публичной разметке не выводим вовсе: значения рендера
  (фокус картинки, цвет метки, процент) — `StyleVars::apply()` (т. 362).
- Перевод: механизм А (`*_translations`) и Б (отдельная запись с
  `translation_group_id`). Новый код спрашивает `App\Core\Translations`, а не
  собирает своё. Наложение — `Translations::overlayFields` (т. 183).
- Публичные строки — через `t()`, ключ обязан быть в словарях (т. 74), включая
  умолчания конструкторов. **Админку не переводим.**
- `*слово*` и `|` в заголовках — только в декоративных (`TitleMarkup`); в
  заголовке новости их нет (он уходит в RSS/Telegram/meta).
- `schema.sql` совпадает с миграциями: колонки в CREATE TABLE и файл в
  `INSERT INTO migrations` (тест консистентности).

**CSS и фронт**
- Акцент не хардкодим: голое `var(--gov-teal)`/`--gov-teal-text`/`--gov-navy`
  без запасного значения; числа живут только в `:root` начала `gov-theme.css` (т. 345).
- `font-size` — только ступени `--step-*` (т. 236); переломы — только
  `480/560/640/720/900/1000/1100/1360` (+1 для `min-width`), кроме 768/769 у
  `BlockVisibility` (т. 232).
- Скругления — `var(--radius…)`, тень покоя — `var(--card-shadow, …)`.
- Режимный класс на `<body>` — внутри `:where()` (т. 262). Дубли селектора в
  одном контексте запрещены (т. 262). `@layer`, `text-wrap: balance`,
  JS-«плавную прокрутку» и SPA не вводим.
- Правила частей темы берут цвет секции: `var(--section-*, <токен>)` (т. 274);
  выносить часть темы — только если поздние файлы её не трогают (т. 262),
  тесты читают `theme_css()`.
- Анимации уважают `prefers-reduced-motion` и `asdrReduceMotion()`; `transition`
  с CSS-переменной — только longhand (минификатор выбрасывает сокращение).
- Контраст текста ≥ 4.5:1; цель касания 44px (у точек карусели — 24px).
- После правок CSS/JS — `npm run build:assets`; намеренная смена вида —
  `npm run test:visual -- --update-snapshots` и эталон в тот же коммит.
- Новая настройка «Дизайна» обязана иметь потребителя в CSS (т. 243, 309).

**PHP и безопасность**
- Рендер публичной страницы **не ходит в сеть** (т. 110): внешние запросы —
  только воркеры по cron или админка.
- `date($f, strtotime($x))` запрещено — `DateFormatter::format()`.
- `json_encode`: свои данные — `JSON_THROW_ON_ERROR`, редакторские —
  `JSON_INVALID_UTF8_SUBSTITUTE` (+ `?: '[]'` в атрибут); `(string)` поверх
  нельзя (т. 356).
- Выборку отдавать через `Database::rows($stmt)` / `Database::row($stmt)`
  (типизированы), а не голым `fetchAll()`/`fetch()`.
- Значение `X|false` не отдавать типизированному параметру под `strict_types`.
  Эталон PHPStan только уменьшается; новый код — без находок (т. 293).
- `custom_css`/`custom_js` и блок «HTML» — только супер-админ, только файлами.
  Ролей две: `admin`, `editor` (`RbacGuard::ROLE_*`).
- Замену файлов обновления не выполняет веб-запрос (т. 291) — только воркер.
- В `create()` читать `lastInsertId()` **до** `bustPageCache()`.
- Тесты, пишущие в `settings`, в начале зовут `reset_design_state()`.
- Не добавлять ключи Telegram в `SettingsController::TEXT_KEYS`.
- Перебор записей — пакетными запросами, быстрый путь сверяется с медленным (т. 294).
- Новый раздел админки — строка в `AdminUi::navigationIcon()` (т. 248).
- Новый двухсегментный маршрут — **перед** `/{type}/{slug}` в `public/index.php`.
