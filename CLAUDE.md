# ArtStudio CMS — заметки для Claude

Цель файла: быстрый старт без перечитывания всей ветки. Здесь — карта проекта,
договорённости и команды. Обновляй при заметных изменениях архитектуры.

## Что это
Госсайт «Агентство стратегического развития…». Тестовый адрес — **artstudio.uz**
(прежний asr.artstudio.uz больше не существует).
Собственная CMS: **чистый PHP 8.4+ без runtime-зависимостей Composer**,
MySQL/MariaDB. Composer/PHPStan и npm/Playwright нужны только разработке и CI. Свой
автозагрузчик (`app/Core/bootstrap.php`), свой роутер (`public/index.php`),
свой тест-раннер. Деплой — shared-хостинг (cPanel), поэтому: никаких внешних
зависимостей времени выполнения, всё работает на голом PHP+cURL.

## Режим экономии (по умолчанию)
Владелец бережёт лимиты. Работать максимально экономно по токенам:
- Минимум лишних чтений: сначала `CLAUDE.md`, потом точечно нужный файл (Grep/Read
  диапазона), не «осматривать» всю ветку. Не перечитывать то, что уже видел.
- Не проверять то, что не менял. Верификация — соразмерно правке (мелкая CSS-правка
  не требует полного smoke). Для проверки сайта — `scripts/smoke.php`, а не ручные скрины.
- Ответы короткие и по делу, без длинных пересказов и списков опций. Не гонять
  тесты/сборки без причины. Батчить независимые вызовы инструментов в один шаг.

## Договорённости с владельцем (важно)
- Работать **автономно**, не переспрашивать по мелочам; решения объяснять кратко.
- **Не всё делать буквально**: если просьба спорна — сначала коротко объяснить,
  почему стоит/не стоит, потом делать.
- Перед изменениями синхронизировать `main`, работать в отдельной тематической
  ветке и доводить работу до `main` **только через PR — всегда, без
  исключений**. Прямой push в `main` запрещён: на репозитории включено правило
  «Changes must be made through a pull request», и push его обходит (GitHub
  пишет в журнал `Bypassed rule violations`).
  Полный цикл — не «создать PR и остановиться», а довести до конца:
  ветка → PR → **подписка на события PR** (`subscribe_pr_activity`) →
  чинить падения CI и отвечать на комментарии ревью → мерж по зелёному CI.
  Оставлять висящий PR и ждать, что его вольёт владелец, не нужно.
- Влитый PR закрыт и новые коммиты не отслеживает. Если работа продолжается
  после мержа — это новая ветка от свежего `main` и новый PR, а не push в
  старую ветку (иначе коммит уходит «в никуда»: именно так потерялся фикс
  контраста после PR #129).
- **Не переводить админку** (интерфейс админки — по-русски). Переводится только
  публичная часть (RU=ключ, UZ-словарь) и контент (per-language в БД).
- Коммиты — короткие и осмысленные; не добавлять служебные идентификаторы
  модели или сессии в коммиты, PR, код и артефакты.
- **Не хардкодить бренд-акцент** `--gov-teal` (он настраивается в админке через
  `--color-accent`). Для затемнений использовать `color-mix`, не фикс-цвет.

## Как запустить локально

Нужны PHP 8.4+ и MySQL/MariaDB. В Linux-контейнере БД при необходимости
поднимается отдельно; встроенный PHP-сервер запускается с router-файлом,
поскольку он не читает `.htaccess`.
```bash
sudo service mariadb start                     # или: mysqld_safe &
php -S 127.0.0.1:8000 -t public public/router.php
```
Базы: `asdr_cms` (демо-контент), `asdr_test` (для тестов — имя жёстко ждут
тесты и CI, `tests/load_schema.php asdr_test` заливает схему). Доступ
root@127.0.0.1 без пароля. Если админ-пароль неизвестен — сбросить в БД
(`users.password_hash`, `password_hash()`), логин `admin`.

## Проверки (вместо ручного клика)
```bash
# Полный прогон: 1293 сценария; без TEST_DB_* 199 DB-сценариев пропускается
TEST_DB_HOST=127.0.0.1 TEST_DB_DATABASE=asdr_test TEST_DB_USERNAME=root TEST_DB_PASSWORD= php tests/run.php

# Smoke-обход всего сайта (HTTP+PHP-фаталы), RU+UZ, публичка и вся админка.
# --totp обязателен, когда у админа включено приложение-аутентификатор:
# без него обход не проходит второй фактор и админку просто пропускает.
php scripts/smoke.php http://127.0.0.1:8000 --admin admin:ПАРОЛЬ --totp СЕКРЕТ
```
На боевом сервере к этому добавляются `scripts/release_check.php` (в т.ч. DNS
почты SPF/DKIM/DMARC, свежесть репетиции восстановления, наличие эталона
целостности) и `app/Console/integrity_check.php` — почасовая сверка SHA-256
файлов кода с эталоном, алерт в Telegram при подмене (`App\Core\Integrity`,
эталон пересобирает `scripts/release.php`).

После правок PHP: `php -l <файл>`. Сброс кэша страниц: `rm -rf storage/cache/page/*`
(в админке — кнопка «Сброс кэша» в шапке).

## Навык impeccable (дизайн-ревью)
Установлен в `.claude/skills/impeccable` (Apache 2.0, pbakaus/impeccable) — вызов
`/impeccable`, полезен как второй взгляд на публичную часть. В релизный архив не
попадает (`/.claude export-ignore`). Его предложения принимаются только в рамках
проекта: акцент берётся из админки (`--color-accent`), инлайн-стили в блоках
запрещены тестами (scoped CSS через `$templateCss`), анимации уважают
`prefers-reduced-motion` и настройку «остановка анимаций», контраст текста не
ниже 4.5:1, после правок CSS/JS — `npm run build:assets`. Админку не трогаем.

## Архитектура — где что лежит
- **Блоки страниц** (конструктор): `app/Core/BlockRenderer.php`
  (`defaults()` = список типов и их поля; `enrichData()` = блоки-обёртки, которые
  тянут данные из БД), шаблоны — `templates/blocks/*.php`, редактор полей —
  `app/Views/admin/pages/block_form.php`, сохранение (whitelist полей) —
  `app/Controllers/Admin/BlockController.php::collectData()`.
  **Настройка блока объявляется один раз — в схеме полей**
  (`App\Core\BlockData\BlockFieldSchema`, тип поля описывает `Field`). Из
  описания получаются умолчание, поле формы, нормализация присланного и
  приведение сохранённых данных на выводе (`apply()` зовёт `BlockRenderer`), так
  что шаблон читает `$data` как есть. Прежде то же самое лежало в четырёх
  местах — реестр, форма, `collectData()`, шаблон, — и списки значений
  расходились молча: форма отдавала значение, нормализатор принимал, шаблон о
  нём не знал и откатывался к умолчанию. Переезд типов постепенный: на схеме
  `columns`, `tabs`, `partners`, `advantages`, `testimonials`, `projects_list`,
  `faq`, `stages`, `docs_list`, `subscribe`, `slider`, `person_cards`,
  `contact_cards`, `icon_text`, `cta`, `counters`, `cards_grid`,
  `media_gallery`, `news_latest`, `news_feature`, `news_docs`, `map_point`,
  `text_image`, `anchor_nav`, `timeline`, `team_list`, `person_profile`,
  `leader_card`, `org_structure`, `bio_education` (у них в
  `BlockTypeRegistry::BASE_DEFAULTS`
  пустой массив — ключ остаётся ради порядка типов в редакторе), остальные
  по-старому. Число из закрытого набора — `Field::intChoice`, и значение вне
  набора заменяется умолчанием, а не ближайшим допустимым: в списке его нет,
  значит форма подделана. Картинка, иконка и цвет — тоже виды полей
  (`Field::media/icon/color`): их рисуют готовые виджеты `AdminUi`, поэтому
  условие показа вешается обёрткой снаружи, а соседние цвета схема сама
  собирает в `.colorfield-row`. `Field::mediaPosition` — единственное поле,
  владеющее двумя ключами (`image_position` и тот же ключ с `_mobile`): виджет
  рисует оба списка сразу, и разносить их по двум описаниям значило бы
  разложить один элемент управления на половины. Тесты, проверяющие «настройка доступна редактору»,
  обязаны читать `block_editor_markup()` (форма + поля схемы), а не один
  `block_form.php`. Мимо схемы идут репитеры (`items`) и значения, зависящие от
  соседнего поля (`ratio` зависит от числа колонок) — их умолчания в
  `BlockFieldSchema::EXTRA`. Стережёт тест 275.
- **Ритм ленты новостей** (`App\Core\NewsFeedRhythm`): лента `/news` идёт циклом
  из четырёх рядов — «обложка + две компактные», ряд из четырёх компактных,
  «две компактные + широкая», ряд из четырёх компактных. Крупных вида **два, и роли у них разные**: обложка
  (`SLOT_HERO`) открывает цикл — фотография во всю карточку, текст поверх неё,
  это главная новость страницы; широкая (`SLOT_WIDE`) замыкает цикл — кадр
  сбоку, текст рядом, веса хватает завершить композицию, но за роль главной она
  не спорит. Обе занимают ровно **две ячейки**. Вид карточки шаблон не
  вычисляет: `slot()` отдаёт имя, оно же идёт в класс `relnews-card--<slot>`.
  Отдельной крупной новости над сеткой нет: первая новость и есть обложка цикла.
  Арифметика: цикл — 14 карточек и 16 ячеек (крупные на позициях 0 и 9), то есть
  при четырёх колонках ровно четыре полных ряда, при двух — восемь. `PAGE_SIZE` =
  14, ровно один цикл: страница обязана быть целым числом циклов, иначе
  последний ряд обрывается на середине композиции. **На три колонки цикл не раскладывается**, и крупная
  карточка рано или поздно упирается в последнюю колонку: места на две ячейки
  нет, сетка переносит её вниз и оставляет дыру — поэтому в диапазоне
  1001–1100px растяжение выключено, там все карточки в одну ячейку (обложка
  сохраняет свой вид, только уже). На узком экране растяжение снимается по той
  же причине: `span 2` в одноколоночной сетке создаёт вторую колонку и
  горизонтальную прокрутку.
  **Кадры крупных карточек занимают свою площадь целиком.** У обложки кадр
  лежит подложкой (`position: absolute; inset: 0`), а **подложка под текстом
  принадлежит самому тексту**, а не кадру: тело карточки прижато к низу
  (`margin-top: auto`, не `flex: 1`) и несёт сплошную заливку
  `rgba(6,14,28,.88)` с растушёвкой `--newshero-fade` сверху — одно число на
  высоту растушёвки и верхний отступ текста. Градиент во всю карточку за
  контраст отвечать не может: его плотность считается в процентах от высоты
  карточки, а высота текста от неё не зависит, и на светлой фотографии
  заголовок попадал в зону, где затемнения почти нет — замерено 1.9:1 при
  норме 4.5:1. Сплошная заливка даёт 13:1 даже поверх белого кадра. Заголовок
  обложки ограничен тремя строками: подложка растёт вместе с текстом, и
  длинный заголовок закрасил бы фотографию целиком. У широкой кадр тянется на всю высоту своей половины: фиксированная
  пропорция оставляла сверху и снизу пустые поля в полсотни пикселей — высоту
  ряда задаёт соседняя компактная карточка, а не эта фотография, и на белой
  карточке такие поля читаются как незагрузившийся снимок.
  **Ширина кадра широкой карточки — ровно одна колонка сетки**
  (`calc(50% - var(--newsgrid-gap)/2)` плюс такой же промежуток внутри
  карточки), а не произвольная доля: карточка растянута на две ячейки, и при
  доле вроде 56% её внутренняя граница попадала между колонками — текст
  начинался не там, где начинается карточка ряда выше. Промежуток сетки
  объявлен переменной `--newsgrid-gap` у `.newslist-grid` и берётся оттуда же,
  иначе два числа разъедутся при первой правке.
  **Метка на обложке лежит отдельным слоем**, поэтому тело карточки резервирует
  под неё место сверху: на узком экране, где текста больше, чем высоты, первая
  строка заезжала прямо под метку.
  **Кадр карточки новости не наезжает при наведении.** Карточка уже
  поднимается, меняет цвет рамки и тень — зум был четвёртым движением на одном
  элементе, и в сетке из четырнадцати карточек лента дёргалась под курсором.
  У альбомов, проектов и каталога зум остаётся: их на странице три-четыре.
  Переход `transform` объявлен только у них — у карточки новости он читался бы
  как рабочий приём.
  **«Читать подробнее» в ленте нет вовсе.** Карточка сама является ссылкой,
  поэтому надпись была скрыта от диктора (`aria-hidden`) — то есть не сообщала
  ничего и ему, — а глазу повторяла очевидное и на каждой из четырнадцати
  карточек рисовала лишнюю строку, обрывая низ ряда. В блоках подборок
  (`news_feature`) `.card-more` остаётся: там карточек три-четыре и ссылка
  отделяет их от текста.
- **Контейнеры** (`BlockTypeRegistry::CONTAINER_TYPES` = `columns`, `tabs`):
  содержимое — вложенные блоки (`blocks.parent_block_id` + `column_index` =
  номер колонки/вкладки), шаблона нет, рендер программный
  (`BlockRenderer::renderColumns/renderTabs`). Контейнер в контейнер не
  вкладывается. Вкладки без JS показывают все панели подряд; переключение
  надстраивает `public/assets/js/blocks/tabs.js`. Подробности — docs/BLOCKS.md.
- **Условия показа блока** — `App\Core\BlockVisibility` (ключи `_visible_from`,
  `_visible_to`, `_visible_device` в data блока). Расписание считается на
  сервере: блок вне окна вообще не попадает в HTML. Устройство — классами
  `.cms-block--only-mobile/desktop`, потому что кэш страницы общий для всех
  посетителей. `BlockRenderer::renderPage()` отдаёт `expires_at` (ближайшая
  граница расписания), `PageController` по ней пересобирает кэш — иначе баннер
  «до 30 июля» висел бы и 31-го.
- **Обложка (Hero) — отдельный тип контента**, а не содержимое блока. Запись в
  `heroes` (общие настройки JSON + статус draft/published/scheduled с окном
  показа и приоритетом) плюс её слайды в `hero_slides` (`sort_order` —
  он же порядок показа, `is_active`, поля слайда JSON) и переводы текста в
  `hero_slide_translations` (механизм А: медиа и раскладка у слайда общие для
  всех языков, переводится только текст). Раздел админки — `/admin/heroes`:
  список слайдов с превью, перетаскиванием, дублированием и включением;
  сам слайд правится на своей странице (полей полсотни, в репитере они не
  помещаются). Блок страницы «Обложка» хранит только `hero_id` и ничего больше
  — одну обложку можно вывести на нескольких страницах. `hero_id = 0` —
  старая обложка, собранная прямо в блоке; такие страницы работают по-прежнему.
  Классы: `App\Core\Hero\HeroSettings` (контракт общих настроек),
  `HeroSlideData` (поля слайда; **пустое значение оформления = «как у
  обложки»**, явное «нет» — это `none`), `HeroPresets` (Editorial, Government,
  Navy, Full Image, Video, Minimal — разовое действие, ничего не блокирует),
  `HeroRenderer` (разметка и scoped CSS). Фронт — `blocks/hero.css` +
  `blocks/hero.js`, подключаются по ключу `hero_slides` (не по типу блока:
  старой обложке они не нужны).
  **У слайда осталось только то, что зависит от кадра.** Раскладка, размеры
  текста и палитра принадлежат обложке: переопределения у слайда удваивали
  настройку и молча расходились с ней. От кадра к кадру меняются фотография,
  наложение поверх неё и цвет текста (`content_scheme`) — они и остались.
  Настроек всего 79 (31 у обложки, 48 у слайда) — было 123.
  **Наложение — не «затемнение», а вуаль любого цвета:** тёмная затемняет кадр,
  светлая осветляет. От плотности 25 % оно решает за кадр: по светлоте вуали
  выбирается цвет текста (`HeroRenderer::veilIsLight`). Для прозрачной шапки в
  счёт идёт только **сплошное** наложение — градиент гуще там, где текст, и к
  другому краю сходит на нет, а шапка тянется во всю ширину.
  **Свой цвет текста главнее автоподбора:** классы `hero--content-light/dark`
  объявляют `--hero-fg` на `.hero__text`, то есть глубже схемы, и затирали
  выбранный цвет. Схема `custom` со своим цветом даёт `hero--content-custom`,
  под который правил нет. Явный выбор «светлый/тёмный» главнее и того, и
  другого — это решение редактора.
  **Отступ всего текста сверху** — `text_offset_top` у обложки, переменная
  `--hero-text-offset`. Отдельной настройки для телефона нет: на узком экране
  значение ограничивается `min(Npx,10vh)`, поэтому крупный отступ не выдавит
  текст за экран, а небольшой не изменится. Промежутки между частями текста
  (`--hero-gap-*` в `blocks/hero.css`) настройкой не являются — это
  типографика, и у первой части они сняты.
  **Поведение автопрокрутки не настраивается**: пауза при наведении и после
  действия посетителя, возобновление через 10 секунд и отсутствие
  автопрокрутки на телефоне зашиты в `blocks/hero.js`. Настройки — только
  «включить» и интервал (у слайда бывает своя `duration`).
  **Каждая настройка обязана что-то менять на выводе** — тест 269 рендерит
  обложку дважды (умолчание против изменённого значения) и требует различий;
  зависимые проверяются в контексте, где действуют. Новая настройка обязана
  получить там пробу, иначе тест падает.
  **Кадр-замена лежит под видео всегда.** Поэтому «видео не загрузилось»,
  «автовоспроизведение запрещено», «выключено на телефоне» и «меньше движения»
  — это один сценарий, а не четыре: скрыть видео, под ним уже готовый кадр.
  Iframe YouTube сервер не отдаёт вовсе — его создаёт скрипт и оставляет
  прозрачным, пока плеер не ответит на `{"event":"listening"}`; не ответил за
  4 секунды — iframe убирается. Пустой обложки не бывает ни при каком отказе.
  **Цвет разведён на два уровня:** схема обложки (`scheme`: light/dark/navy/
  custom) красит фон и её собственный текст, `content_scheme` (auto/light/dark)
  — только текст. Цвет объявлен переменной `--hero-fg` на `.hero__text`, а не
  каскадом `color`, поэтому вложенный компонент со своей поверхностью
  (`.hero__surface`) переопределяет её у себя и остаётся тёмным на светлом.
  **Навигация не перекрывает контент:** она лежит отдельной полосой, а
  `.hero__inner` резервирует под неё `--hero-nav-space`. Но соседний блок
  перекрыть её может: тема надвигает «Счётчики» на низ обложки
  (`margin-top` объявлен в gov-theme дважды, действует последний —
  `clamp(-100px,-7vw,-60px)`, и на телефоне тоже). Поэтому полоса поднимается
  на `--hero-nav-bottom`; величину сверяет тест — разъедется с темой, и стрелки
  снова пропадут.
  **«Во всю ширину» — это фон, а не контент:** `.hero--w-full` выходит из
  контейнера страницы (`margin-inline: calc(50% - 50vw)`), а `.hero__inner`
  держит текст в колонке сайта и выравнивает его по остальным блокам
  (`--hero-gutter` = боковой отступ `.site-content`).
  **Фоновая надпись** (`watermark`) — крупное слово за контентом. Это
  декорация из текста, поэтому обязательств три: переводится наравне с
  заголовком (колонка в `hero_slide_translations`), `aria-hidden` — иначе
  диктор читает её посреди заголовка, — и `pointer-events:none`, иначе слово
  шириной в экран накрывает кнопки. Настроек пять и они одинаковы у слайда и
  у секции: текст, `watermark_size` (**числом**, в % ширины экрана: нужный
  кегль зависит от длины слова, пресетом «крупная / средняя» его не угадать),
  привязка `watermark_x/y` и `watermark_opacity`. Смещений по осям, контура с
  толщиной, своего цвета и выбора семейства нет — слово рисуется цветом текста
  секции или обложки и потому видно на любой схеме. Размер намеренно **не из
  шкалы `--step-*`** — шкала для читаемого текста, а декорация растёт вместе с
  экраном (стережёт тест 249, он же сверяет наборы обеих поверхностей).
  Та же надпись есть у любой секции (`_watermark*` в data блока,
  `.cms-block__watermark`); там текст перевода не требует — блоки у каждого
  языка свои.
  **Свой CSS-класс слайда** (`css_class`) — аварийный выход для оформления,
  которого нет в полях: класс вешается на слайд, стили пишутся в «Свой CSS»
  страницы (супер-админ). Значение чистится жёстко (имя класса с буквы,
  до пяти штук) — оно уходит в атрибут.
  **Длительность показа бывает своя у слайда** (`duration`, 0 = как у обложки):
  таймер и полоса прогресса считают по ней, а не по общему интервалу.
  «Меньше движения» гасится множителем `--hero-motion` (0/1), а не `!important`.
- **Страница-раздел**: любую страницу можно назначить шапкой ленты `/news`
  или списка `/projects` (`pages.section` = `news|projects`, поле «Шапка
  раздела» в сайдбаре формы). Она отдаёт разделу заголовок, лид и SEO, а её
  блоки выводятся **под** списком (`App\Core\SectionPage`, `Page::forSection`).
  Раздел не назначен — работают прежние строки из шаблона.

  тем же порядком, что в `findHome`: запись нужного языка с ролью → запись
  нужного языка **из группы перевода** → и только потом `page_translations`.

  русский заголовок при живой узбекской версии: страницы переводятся отдельной
  записью (механизм Б), а откат шёл на механизм А. Отсюда следствие для
  редактора: назначать роль на каждом языке не нужно, достаточно одного раза.
  Собственный адрес страницы отдаёт **301 на адрес раздела** (`Page::sectionOf`
  + `sectionUrl` в `Site\PageController`) — иначе один и тот же заголовок, лид
  и блоки живут по двум адресам с canonical на самих себя. Ровно так же ведёт
  себя главная со своим slug'ом. Внутри одного языка роль по-прежнему одна:
  назначение забирает её у прежней страницы.
- **Проект — это страница с подтипом** (`pages.entity_type` = `page|project`).
  Отдельных таблиц у проектов нет: и чтение, и запись идут в `pages` с фильтром
  по типу (`App\Models\Project`). Обложка, «показать на главном» и ручной
  порядок — колонки `pages`; `pages.lead` у проекта это анонс для карточки, а
  тело собирается блоками тем же конструктором, что и у страниц (общий партиал
  `admin/pages/_block_editor.php`). Форма проекта: паспорт (название, адрес,
  анонс, обложка, статус, порядок, «на главном») плюс конструктор — второго
  места для содержимого нет.
  **Различаются записи по `entity_type`**: свой раздел админки и своя форма у
  каждого типа, форма страницы отдаёт 404 на проект (и наоборот, `Project::`
  не видит страниц), публичный адрес страницы — `/slug`, проекта —
  `/projects/slug`, slug уникален внутри типа. Любой новый список по `pages`
  обязан фильтровать тип.
  **Язык у проекта один механизм** — отдельная запись своего языка
  (`lang` + `translation_group_id`, кнопка «Создать перевод» в сайдбаре),
  slug у версий общий. Старых таблиц (`projects`, `project_translations`,
  `project_images`, `project_fields`) не осталось: миграция
  `2026_08_13_projects_into_pages.sql` переносит галерею и свободные поля в
  блоки и удаляет их, свежая установка их и не создаёт.
- **Модели** — `app/Models/*` (Project, News, PhotoAlbum, TeamMember, Page,

- **i18n публички**: `App\Core\Lang` + глобальный `t()` (`app/Core/helpers.php`),
  словарь `app/Core/lang/uz.php` (RU-строка → UZ). Контент — таблицы `*_translations`.
- **Разметка внутри заголовка** — `*слово*` (выделение) и `|` (принудительный
  перенос строки), обе в `App\Core\TitleMarkup`. Разметка
  живёт внутри самой строки, а не в отдельной колонке «какие слова красить»:
  колонка разъезжалась бы с текстом при первой правке и отдельно на каждом
  языке. `html()` экранирует и оборачивает в `span.tx-mark`, `plain()` снимает
  звёздочки для мест без разметки (`aria-label`, `title=`, оглавление). Разбор
  идёт **после** экранирования, поэтому HTML в заголовок не проходит. Вид
  выбирается в «Дизайне» (`title_mark`: акцент / рукописный / мазок / без) и
  приезжает классом `design-mark-*` на `<body>`.
  **Перенос сделан чертой, а не тегом `<br>`:** тег в заголовке экранируется и
  виден как текст — правило «поля-заголовки не принимают HTML» важнее удобства
  записи. Черта разбирается уже после экранирования, как и звёздочки, поэтому
  приехать из самого текста не может. Символ выбран за то, что в заголовке
  госсайта он не встречается: слэш бывает в «24/7» и в адресах. `plain()`
  превращает его в пробел — склейка «АгентствоРазвития» это другое слово.
  **Общая шапка секции разбирает разметку сама** (`App\Core\SectionHead`): она
  рисует заголовок полутора десятков блоков и экранировала его в обход
  `TitleMarkup`, поэтому у них не работало ни выделение, ни перенос, хотя у
  блоков со своим заголовком работало и то, и другое.
  **Подсказку о разметке поле получает само**: `Field::named('title_field')`
  подставляет `Field::TITLE_MARKUP_HINT`, если своей подсказки у поля нет —
  объяснять приём в тридцати описаниях по отдельности значило бы разъехаться
  с ними при первой правке. Форма обложки не блок, там подсказка проставлена
  руками.
  **Приём включён только у декоративных заголовков** — секций и обложки.
  Заголовок новости уходит ещё в RSS, Telegram, sitemap и meta; там звёздочки
  протекли бы наружу, поэтому в новостях его нет.
  **Проявление заголовков** (`title_reveal`: без / целиком / слева направо) —
  соседняя настройка «Дизайна». Заголовок секции (`.cms-block h2` — у карточек
  h3/h4, поэтому список ровно такой) ждёт прокрутки бледным и набирает свой
  цвет. Бледное состояние вешает **только JS** (`is-title-reveal`): без
  скриптов, при «меньше движения» и в режимах контраста заголовок обычный.
  «Слева направо» — градиент по тексту (`background-clip: text` +
  `-webkit-text-fill-color: transparent`), поэтому правило обёрнуто в
  `@supports`: без поддержки прозрачная заливка сделала бы заголовок не
  бледным, а невидимым. Цвет берётся `currentColor`, поэтому приём работает и
  на тёмной секции; `color` не обнуляем — иначе градиент нечем красить. После
  показа класс снимается: выделение мышью, печать и выбранное слово
  (`.tx-mark`) возвращаются к своим стилям.
  **Рукописные шрифты — отдельный каталог** `DesignSettings::SCRIPT_FONTS`
  (Caveat, Bad Script, Great Vibes, Pacifico), настройка `design_font_script`,
  переменная `--font-script`. В общий каталог их класть нельзя: он предлагается
  для текста всего сайта. Требование к семейству — подмножества
  cyrillic-ext + cyrillic + latin, иначе не рисуются Ғғ Ққ Ҳҳ и установка
  падает проверкой покрытия (так отсеян Marck Script).
- **Обложка-карточка новости** (`layout_type = 'card'`, `App\Core\NewsCard`):
  своя короткая строка заголовка (`card_title`), вторая плашка (`card_badge`,
  контуром — рядом с обычной меткой две заливки спорят), показатели
  (`card_stats`, JSON, до трёх), подпись рукописным шрифтом (`card_signature`)
  и сноска (`card_note`). Все пять переводятся (`news_translations`).
  **Заголовок обложки — не заголовок новости**: настоящий уходит в ленту, RSS,
  Telegram, sitemap и поиск, укорачивать его ради картинки нельзя. Поэтому и
  звёздочки выделения работают только в `card_title`.
  Колонки названы `card_*`, а не `cover_*`, намеренно: рядом лежит колонка
  `image` (обложка-картинка), и тест 117 считает поле формы с «cover» в имени
  полем картинки без медиапикера.
- **Показатели** — блок `counters`. Значение хранится **строкой**: «1 200»,
  «24/7», «№1», «-12.5». Прежде из него вырезались все нецифры ради анимации —
  и «24/7» превращалось в 247. Отсчёт при появлении включает шаблон, когда в
  значении одни цифры. Пробел-разделитель разрядов нормализатор делает
  неразрывным (`groupedNumber`) — запрещать перенос всей ячейке нельзя, тогда
  длинное значение вылезает за карточку вместо переноса после приставки.
  Есть приставка, примечание, ссылка, вид (`variant`: полоса / карточки) и
  размер чисел (`value_size`).
  **Подложка блока — настройка** (`panel`: карточка / без подложки). Прежде
  белая карта с рамкой, тенью и подъёмом при наведении рисовалась всегда, и
  одиночный показатель нельзя было поставить прямо на фон секции. «Без
  подложки» снимает фон, рамку, тень, внутренний отступ и боковые отступы
  крайних показателей — так блок годится и для одного числа с иконкой.
  Положение иконки (`icon_position`: слева / справа / сверху / сверху по
  центру) и выравнивание (`text_align`) двигают **пару «иконка + текст»
  целиком**: пока подпись тянулась на всю ширину ячейки, «по центру»
  центрировало текст, а иконка оставалась у края. Иконка справа переворачивает
  ряд (`row-reverse`), и главная ось начинается справа — выравнивание вправо
  там задаётся `flex-start`. Заголовок блока выравниванию не подчиняется: он
  центрирован общим правилом вместе с заголовками соседних блоков.
- **Тема/дизайн-токены**: `public/assets/css/frontend.css` (база) →
  `public/assets/css/gov-theme.css` (активная тема, идёт после базы;
  navy `--gov-navy`, teal `--gov-teal`, свет/тьма через `:root[data-theme]`).
  **`text-wrap: balance` в публичном CSS нет.** Браузер разносил заголовок по
  строкам, исходя из его собственной ширины, и в сетке карточек соседние
  заголовки ломались в разных местах — ряд читался неровным, а на телефоне
  строка вдруг оказывалась вдвое короче колонки. Ширину строки задаёт колонка.
  `text-wrap: pretty` остаётся: он убирает висячее слово, а не двигает перенос.
  Стережёт тест 233.
  **Размеры шрифта берутся только из шкалы** `--step--4 … --step-12` в `:root`

  подбирать заново нельзя — стережёт тест 236. Ступени намеренно неравномерны

  два тона на одной странице читались как грязь; уровни различаются светлотой,
  а не только цветом. a11y-слой — `a11y.css`. JS фронта — `public/assets/js/frontend.js`.
  Публичная страница загружает сгенерированные `public.min.css` и
  `public.min.js`; после изменения исходников выполнить `npm run build:assets`.
  CI проверяет актуальность и Brotli-бюджет командой `npm run check:assets`.
- **Цель для касания — 44px, но не всегда размером.** Иконочные кнопки

  прозрачным `::after` до 44×44 (`.site-search-toggle`, `.site-theme-toggle`,

  считает сама спека. Вход один на файл — шаг TOTP одноразовый, поэтому
  тесты идут последовательно в одной вкладке; мобильный проект админку не
  снимает. Переходы гасятся инлайн-стилями, а не тегом `<style>`: слой
  переопределений объявляет свои `transition` через `!important`, и снимок
  ловил цвет посреди перехода темы.
- **Ширина колонки чтения — один токен** `--editorial-reading` (760px, около
  80 знаков в строке при основном кегле). Вариант «Секция» держал свои 900px
  и давал 94 знака — длиннее соседних блоков той же страницы. Новое правило с
  собственной шириной текста — повод свериться с токеном, а не выставить своё
  число.
  **Ритм отступов между секциями осмысленный, а не ровный:** маленький нижний
  отступ (`pb16…22`) притягивает заголовок к следующему блоку, крупный
  верхний (`pt72…80`) отделяет тяжёлую секцию. Выставлять блокам свои
  `_pad_top`/`_pad_bottom` в шаблонах не нужно — это ломает приём: у страницы
  получались промежутки 16px рядом со 128px.
- **Правила частей темы обязаны спрашивать цвет секции.**
  `public-editorial-pages.css` подключается после общего бандла, поэтому
  `.editorial-page__content > .cms-block--text .block-text__content {color:
  var(--gov-ink)}` весит (0,3,0) и побеждает `:where(.rich-content)` с нулём —
  текст переставал слушать свою секцию. На тёмной секции это давало **1.00:1**:
  абзац красился ровно в цвет фона и пропадал совсем. Внутри блоков цвет
  берётся как `var(--section-*, <прежний токен>)`: вне тёмных секций
  переменная не задана, поэтому светлые страницы не меняются. Шапка страницы и
  крошки — не секции, им `--section-*` не адресован (в `:root` он разрешается в
  цвет темы и снимет полупрозрачность). Стережёт тест 274.
- **Вынести часть темы можно не всякую** (тест 262). Части подключаются
  **после** общего бандла, поэтому вынос поднимает семейство правил в каскаде
  выше `public-layout-polish.css` и `public-editorial-pages.css`. Если те
  задают тем же селекторам те же свойства, вид меняется молча: у «Этапов»
  после выноса `padding-top` стал 24px вместо 28px из polish. Выносить —
  только семейства, которых поздние файлы не касаются (сверяет тест).
  Тесты, читающие правила темы, должны брать `theme_css()` (склейка темы с
  вынесенными частями), а не `gov-theme.css` напрямую.
- **Переход между страницами — View Transitions, без SPA.** Сайт серверный:
  каждая ссылка это новый документ, и шапка перерисовывалась вместе со всем
  остальным, хотя на всех страницах она одна и та же. `@view-transition
  { navigation: auto }` плюс `view-transition-name` у `.site-header` и
  `.site-topbar` — браузер сопоставляет именованные снимки двух документов и
  переносит их, а не рисует заново. Приём декларативный: JS-роутера нет,
  браузер без поддержки просто переходит по ссылке как раньше.
  **Перенос снимка шапке при этом снят** (`::view-transition-group(site-header)
  { animation: none }`). Шапка у нас не липкая, и по умолчанию браузер везёт
  снимок от старого положения к новому: уходя со страницы, прокрученной вниз,
  старое положение шапки — выше экрана, и она **влетала сверху**, оставляя верх
  новой страницы пустым (замерено: на 700 мс перехода шапки в кадре не было).
  Со снятым переносом снимок сразу стоит на новом месте.
  **И перелив старой шапки в новую тоже снят** (`::view-transition-old(...)
  {opacity:0}`, `new {opacity:1}`). Вид шапки зависит от страницы: на обложке
  она прозрачная со светлым набором, на остальных — сплошная. Перелив двух
  таких снимков держал **белую полосу поверх уже тёмной обложки** — это и
  читалось как мигание белой шапки при переходе на главную. Шапка не контент,
  который должен превращаться одно в другое: это постоянная часть страницы,
  поэтому новая встаёт сразу, а старая не показывается вовсе. Белый набор при
  этом читается и на светлом: под прозрачной шапкой всегда есть затемняющая
  подложка (`--hdr-scrim`), и она едет вместе со снимком.
  **Подвалу имя не даём:** внизу страницы он то виден, то нет, и снимок ехал бы
  за экран на глазах у читателя. Верх страницы такой разницы не знает.
  Имя обязано быть уникальным: два элемента с одним именем отменяют переход
  целиком. «Меньше движения» гасится **своим** селектором
  (`html[data-a11y-motion="off"]::view-transition-group(*)` и такой же под
  `prefers-reduced-motion`): псевдоэлементы перехода живут отдельным деревом у
  корня, и общее правило `html[data-a11y-motion="off"] *` их не достаёт.
  Стережёт тест 262 — он же сверяет, что опт-ин пережил минификатор.
- **Гигиена публичного CSS** (тест 262): один селектор нельзя объявлять
  дважды в одном контексте так, чтобы нижнее правило перекрывало верхнее
  целиком — мёртвая копия читается как действующая, и правка в ней «не
  срабатывает». Именно так требование `.carousel-nav__btn {44px}` (touch-цель)
  жило рядом с работающими 40px. Повтор внутри `@media` законен — контекст
  входит в ключ. Число `!important` в публичных файлах ограничено сверху и
  может только уменьшаться: каждый из них делает следующую правку
  непредсказуемой.
- **Режимный класс на `<body>` не добавляет веса** (тот же тест 262).
  Настройки «Дизайна» приезжают классами (`design-type-static`,
  `design-cards-*`), и правило `body.design-type-static h2` весит (0,2,1) —
  больше любого одиночного класса компонента. Поэтому заголовок карточки
  каталога рисовался размером H2 (32px вместо 20px), заголовок обложки —
  42px вместо своих 56px, а заголовок панели настроек — 32px вместо 16px:
  общее правило перебивало собственные размеры компонентов. Квалификатор
  режима оборачивается в `:where(body.design-type-static)`, и правило весит
  ровно столько, сколько сам селектор: голый тег остаётся базой для
  заголовков без класса, а компонент со своим размером побеждает.
  Правило, где тег уже сужен компонентным классом
  (`body.design-type-static .block-cta h2`), — законно.
- **Слои каскада (`@layer`) в проект не вводим.** Замерено: перевод бандла в
  слои даёт 1573 расхождения вычисленных стилей, потому что слой сильнее
  специфичности и разом меняет победителя во всех межфайловых спорах. Хуже
  того, вне слоёв остаются сгенерированный CSS «Дизайна», части темы и
  scoped-CSS блоков — а нелойеный CSS сильнее любого слоя, и `:root` из
  настроек начинал перебивать `:root[data-theme="dark"]` темы (тёмная гамма
  ломалась целиком). Чтобы слои были безопасны, в них пришлось бы завернуть
  и PHP-генерацию CSS. Выгода — снять ~112 `!important` — этого не стоит.
- **Точки перелома публички — общая шкала**: `480, 560, 640, 720, 900, 1000,
  1100, 1360` (парный `min-width` = граница + 1: 561, 721, 901, 1001, 1361).
  Других значений в публичном CSS быть не должно — стерегут тесты 232. Раньше
  их было 33 (680, 760, 820, 980, 1040, 1180…), и соседние правила
  переключались на разных ширинах. Исключение одно: пара **768/769** у
  `.cms-block--only-mobile/desktop` — это контракт условий показа блоков
  (`BlockVisibility`), а не оформление; сдвиг границы поменял бы, кому блок
  виден, поэтому её не трогаем и на неё не вешаем стили. Отдельно помни:
  `901px` — граница мобильной раскладки сеток (`GridBalance`), а схема
  оргструктуры складывается в столбец на `900px` (на 910px четыре колонки
  ещё держатся без переполнения).
- **Ширина контейнера** (`DesignSettings::containerWidth`): узкий 1200,
  стандарт 1440 (умолчание), широкий 1500, очень широкий 1700, «на всю ширину».
  Откаты `var(--container-max, …)` в CSS держим равными умолчанию.
- **Раздел «Дизайн» отвечает только за то, чем управляет**: 18 настроек —

  вместе с мёртвым CSS — их классы `bodyClasses()` давно не выводил. Новая
  настройка обязана иметь потребителя: класс на `<body>` или переменную темы

- **Фон секции и подвала** — `App\Core\BlockBackground`: свой цвет, градиент,
  фотография (затемнение, кадр, фиксация), плитка и встроенные узоры (точки,

  абсолютным адресом — `var(--gov-emblem)` объявлена относительным url и из

- **Цвет секции и цвет карточек — два разных уровня** (`App\Core\SectionColors`).
  `_bg_text_scheme` (auto|light|dark|custom + `_bg_text_color`) красит текст
  самой секции целиком — заголовки, описания, списки, ссылки, а не один
  заголовок. `_bg_card_scheme` (auto|light|dark) отвечает за вложенные
  карточки, и `auto` означает «карточка сохраняет свою схему».
  **Механика — переменные, а не каскад `color`.** Секция объявляет себе
  `--section-fg/--section-title-fg/--section-muted-fg/--section-link-fg`,
  а компонент со своей поверхностью объявляет их заново для своего поддерева
  (один список `SectionColors::SURFACES`, продублирован правилом в
  gov-theme.css, сверяет тест 247). Поэтому белая карточка внутри navy-секции
  сохраняет тёмный текст, и спорить о специфичности не с кем: секция и
  карточка — разные элементы. Правило вида `.cms-block--bg-navy h3 {color:#fff}`
  писать нельзя — именно оно давало белый текст на белой карточке.
  Заголовок уровня секции обязан брать `var(--section-title-fg)`, а не
  `var(--gov-title)`: умолчание у переменной то же самое, но настройка секции
  тогда работает. Заголовки карточек, наоборот, остаются на `--gov-title`.
  На тёмной секции стеклянные (полупрозрачные) карточки темы делаются
  непрозрачными — иначе сквозь них просвечивает фон и тёмный текст карточки
  теряет контраст. Прежний флажок `_bg_light_text` читается как схема `light`.
- **Прозрачная шапка лежит на кадре обложки.** Светлый набор — белое лого,
  белое меню, белые иконки — читается только на тёмном кадре, поэтому под
  шапкой и верхней полосой всегда есть затемняющая подложка (`--hdr-scrim`):
  она работает без JS и на любой картинке. Весь набор идёт через переменные
  (`--hdr-fg`, `--hdr-veil`, `--hdr-icon-border`, `--hdr-ink-shadow`) — раньше
  цвет был белым литералом в десятке правил, и переключить его было нечем.
  На светлом кадре `blocks/hero.js` ставит `body.is-hero-light` по атрибуту
  слайда `data-hero-scheme`, и набор переключается целиком. Признак даётся
  только слайду, о кадре которого что-то известно: заливка или сплошное
  наложение; под фотографией без вуали работает подложка. Смена набора
  приходится на середину перехода между слайдами — сразу по клику она давала
  тёмное лого поверх ещё не ушедшего тёмного кадра.
- **Меню раздела в сайдбаре** — виджет `section_menu` (`App\Core\SectionMenu`):

- **Слой «Enterprise Scale» в `admin.css` разбирается семьями, а не разом.**
  Он перебивает компоненты через `!important` (было 961 на всю админку), и
  каждая такая строка делает следующую правку непредсказуемой: так поле Coloris
  получало HEX под образцом, а базовый кегль `body` был на пиксель крупнее
  полей вокруг. Но снимать `!important` пачкой нельзя: для части компонентов
  этот слой — единственное место, где они вообще оформлены (у
  `.btn--small.btn--icon` пропадали отступы, у `.image-field__upload` — flex,
  кнопка «показать ещё» исчезала совсем). Порядок: правило переносится в
  компонент или получает честный вес селектора, потом снимается `!important`,
  и **срез вычисленных стилей** доказывает, что вид не поехал —
  `node scripts/admin-style-snapshot.mjs before|after|--diff` снимает всё дерево
  двенадцати экранов в обеих темах (~28 000 узлов), в отличие от эталона
  admin-visual.spec с десятком селекторов на экран. Бюджет `!important` только
  уменьшается (тест 279): 961 → 895 (поля форм) → 867 (таблицы) → 860 (бейджи)
  → 845 (заголовки) → 372 (остальные секции слоя).

  поднимает вес селектора на класс, и правило начинает перебивать соседей — так
  подпись поля забрала кегль у галочки «по умолчанию». `:not(:where(.btn))`
  ничего не поднимает.

  `.data-table`, а разделы вроде «Базы данных» — `.admin-table` / `table.table`
  со своим набором. У второго правила лежали в трёх местах и перебивали друг
  друга наполовину, отчего `.table--compact` и `.table--striped` не работали:
  у общего правила вес (0,1,2) из-за `table.table`, у классов-модификаторов —

  полоса осталась бы на ней навсегда). Вторая: **возврат к месту правки** —
  сохранение уводило в начало страницы, а «Настройки сайта» это 6600px.
  Позиция кладётся в `sessionStorage` по пути страницы и возвращается после
  перезагрузки; **якорь в адресе главнее** (`/admin/telegram#telegram-channel`
  — осознанная цель редиректа, и спорить с ней нельзя). Стережёт тест 279.
- **Классы, которых нет в CSS, стережёт тест 278.** Класс без правила ничего не
  ломает и потому живёт годами: `.btn--success` рисовал обычную серую кнопку,
  `.badge--warning` — нейтральную пометку, `.admin-grid` не давал сетки. Разом
  нашлось 52 таких класса; остаток — хуки и дубли — держится бюджетом, который
  может только уменьшаться.
- **Переиспользуемые компоненты форм**: `App\Core\ImageField::resolve()`
  (пустое присланное поле = очистка!), `AdminUi::imageField()`, `AdminUi::colorField()`.
- **Миграции**: `database/migrations/*.sql`, применяет `database/migrate.php`
  (трекинг в таблице `migrations`). **`schema.sql` обязан совпадать**: при новой
  миграции добавь и колонки в CREATE TABLE, и файл в список
  `INSERT INTO migrations(...) VALUES` (иначе падает тест консистентности).
- **Полоса страниц** — `App\Core\Pager` + партиал `site/_pager.php`, общий для
  ленты новостей и каталогов: края, окно вокруг текущей страницы, многоточия на
  разрывах и стрелки с подписями для диктора. Соседние страницы вью кладёт в
  `$pagerPrev/$pagerNext`, шапка выводит их как `<link rel="prev|next">`.
- **Ряды карточек без дыр**: `App\Core\GridBalance` считает дорожки сетки и
  ширину карточки (`--grid-track`/`--grid-span` в scoped CSS блока). Колонок
  берётся столько, чтобы в последнем ряду не осталась одинокая карточка
  (пятёрка ложится 3+2), а карточки хвоста растягиваются на всю ширину.
  Используют `advantages` и `docs_list`; мобильную раскладку задаёт тема,
  поэтому растяжение живёт в `@media (min-width:901px)`.
- **Появление при скролле включено у нового блока по умолчанию**
  (`BlockPresentationNormalizer::newBlockPresentation`, зовёт `BlockController::store`).
  Исключений два: **первый блок страницы** — это первый экран, и пряча его до
  появления, мы задерживаем то, ради чего страницу открыли (и то, что Google
  меряет как LCP), — и **вложенный блок**, который появляется вместе со своим
  контейнером, иначе анимация играет дважды. Это умолчание, а не правило
  вывода: редактор меняет его в «Оформлении». Страницы, собранные раньше,
  догоняет `php scripts/enable_block_reveal.php` (есть `--dry-run`, `--type=`,
  `--page=`) — у него те же исключения плюс «обложка» и «редактор уже выбрал
  анимацию». Стережёт тест 289.
  **Демо-контент получает то же правило через `PagePresets::rhythmFor()`**
  (первый блок без появления, остальные — `stagger` у сеток, иначе `fade`).
  Две ветки посева шли мимо ритма: демо-главная и тела демо-проектов, и самая
  заметная страница демо показывалась одним снимком — редактор не видел
  настройки, которая по умолчанию включена. Теперь они берут из ритма **только
  появление**: фоны и отступы у главной и проектов свои, и ритм их не
  переписывает. Стережёт тест 107.
- **Появление при скролле** — только прогрессивное улучшение: `_reveal` с
  типом `stagger` (`data-reveal-items`) прячет карточки классом, который вешает
  JS, поэтому без JS всё видно. Обычный `data-reveal` прячет блок сразу в CSS —
  для ключевого контента (профиль руководителя) его не включаем, а страховка
  `@media (scripting: none)` возвращает видимость при отключённом JavaScript.
  **Наблюдение включается кадром после первой отрисовки** (`afterFirstPaint` в
  `frontend.js`): скрипт с `defer` выполняется раньше неё, и блок первого
  экрана получал `is-visible` в том же кадре, где впервые получил стили —
  начальное состояние не нарисовано, значит и переходить не от чего, поэтому
  на верхних блоках настройка не работала вовсе.
  **Показ карточки описан ключевыми кадрами** (`@keyframes card-reveal`), а не
  переходом: у карточек темы (`.feature-card`, `.news-card`, …) объявлен свой
  `transition`, тема грузится после базы и заменяла список целиком — `opacity`
  в нём нет, и каскад не проявлялся. Заливка `backwards` держит начальный кадр
  во время задержки и отпускает `transform` после показа, поэтому собственный
  ховер карточки остаётся своим. Сдвиг и масштаб — переменные
  (`--card-reveal-shift/scale/duration`), у крупных колонок новостей свои.
  **«Карточки по очереди» у блока без подходящей сетки** (текст, баннер,
  одиночная карточка) откатываются на обычное плавное появление секции:
  очередь строить не из чего, а настройка обязана что-то менять. Список сеток
  — `GRIDS` в `frontend.js`. Стережёт браузерный тест на `/reveal-check`
  (фикстура — `tests/browser/seed_visual.php`).
- **Скелетон-заглушка одна** (`.skeleton` в `frontend.css`) и стоит ровно в
  одном месте — коробка ролика YouTube на странице новости (`news.js` снимает
  класс по загрузке). Перелив подмешивается к цвету текста: белый на 18 %
  поверх светлой поверхности давал #f8f9fa, то есть приём был невидим и
  считался несуществующим. Второй набор правил под ту же задачу
  (`.media-skeleton`) не использовался нигде и удалён — класс без потребителя
  читается как рабочий приём. Расширять заглушку на карточки списков стоит
  только вместе с решением, что показывать на быстром соединении: мелькание
  перелива на каждой карточке хуже, чем его отсутствие.
- **Иконки**: `App\Core\Icon::render()` отдаёт `<use href="#tabler-…">`, а
  `Icon::injectSprite()` (вызывается из `View::render`) вырезает нужные
  `<symbol>` из вендорного спрайта по индексу
  `app/Core/data/tabler-sprite-index.php` и встраивает их после `<body>`.
  Ключи берутся из готового HTML, а не из счётчика вызовов — блоки приходят
  из кэша. Иконки, которые вставляет JS уже после загрузки, перечислены в
  `Icon::RUNTIME_ICONS` (сверяется тестом с `frontend.js`). Индекс
  пересобирается `npm run build:vendor`. Полный спрайт (2 МБ) грузится только
  пикером иконок в админке.
- **CDN**: `App\Core\Asset` (версионирование `?v=hash` + префикс CDN),
  `Asset::rewriteMedia()` переписывает `/uploads/public` в HTML на CDN.
  Pull-zone CDN (BunnyCDN и т.п.) — без переноса домена. `App\Core\Cloudflare` —
  purge через API (только если домен проксируется через CF).
- **CI**: `.github/workflows/ci.yml` — 4 джобы: php -l + тесты на PHP 8.4/8.5
  с MariaDB; PHPStan **блокирующий** (`composer analyse`) + `composer audit`;
  проверка синтаксиса JS (`node --check`); browser smoke на Chromium (Playwright).
  Отдельный сторож против тихого устаревания: прогон тестов пишет уведомления
  PHP в `storage/logs/ci-php.log`, обход сайта — в свои журналы, и шаги
  «Прогон без устаревших вызовов» / «Устаревшие вызовы на боевой версии PHP»
  роняют сборку, если в них появилось `Deprecated`. Смоук идёт на 8.5 — версии
  боевого сервера.

## Реализованные фичи (чтобы не изобретать заново)
- Конструктор шапки/футера (drag-and-drop зон), 4 макета, отдельный мобильный билдер.
- **Шаблон страницы — файл** (`App\Core\PageTemplateFile`, docs/PAGE_TEMPLATES.md):
  библиотека шаблонов (`block_snippets`) умеет выгружаться JSON'ом и
  загружаться обратно — кнопки в секции «Шаблоны страницы» редактора.
  Конверт помечен `kind: artstudio.page-template`: без пометки об ошибке
  узнают только после импорта, когда собралось не то. **Присланный файл — не
  свои данные:** тип сверяется с реестром, поля `data` — с умолчаниями типа
  (лишний ключ всё равно потерялся бы при первом сохранении), блок «HTML» и
  `custom_css` принимает только супер-админ. Ключи оформления (`_*`)
  перечислять руками нельзя — они прогоняются через тот же
  `BlockPresentationNormalizer`, что и форма блока: свой список молча
  разъезжается с нормализатором и начинает либо терять оформление, либо
  пропускать непроверенное значение. Загрузка только пополняет библиотеку и
  ничего не заменяет — применение к странице остаётся отдельным действием.
- **«Цели» (Maqsadlar)** — название, описание и набор снимков (`goals` +
  `goal_images` + `goal_translations`, модель `App\Models\Goal`); на сайте цель
  видна каруселью в виджете: текст над кадрами. Текст виден посетителю, поэтому
  **переводится** (механизм А, `Goal::localize`) — набор снимков без единого
  слова не сообщает, что за объект показан. Публичного адреса, slug'а и SEO у
  цели нет: держать стабильным нечего, поэтому языковая версия остаётся
  переводом строки, а не отдельной записью. Раздел админки `/admin/goals`
  постраничный, с поиском по названию и колонкой «Языки» — записей сотни.
  Порядок кадров внутри цели авторский: **случайной бывает сама цель, а не её
  слайды**.
  **Название — не заголовок разметки** (`p.goal-carousel__name`): виджет встаёт
  в любое место страницы, и уровень заголовка там не предсказать; диктор
  получает имя цели подписью карусели (`aria-label`).
  **Случайность переживает кэш только на своём адресе.** Страница кэшируется
  ключом `page:<id>:<lang>`, поэтому цель, выбранная при сборке, стала бы общей
  для всех до сброса кэша. Виджет отдаёт такую цель как запасную (без JS видна
  она), а свежую запрашивает `blocks/slider.js` у `/goals/random`
  (`Site\GoalController`, `Cache-Control: no-store`, `X-Robots-Tag: noindex`).
  Не ответил сервер — остаётся запасная: пустой карусели не бывает.
  **Ответ — JSON из двух кусков разметки** (`text` + `slides` + `label`): текст
  ложится над каруселью, кадры — в дорожку, склейкой одной строкой их не
  развести. **Адрес приезжает из разметки** (`data-goal-slider="/uz/goals/random"`,
  `Locale::url`): скрипт про текущий язык не знает, и жёсткий `/goals/random`
  приносил на узбекскую страницу русскую цель.
- **Пропорции кадра карусели — один список** (`App\Core\SliderRatio`) на блок
  «Слайдер» и виджет «Фотокарусель»: разметка и стили у них общие, поэтому и
  набор пропорций обязан быть общим — раздельные списки разъезжались молча.
  Ключ пропорции это имя класса (`.block-slider--ratio-9-16`), поэтому пишется
  через дефис. Кроме широких форматов есть вертикальные (1:1, 4:5, 9:16):
  карточки для соцсетей приходят именно такими, а при широкой пропорции
  `object-fit: cover` срезает у них верх и низ. Плитка «Медиагалереи» — не
  карусель: у неё свой набор (16-9, 4-3, 1-1) и свои правила, сводить их
  вместе незачем. Новая пропорция обязана получить правило в `frontend.css`,
  иначе настройка ничего не меняет (стережёт тест 273).
- **Виджет «Фотокарусель»** (`photo_slider`, `templates/widgets/photo_slider.php`):
  набор снимков без подписей и ссылок, с необязательной автопрокруткой и
  случайным порядком. Разметка и стили общие с блоком «Слайдер»
  (`.block-slider` в `frontend.css`) — поведение у них одно, и второй набор
  правил разъехался бы с первым. **Перемешивает браузер, а не сервер**
  (`data-slider-shuffle` → `blocks/slider.js`): страницы кэшируются общим
  ключом `page:<id>:<lang>`, и порядок, выбранный при сборке, застыл бы для
  всех посетителей до сброса кэша. Без JS карусель работает в порядке
  редактора. Скрипт просит сам шаблон (`AssetCollector::requireJs('slider')`)
  — этого хватает виджету сайдбара, который собирается на каждый запрос; для
  виджета **внутри блока** ключ добавляется по готовому HTML в
  `BlockRenderer::renderPage()` (`widget--photo_slider`), потому что на
  попадании в кэш шаблон не выполняется. Источник кадров — свои снимки или
  «случайная цель» (`source`, см. «Цели»).
- Обложка как тип контента: слайды с DnD-порядком, стрелки, свайп, клавиатура,
  индикаторы (точки / `01 / 05` / полоса / миниатюры), автопрокрутка (пауза по
  наведению и по действию зашиты), переходы Fade/Slide/Fade+Slide/Ken Burns,
  фон Image/MP4/YouTube с кадром-заменой, пресеты и расписание публикации.
- Hero (видео/фото/overlay, бесшовное loop-видео без кнопок), счётчики,
  направления, новости (лента + крупная), медиа-галерея, проекты, команда, FAQ и т.д.
- Блоки-обёртки, тянущие данные из БД: `news_latest/news_feature/news_docs`
  (новости), `projects_list` (проекты), `team_list` (команда).
- **Категории новостей** (`news_categories` + `news_category_translations`,
  модель `App\Models\NewsCategory`): рубрика — запись со slug и переводимым
  названием, `news.category_id` — ссылка. Slug один на все языки (это адрес и
  ключ выборки), переводится только название; механизм А. Раздел админки —
  `/admin/news-categories`, выбор — в сайдбаре формы новости, в списке новостей
  колонка «Категория» и фильтр (`?category=<id>|none`), у блоков новостей поле
  «Категория новостей», на публичке — рубрикатор `?category=<slug>`.
  **Метка (`news.badge`) — это не категория**: необязательная пометка
  («Важно», «Анонс») со своим цветом фона (`news.badge_color`); цвет текста
  считается по контрасту — `App\Core\NewsBadge` (он же рендерит разметку для
  всех трёх мест вывода). Старые бейджи-рубрики переносит разовый скрипт
  `php database/migrate_news_badges.php` (есть `--dry-run`).
- **Автозагрузка видео с YouTube-канала** (`App\Core\YoutubeChannel` — чтение
  канала, `App\Core\YoutubeImport` — импорт; панель в `/admin/videos`, cron —
  `app/Console/youtube_worker.php`). Забирается **карточка** ролика: название,
  описание, ссылка и кадр-превью; **само видео не скачивается** — оно остаётся
  на YouTube, сайт хранит только `videos.video_url`.
  По умолчанию источник — открытая RSS-лента канала (`/feeds/videos.xml`):
  никаких ключей и лимитов квоты, но только последние 15 роликов и без
  длительности. Ключ Data API (`youtube_api_key`, шифруется как секрет) —
  необязательное усиление: больше 15 записей за проход и длительность ролика.
  По @псевдониму лента не строится, нужен UC-id: он ищется один раз по странице
  канала и запоминается в `youtube_channel_id` (смена канала его обнуляет).
  **Ключ повторного прохода — `videos.youtube_id`**, поэтому импорт идемпотентен
  и его можно вешать на cron. Ролик, заведённый вручную, не дублируется: запись
  узнаётся по ссылке (`Core\Video::youtubeId`) и просто привязывается к каналу.
  **Правка редактора важнее источника**: название и описание переписываются
  только при включённой настройке «обновлять» — иначе ночной проход затирал бы
  ручные заголовки и переводы. Кадр-превью по умолчанию скачивается в медиатеку
  (`maxresdefault` с откатом на кадр из ленты): в админке CSP запрещает внешние
  картинки, и ссылка на `i.ytimg.com` дала бы пустую обложку в списке.
  Список видео умеет **массовые действия** (`/admin/videos/bulk`): публикация,
  снятие, «на главной» и удаление — импорт приносит записи десятками и
  черновиками, открывать их по одной незачем. Разметка та же, что у новостей
  (`data-bulk-form` + `data-bulk-item`), удаление подтверждается — корзины у
  раздела нет.
- **Постраничный вывод блока «Медиа»** (`App\Core\BlockPager`, галочка
  «Постраничный вывод» у `media_gallery`). Выключена по умолчанию: на главной
  блок остаётся витриной отмеченных «на главной» записей. Включённая галочка
  меняет смысл блока — он показывает **весь опубликованный список** страницами
  по `limit`, и «сколько показывать» становится размером страницы. Для видео
  это единственный способ дойти до старых роликов: публичного раздела «Видео»
  на сайте нет.
  **Номер страницы — свой параметр `?mpage=`**, не общий `page`: страница может
  быть назначена шапкой ленты новостей, и два пейджера подрались бы за один
  параметр. Ссылка ведёт на якорь блока (`#block-<id>`) — иначе переход
  выбрасывает читателя в начало длинной страницы.
  **Вторая и дальше страницы не кэшируются** (`PageBlocks::compile`): ключ кэша
  `page:<id>:<lang>` не знает про параметры адреса, и записанная под ним вторая
  страница галереи уехала бы всем посетителям главной. Номер ограничен сверху
  (`BlockPager::MAX_PAGE`), чтобы `?mpage=999999` не превращался в работу.
  Смешанный источник (видео + фото) листает оба списка вместе: у каждой вкладки
  своя порция на странице, страниц столько, сколько нужно длинному списку.
- **«Показать на главном»** (`is_featured` у projects и photo_albums): блоки
  `image_cards` (источник «Проекты») и `media_gallery` (источники «Фотоальбомы»,
  «Видео» или «media» = оба сразу с вкладками Видео/Фото)
  собирают отмеченные записи автоматически; нет отмеченных → откат на последние.
- i18n публички, переводимые вводные тексты разделов, per-language логотипы.
- **Переводы контента (per-language) у всех текстовых сущностей**: новости
  (`news_translations`), страницы (`page_translations` + блоки), проекты
  (`project_translations`: title, description), команда
  (`team_member_translations`: name, position — переводится и имя!), альбомы
  (`photo_album_translations`), видео (`video_translations`), контент-записи
  (`content_entry_translations`). Паттерн един: RU=база, перевод накладывается
  `Model::localize()`/`localizeRows()` с graceful-fallback к основному языку
  при пустом поле; `Model::published/all/forHome/findPublishedBySlug` принимают
  `?string $lang`. В админ-списках — колонка «Языки» (partial
  `admin/layout/lang_badges`, данные из `Model::availableLangsForIds()`), в
  формах — вкладки перевода (`data-lang-tabs`). Одноязычны только служебные
  разделы (меню, формы, редиректы, пользователи).
- **Два механизма перевода — спрашивай `App\Core\Translations`.** Кроме полей
  в `*_translations` (механизм А) языковая версия бывает **отдельной связанной
  записью** (`lang` + `translation_group_id`, механизм Б) — у новостей, страниц
  и проектов, где у версии свой slug. Код, написанный под один механизм, второй
  не замечает молча: так двуязычная новость уходила в Telegram двумя постами, а
  hreflang вёл на адрес с редиректом. `Translations::rows/langs/paths/primaryId`
  отвечают с учётом обоих; новый код обязан спрашивать там, а не собирать свою
  логику по месту. `primaryId()` — запись, от имени которой действует группа
  (очереди и счётчики адресуются ей, иначе одна новость учитывается дважды).
- Лид/описание страниц, цвета фона/текста/кнопок у блоков.
- **Команда по подразделениям**: у сотрудника сектор (`department`, верхний
  уровень) и отдел/группа (`unit`), оба переводятся. Блок `team_list` умеет
  группировать (якорь секции `#team-<slug>`, slug считается от названия на
  основном языке — ссылка одна для всех языков) и фильтровать по сектору.
  Схема оргструктуры ссылается на состав сектора строкой `Название | /стр#team-…`
  (готовую строку подставляет выбор сектора в форме блока — `App\Core\TeamAnchors`
  собирает адрес по данным команды);
  BlockHints предупредит, если группировка выключена или сектор не найден.
  Поиск по сайту ищет сотрудников и ведёт на страницу с блоком команды.
- **Ассеты, нужные не на каждой странице**, подключает `App\Core\AssetCollector`:
  `JS_MAP`/`CSS_MAP` — скрипты и стили самостоятельных блоков (выводятся после
  дизайн-CSS админки), `THEME_PART_MAP` — части общей темы, вынесенные из
  бандла (выводятся до него, чтобы настройки «Дизайна» продолжали действовать).
  Если ключ совпадает с типом блока, подключение происходит само: список типов
  страницы отдаёт `BlockRenderer::renderPage()`. Вынести новую часть темы —
  `node scripts/split-theme-part.mjs`, см. docs/PERFORMANCE_PLAN.md, раздел 2.1a.
- **Разделитель** (`divider`) — линия, короткая черта, знак-эмблема или пустое
  место. Элемент один — `<hr>`: тематический разрыв это ровно его роль, а
  обычный `<div>` без текста и картинки считался бы пустым блоком и на страницу
  не попал бы (`hr` поэтому и добавлен в список самодостаточных элементов в
  `BlockRenderer::isVisuallyEmpty`). Расстояние вокруг линии задают отступы
  секции — второй настройки того же не заводим; своя высота есть только у
  пустого места. Маска знака приезжает из scoped CSS абсолютным адресом
  (`BlockBackground::emblemUrl`): `var(--gov-emblem)` объявлена относительным
  url и из другого файла разрешается не туда — знак молча не рисуется.
- **Кнопки** (`buttons`) — до трёх действий в ряд, без карточки и заголовка (в
  отличие от «Призыва к действию» с его подложкой и одной кнопкой). Четвёртой
  нет намеренно: это уже меню, и главное действие теряется среди равных.
  **Класса `.btn` в разметке нет**: общее правило темы красит его в navy через
  `!important` и при этом не задаёт отступов — «контурная» и «ссылкой»
  превратились бы в ту же заливку с прижатым к краям текстом. Вид «основная»
  повторяет ту же кнопку своими правилами и теми же токенами. Внешняя вкладка
  получает `rel="noopener noreferrer"` и подпись для диктора.
- **Аккордеона и «Цитаты» отдельными блоками нет** — это FAQ и «Отзывы»:
  разметка (`details/summary`), скрипт и стили у них те же, и блоки-близнецы
  разъехались бы с ними при первой правке. Названия в списке добавления
  блока поэтому упоминают оба применения (стережёт тест 285).
- **Диаграмма** (`chart`) — сравнение величин (полосы), доли целого (одна
  полоса из сегментов) и показатель к цели (шкала). Рисуется разметкой и CSS:
  библиотеку публичная CSP не пропустит, а картинка не переводится, не
  читается диктором и мылится на плотном экране. Данные — построчно
  «Подпись | Значение» (`App\Core\ChartData`), значение принимается как в
  документе: «5,6» и «12 400».
  **Круга и кольца нет намеренно**: доли на круге сравниваются глазом хуже,
  чем на одной полосе, а сегмент меньше пяти процентов там не читается.
  **Подпись и значение — настоящий текст рядом с полосой**, а не подсказка при
  наведении: диктор читает «Транспорт — 24 %», отдельного текстового описания
  диаграмме не нужно, а сама полоса скрыта `aria-hidden`.
  **Палитра долей — шесть фиксированных оттенков в проверенном порядке**
  (`blocks/chart.css`): соседние слоты разведены по различимости при
  дальтонизме (protan ΔE 9.1, tritan 27.0 на светлой поверхности; 8.4 и 23.8 на
  тёмной — считает `scripts/validate_palette.js` навыка dataviz), поэтому
  переставлять их нельзя. Седьмого оттенка нет: он был бы неотличим от
  занятого, и хвост сворачивается в «Прочее» (`ChartData::MAX_SERIES`). Тёмный
  набор — та же шестёрка, пересчитанная под тёмную поверхность, а не
  осветлённая автоматически. Полосы и шкала берут один тон из `--color-accent`.
  Стережёт тест 284.
- **Внешняя врезка** (`embed`) — ролик YouTube, пост Telegram или форма
  Google. Прежде вставить это мог только супер-админ блоком «HTML».
  **Источник опознаётся по ссылке** (`App\Core\EmbedSource`), а не выбирается
  полем: дубликат того, что видно в адресе, редактор рано или поздно поставит
  не тот. **Набор источников закрытый, и это главное решение**: `frame-src
  https:` в CSP пропустил бы любой домен, но произвольный iframe — это чужой
  код на странице (реклама, счётчики, перехват клика), а произвольный код у
  нас доступен только супер-админу, и в обход эта дверь не открывается. Новый
  источник добавляется в `EmbedSource::PROVIDERS` вместе с решением, что ему
  можно доверять. Пост Telegram берётся как `t.me/…?embed=1`, а не официальным
  виджетом: виджету нужен их скрипт на странице. YouTube — на домене без кук.
  **Неопознанная ссылка не выводится вовсе**: посетителю сообщение редактору не
  адресовано, а пустая рамка выглядит поломкой — причину называет подсказка
  `BlockHints` в форме. Своя высота уходит переменной в scoped CSS. Стережёт
  тест 283.
- **Изображение** (`image`) — один снимок с подписью. Прежде одиночной
  картинки было нечем поставить: «Текст с фото» требует текста,
  «Медиагалерея» — сетка, «Слайдер» — карусель. Подпись и источник рисует
  общий компонент `.media-caption`, тот же, что у галереи новости и альбома.
  **Клик делает что-то одно**: заданная ссылка отключает увеличение — два
  действия на один клик редактор не разведёт, а посетитель не угадает.
  Увеличение — это ссылка на сам файл: общий лайтбокс ищет её внутри
  известного контейнера, и блок попадает в `PHOTO_SCOPES` отдельным классом
  `.block-image--zoomable`, поэтому обычный снимок остаётся обычным. Ширины
  две — как у блоков и колонка чтения (`--editorial-reading`); «во всю ширину»
  не дублируется, это настройка секции. Стережёт тест 282.
- **Таблица** (`table`) — реквизиты, тарифы, график приёма, сравнение
  показателей. Ряды набираются **построчно**, ячейки через `|`
  (`App\Core\TableRows`): репитер «ряд с вложенным репитером ячеек» нечитаем —
  чтобы поправить одно число в таблице 6×8, редактор разворачивал бы сорок
  восемь полей. Тот же приём, что у оргструктуры и «Иконки и текста»: таблицу
  видно целиком, её можно вставить из документа и править как текст. Короткий
  ряд добивается пустыми ячейками, лишняя ячейка в длинном **не отбрасывается**
  — набранные данные молча теряться не должны. Шапка размечается
  `th scope="col|row"`, иначе диктор читает набор чисел без смысла. Широкая
  таблица прокручивается **внутри своей рамки** (`role="region"` + `tabindex`):
  горизонтальная прокрутка всей страницы ломает шапку и якорную навигацию, а
  без tabindex до прокрутки не добраться с клавиатуры. Ячейка — простой текст,
  HTML в неё не допускается. Стережёт тест 281.
- **Коллаж** (`collage`) — композиция из разнотипных элементов на общей сетке:
  фотография, плитка с числом, круглая печать и узор. Размещение хранится
  **номерами ячеек** (колонка + ширина, строка + высота), а не координатами:
  свободные X/Y нечем сложить в столбец на телефоне, и проверить их тоже
  нечем. Наложение получается тем, что два элемента занимают одни и те же
  ячейки; кто ниже в репитере — тот сверху, отдельной настройки `z-index`
  нет. Элемент, вылезающий за край полотна, **обрезается до края, а не
  переносится**: перенос сдвинул бы соседей. Правила размещения уходят в
  scoped CSS (инлайн-стили в блоках запрещены тестами), точка фокуса кадра —
  аргументом в `Media::picture`, а не своим `object-position`: рендерер
  печатает её инлайновой переменной у `<img>`, и своё правило либо проиграло
  бы ей, либо затёрло точку из медиатеки. Узоры берутся из
  `BlockBackground::PATTERNS` — второй список тех же градиентов разъехался бы
  с фоном секции. Печать всегда круглая, и диаметр считается по **меньшей**
  стороне ячейки (`min(100cqw,100cqh)`): при `aspect-ratio` с ограничением по
  высоте браузер режет только высоту, и круг становится эллипсом (замерено:
  ячейка 190×170 давала печать 190×170). Надпись по кругу собирает
  `App\Core\CollageBadge` — шаблонам запрещено носить свою геометрию в
  `<svg>`, а кегль там задан **атрибутом**: это доля диаметра в единицах
  viewBox, шкале `--step-*` она не принадлежит. На телефоне сетка складывается
  в столбец, размещение снимается `!important` (у scoped CSS вес по id).
  Стережёт тест 280.
- **Оргструктура** (`org_structure`): совет над руководителем, органы сбоку,
  ветки заместителей рядами по 2–4 колонки (ряды выравниваются: 5 веток при 4
  колонках дают 3+2), ветка без должности = подчинение руководителю напрямую.
  Есть поиск по схеме (галочка в блоке): поле приходит скрытым, открывает и
  фильтрует его `blocks/org_structure.js` — без JS схема остаётся обычным списком.
  Построчная разметка списков разбирается `App\Core\OrgTree`: **отступ в
  начале строки = уровень вложенности** (до четырёх), `Название | /url` —
  ссылка, `* Название` — акцент (проектный офис), `- Название` — прежний
  способ вложить пункт в предыдущий (читается по-старому). Число колонок ряда
  уходит в scoped CSS (инлайн-стили в блоках запрещены тестами).
- **Фирменный слой**: эмблема-гирих — маска `--gov-emblem` (файл
  `public/assets/img/emblem.svg`, заменяется в «Дизайн сайта» → настройка
  `design_emblem`, принимается только свой путь). Используется водяным знаком
  на карточках актов, заглушками карточек без фото и знаком в шапке без лого.
  Маркеры списков (10px) — упрощённая звезда через `clip-path`: настоящая
  эмблема на таком размере превращается в кашу.
  **Маске нужен viewBox.** SVG без него нечем масштабировать — знак не
  рисуется вовсе, хотя файл загружен и настройка сохранена; так же выглядит
  файл, не разобравшийся при загрузке (`Uploader::sanitizeSvgString` кладёт
  вместо него заглушку 1×1). Оба случая ловит `App\Core\Emblem::check()`:
  негодный файл не сохраняется молча, а форма «Дизайна» пишет причину.
  Загрузка достраивает viewBox по `width`/`height`, если он не задан;
  уже лежащий файл чинит `php scripts/check_emblem.php --fix`.
- **Карточки правовых актов** — вариант `acts` блока «Документы»: у документа
  появляются `number` и `date`, поиск по блоку учитывает реквизиты.
- **Оглавление страницы** — у `anchor_nav` галочки «авто» и «закреплять».
  В авторежиме разделы собираются из заголовков блоков (`BlockRenderer::
  pageSections()`, якорь = id секции); липкой делается вся секция, иначе
  `position: sticky` не работает. Подсветка раздела — `blocks/anchor_nav.js`.
- Telegram-публикация новостей, webpush, email-дайджест, формы, редиректы,
  открытые данные, календарь мероприятий, каталоги (`/catalog/{type}`),
  портал репозитория файлов (`/repo`: категории с подкатегориями, загрузка
  пользователями с премодерацией), 2FA, аудит входов, CSP через nonce.
- TinyMCE в админке: цитаты, верхний/нижний индекс и базовое форматирование.
  Демо-контент запускается только из «Настройки сайта» после ввода `DEMO`.
- **Реальный контент Агентства** — фикстура `database/content/agency_content.php`
  (страницы «Об Агентстве», «Руководство», профили руководителя и первого
  заместителя на RU/UZ/EN + записи «Команды»), применяется
  `php database/seed_agency_content.php` (есть `--dry-run`; вся логика —
  `App\Core\AgencyContentSeeder`, её гоняет DB-тест 230). Скрипт заменяет
  блоки этих страниц целиком, поэтому после выкладки контент правят в админке,
  а не повторным запуском. Ключи блоков в фикстуре обязаны совпадать с
  `BlockTypeRegistry::DEFAULTS` — иначе первое сохранение в админке их потеряет
  (стережёт тест 227). Эту же фикстуру накладывает `DemoSeeder` последним
  шагом, поэтому свежая установка сразу получает реальные страницы
  руководства, а не вымышленного директора (тест 229).
- **Настройки отображения** (`App\Core\A11ySettings`, панель `site/_a11y_panel.php`,
  `a11y.css` + `a11y.js`): выдвижная панель справа — размер текста 100–200 %,
  контраст (обычный/чёрно-белый/тёплый) плюс общий переключатель тёмной темы,
  шрифт, интервалы, режим чтения, скрытие картинок, остановка анимаций,
  подчёркивание ссылок. Состояние — cookie `a11y` в формате query-строки,
  применяется на сервере атрибутами `data-a11y-*` на `<html>` (без мигания).
  Тема живёт в своём переключателе (`window.asdrSetTheme`), в настройках не
  дублируется. Cookie прежней версии (`cw:l:on`) переносится автоматически.
- **Короткое название языка** (`languages.short_name`, поле «Короткое» в
  разделе «Языки»): компактный переключатель показывает «Рус»/«Oʻzb», а не код
  страницы. Пусто — берутся первые буквы названия (`Language::shortLabel()`).
- **Узбекская кириллица** (`App\Core\UzCyrillic`): переключатель письменности в
  той же панели (виден только на UZ) и отдельным пунктом «Ўзбекча» в
  переключателе языков; ссылки ведут на `/script/{latn|cyrl}?to=…`
  (`Site\ScriptController`, адрес возврата проверяется на открытый редирект). Перевод делается на готовой странице в
  `View::render` — в БД остаётся латиница, кэш блоков не множится. Не трогаются
  теги, атрибуты, script/style/code/pre, сущности, ссылки и почта, а также любой
  элемент с атрибутом `data-no-translit`.
- **«Меньше движения» — один признак на весь фронт**: `window.asdrReduceMotion()`
  (объявлен в `theme-init.js`) учитывает и системный `prefers-reduced-motion`,
  и тумблер «остановка анимаций» из панели (`data-a11y-motion="off"`). CSS гасит
  только `animation`/`transition`, поэтому фоновое видео обложки и таймеры
  автопрокрутки спрашивают помощник, а не медиазапрос, и не кэшируют ответ:
  настройку переключают на лету. Панель шлёт событие `asdr:motion-change`.
- Доступность: разметка содержит aria/skip-link и настройки контраста, а axe-аудит
  идёт в CI — `tests/browser/a11y.spec.js` проверяет главную, ленту новостей, поиск
  и узбекскую версию в светлой и тёмной темах (WCAG 2.0/2.1/2.2 A и AA), на десктопе
  и на мобильном; кроме них — детальная новость, проект, каталог и страница с
  формой (там нарушений больше всего). Ручная проверка остаётся за тем, что axe
  не умеет: порядок табуляции, осмысленность alt и формулировок для диктора.

## Репетиция восстановления (`App\Core\RestoreDrill`)
Копия, которую ни разу не восстанавливали, бэкапом не является. Ручной
`database/restore.php` требует трёх аргументов, поэтому на cron его не вешают —
и `release_check` годами повторял «восстановление ни разу не проверялось».
`app/Console/restore_drill.php` делает то же самое сам: берёт свежий архив,
сверяет контрольную сумму **до** восстановления (битый архив — самый частый и
самый тихий отказ бэкапа), разворачивает в отдельную базу и временный каталог,
проверяет содержимое и убирает за собой.
**Боевую базу репетиция не трогает никогда, и это проверяется до работы, а не
после**: имя целевой базы сверяется набором символов (оно уходит в
`CREATE DATABASE`/`DROP DATABASE`, где параметр не подставить), затем — с
именем рабочей; **неизвестное имя рабочей базы это тоже отказ**, потому что
доказать «мы не на ней» тогда нечем.
Успехом считается не «дамп залился», а `verifyContent()`: без него пустой дамп
проходил бы за успех — таблицы созданы, строк нет. Проверяются основные таблицы
и наличие хотя бы одной учётной записи (войти в копию без неё нечем). Отметка
`.last_restore_check` ставится **только после успеха** — иначе release_check
считал бы свежей провалившуюся репетицию; провал уходит в Telegram.

## Обновление с GitHub (`App\Core\Updater`, `scripts/update.php`)
Выкладка была ручной: скачать ZIP из Releases, сверить сумму, залить по FTP,
накатить миграции. Пропустить можно любой шаг, и пропускали обычно сверку
суммы — самый тихий из отказов. `php scripts/update.php --check | --dry-run |
<url>` делает всю последовательность сам и **останавливается на первой
неудаче**: релиз → архив и `.sha256` → сверка → проверка состава → полная
резервная копия и снимок заменяемых файлов → режим обслуживания → замена →
миграции → эталон целостности → кэш → `release_check` и smoke.
**Собирает архив workflow «Release package», и запускает его публикация
релиза** (`release: types: [published]`), а не пуш тега. Прежде там стояло
`push: tags: 'v*'`, а теги в репозитории называются `2.4`, `2.7-final`,
`3108` — ни один не начинается с `v`, поэтому сборка не запускалась ни разу с
июля и релизы выходили без установочного архива. Отказ был невидимым: релиз
публикуется, ассетов у него нет, узнают об этом, только когда архив
понадобится. Тег-триггер убран, а не добавлен рядом: публикация через
интерфейс создаёт и тег, и оба события запустили бы сборку дважды. Ассеты
кладутся в уже существующий релиз (`gh release upload --clobber`), потому что
им же сборка и запущена.
**Второй путь — ручной запуск из Actions** (`workflow_dispatch`, `publish:
true` плюс имя): публикация кнопкой доступна только в интерфейсе, и без этого
пути релиз стало нечем выпустить из командной строки или по API. Там релиза
ещё нет, поэтому `gh release create`, а не `upload`; рекурсии не возникает —
события, созданные встроенным `GITHUB_TOKEN`, новых запусков workflow не
порождают. Стережёт тест 291.
**Ставится только собранный архив** `asdr-cms-*.zip` вместе с `.sha256`.
«Source code» не годится (в нём тесты, `.github`, `composer.json`), архив без
суммы — тоже: сверять целостность будет нечем. Релиз без такого архива это
отказ с объяснением, а не установка чего попало: неверная форма дерева снесла
бы структуру сайта.
**Данные сайта неприкосновенны** (`isPreserved`): `config/config.php`,
`storage/`, `public/uploads/`. **Устаревшие файлы удаляются**, но только из
каталогов, которыми владеет релиз (`OWNED_DIRS`: `app`, `templates`,
`scripts`, `database`, `public/assets`) — оставить их нельзя, старый обработчик
с уязвимостью продолжал бы отвечать; удалять за их пределами тоже нельзя, там
данные. Всё удаляемое сначала копируется в снимок отката.
**Адрес репозитория — из окружения** (`UPDATE_REPO`), не из настроек в панели:
настройка дала бы редактору увести обновление на чужой репозиторий, то есть
выполнить свой код на сервере. Ходим только на закрытый список доменов GitHub
и только по https; редиректы (ассеты отдаёт CDN) проходим вручную, проверяя
каждый шаг, — `CURLOPT_FOLLOWLOCATION` увёл бы на любой хост.
**Замену файлов не выполняет веб-запрос** — вот это правило и стережёт тест
291: запрос обрывается по таймауту, и обрыв посреди замены оставит половину
старых файлов и половину новых. Кнопка в панели при этом есть
(`/admin/update`, супер-админ): она **ставит задачу** (`UpdateState::queue`) и
на этом запрос заканчивается, а работу делает `app/Console/update_worker.php`
по cron. Воркер отдельный, а не задача в общей очереди: у `JobQueue` аренда
строки 60 секунд, зависшей задача считается через 600, обновление длиннее — и
вторая копия воркера подхватила бы его посреди замены файлов.
**Без живого cron кнопка не нажимается**: намерение записано, а выполнять его
некому — нажатие выглядело бы как «ничего не произошло», худший вид отказа.
Свежесть воркера контроллер спрашивает у `Heartbeat::lastRun('update')`.
**Опасная последовательность одна на панель и на консоль** — `App\Core\
UpdateRunner`. Две копии разъехались бы при первой правке: проверка суммы
появилась бы в одной, снимок для отката — в другой. `scripts/update.php`
остаётся ради случая, когда панель недоступна, и зовёт тот же бегунок;
`--dry-run` считает план через `UpdateRunner::preview()`, чтобы пробный прогон
показывал ровно то, что потом произойдёт. Миграции и эталон целостности
применяются **в том же процессе** (`MigrationRunner::applyPending`,
`Integrity::writeBaseline`), а не запуском дочернего: `passthru`/`exec` на
shared-хостинге часто запрещены, и обновление обрывалось бы сразу после замены
файлов — в самом неудачном месте.
**Режим обслуживания принадлежит обновлению** (`App\Core\UpdateState`).
Включается перед заменой файлов, снимается в `finally` — то есть и после
отказа с откатом тоже, — и возвращается **в то состояние, в каком его
застали** (`maintenance_before`): сайт, закрытый владельцем на профилактику,
обновление открывать не вправе. А если процесс убили (таймаут хостинга, OOM,
перезагрузка), снимать флаг некому — поэтому на каждом шаге пишется отметка
времени, а воркер при следующем запуске закрывает молчащее дольше
`STALE_AFTER` (15 минут) обновление.
**Но сам сайт после такого обрыва открывается не всегда, и это главная
развилка.** Обрыв до замены оставляет сайт целым — его надо открыть; обрыв во
время замены оставляет половину старых файлов и половину новых, и открытый
такой сайт отдаёт 500 всем подряд, а закрытый — честные 503 и понятную
страницу. Поэтому прямо перед `Updater::apply()` ставится отметка
`files_touched`: пока её нет, `public/index.php` спрашивает
`UpdateState::maintenanceStuck()` и заглушку не показывает даже при мёртвом
cron; после неё сайт остаётся закрытым, а панель (она доступна и при закрытом
сайте) объясняет случившееся и даёт кнопку сброса. Там нужен человек: возможно,
разворачивать резервную копию.

## Сигнал наружу (`App\Core\HeartbeatPing`)
Сторож (`app/Console/watchdog.php`) видит молчащие воркеры, застрявшие очереди
и кончающийся диск — но живёт он на том же сервере: упал сервер или cron, упал
и сторож, и о простое никто не узнает. Поэтому **чистый проход** сторожа
пингует внешний приёмник (healthchecks.io, Better Uptime, любой cron-монитор):
тревогу поднимает не наш сигнал, а его отсутствие.
Отсюда два следствия. Сигнал уходит **только когда проблем нет**: пинг при
известных проблемах прятал бы их от приёмника — сторож молчал бы ровно тогда,
когда нужен. И неудача пинга **не роняет проход**: не дозвонились до приёмника
— это его тревога, а не наша.
Адрес — в переменной окружения `MONITORING_HEARTBEAT_URL`, рядом с
`HEALTH_CHECK_TOKEN`, а не в настройках админки: в нём секретный идентификатор
приёмника, и настройка в панели дала бы редактору увести сигнал на чужой адрес.
Не задан — функция выключена целиком (в сеть не ходим), `release_check`
предупреждает. Запрос идёт через `Http::getSafeRemote` (проверка публичности
хоста + закрепление IP): адрес из окружения, но опечатка не должна превращать
сторож в инструмент обхода сети. Стережёт тест 288.

## Микроразметка (`App\Core\SchemaOrg`)
Уже есть: `GovernmentOrganization` в шапке каждой страницы
(`SeoHelper::organizationSchema`), `BreadcrumbList` в крошках, `NewsArticle` на
странице новости, `Event` у мероприятия, Open Graph и Twitter Card
(`OpenGraphHelper`), полный `hreflang` с `x-default`. Отдельного метода
`SchemaOrg::organization()` в бою нет — его место занял `SeoHelper`
(сверяет тест 171).
**`FAQPage` выводит блок «Вопросы и ответы»**, и на страницу он допускается
ровно один: два таких блока дали бы две разметки, а поисковик отбрасывает обе.
Право забирает первый блок (`SchemaOrg::claimFaqPage`), флаг сбрасывает
`BlockRenderer::renderPage` вместе со счётчиком h1 — иначе вторая страница в
одном процессе осталась бы без разметки. Ответ кладётся **текстом**: HTML в
JSON-LD не допускается, а тег между словами заменяется пробелом, иначе
«форму&lt;br&gt;или» склеивается в одно слово. Пара без вопроса или без ответа
пропускается: неполную разметку поисковик отбрасывает целиком.

## Проверка индексации (раздел «Поиск и индексация»)
`App\Core\Seo\SeoAudit` отвечает на вопрос «почему страница может не попасть в
поиск» — и это не отчёт поисковой системы, а причина, по которой отчёт будет
плохим: Google и Яндекс показывают следствие с задержкой в сутки-трое, здесь
причина видна сразу и **без единого ключа доступа**. Часть проверок считается
по базе (карта сайта, описания, дубли заголовков, редирект поверх живой
страницы), часть требует HTTP-обхода своего сайта — и таких ровно столько,
сколько нужно: `robots.txt`, `sitemap.xml` и выборка из
`SeoAudit::SAMPLE_SIZE` живых адресов. **Полного обхода тут нет намеренно**:
noindex и чужой canonical — системные ошибки, они либо есть у всех страниц
типа, либо нет ни у одной, а полный обход на каждый запуск cron — это часы
работы ради тех же выводов (обходом занимается `scripts/smoke.php`).
`SeoAudit::SITEMAP_NEWS_LIMIT` обязан совпадать с `LIMIT` в
`SitemapController`: карта обрезает новости молча, без ошибки, и проверка
существует ровно ради этого случая (стережёт тест 286). Снимки ложатся в
`seo_audits` (модель `App\Models\SeoAudit`, хранение 90 дней) — история
отвечает на первый вопрос по любой находке: «это новое или так было всегда».
Запуск — `app/Console/seo_worker.php` по cron (ненулевой код возврата при
ошибках) и кнопкой в `/admin/seo` (только супер-админ: проверка ходит по сети
от имени сайта).

## Грабли (уже наступали)
- **Сокращённый `transition` с CSS-переменной минификатор выбрасывает.**
  `transition: --hdr-scrim .3s ease` в исходнике выглядит правильно, а в
  `public.min.css` объявления просто нет — анимации не будет, и ошибку видно
  только замером вычисленных стилей. Пишем longhand:
  `transition-property` / `transition-duration` / `transition-timing-function`.
  Сама переменная анимируема, только если объявлена через `@property` с
  `syntax: '<number>'`.
- **Новая версия PHP выключала сайт целиком.** `ErrorHandler` превращает любую
  ошибку в исключение, а PHP 8.5 пометил устаревшим то, что вчера работало
  молча: `PDO::MYSQL_ATTR_*`, `curl_close()`, `imagedestroy()`,
  `$http_response_header`. Драйверная константа читается при каждом соединении
  с БД, поэтому 500 отдавала любая страница. Теперь `E_DEPRECATED` и
  `E_USER_DEPRECATED` уходят в `storage/logs/error.log` (уровень `DEPRECATED`,
  одинаковое сообщение за запрос пишется один раз), остальные ошибки
  по-прежнему становятся исключением — молчаливое предупреждение это потерянные
  данные. Драйверные атрибуты PDO берутся из подкласса драйвера
  (`Pdo\Mysql::ATTR_*`), а список устаревших вызовов стережёт тест 263.
- **Минимум — PHP 8.4, боевой сервер на 8.5.** Планка стоит там же в четырёх
  местах: `EnvironmentCheck` (установщик), `scripts/release_check.php`,
  `composer.json` и матрица CI. Поднимать её ради самого подъёма незачем —
  версия сервера от этого не меняется; 8.4 выбран как первая версия с
  подклассами драйверов PDO, из-за которых исчез класс-помощник, и оставляет
  один шаг запаса вниз, если хостинг откатит версию.
- **Языковой префикс не создаёт второго адреса служебным областям.**
  `LocalePreference::managesPath()` исключает `/admin`, `/repo`, `/install`,
  `/health`, `/sitemap.xml` и прочие машинные ответы — но смотрит на **путь
  запроса**, и `/uz/admin/users` под её исключения не подпадал: роутер срезал
  префикс и вёз запрос к настоящему обработчику `/admin/users`. Опасен был не
  сам маршрут (контроллеры защищены `requireLogin`/`requireSuperAdmin`), а
  проверки, которые стоят **до** роутера и сверяют путь запроса строкой
  `str_starts_with($path, '/admin')`: онбординг второго фактора в
  `public/index.php` (ограниченная сессия получала всю панель) и
  `AdminEntryGate` — скрытый адрес панели вместе с IP-allowlist (`/admin/login`
  отдавал 404, `/uz/admin/login` — форму входа). Проверка срезанного пути живёт
  в `Router::resolveLocale()`, в единственном месте, где префикс снимается:
  список проверок до роутера ещё вырастет, и каждая повторяла бы ошибку.
  Ответ — 404: локализованной версии у служебной области не бывает. Стережёт
  тест 290, он же следит, что публичный префикс (`/uz/news`) не закрыт заодно.
- **Произвольный код — только супер-админ, и только внешними файлами.** Поля
  страницы `custom_css`/`custom_js` (`CustomAssetHelper`) публикуют свой код
  файлами через `GeneratedCss`/`GeneratedJs`, инлайна в HTML нет. Адрес с
  чужого домена сам по себе не заработает: публичная CSP разрешает только
  `'self'`, поэтому шапка/подвал докладывают origin в директиву через
  `SecurityHeaders::allowPageAssets()` (вьюхи рендерятся в буфер — заголовок
  ещё можно переслать; под `/admin` подмена запрещена, чтобы не ослаблять CSP
  панели). Роль `editor` эти поля и разметку блока «HTML» не меняет — сервер
  сохраняет прежнее значение, что бы ни пришло в форме.
- **Тесты, пишущие в `settings`, обязаны звать `reset_design_state()`** (tests/lib.php)
  в начале. Файлы кейсов сортируются **строкой**, поэтому `111_*` идёт раньше
  `33_*`: тест, оставивший `design_*` в БД, роняет соседей на чистой базе CI, а
  локально — только на следующем прогоне. Сброс удаляет строки, а не пишет '':
  для части ключей пустое значение и отсутствие — разное поведение.
- **Вход в админку — два вторых фактора**: приложение-аутентификатор (TOTP,
  `App\Core\TOTP`, секрет в `users.totp_secret` через `SecretBox`) и код в
  Telegram. Достаточно любого; без обоих сессия ограничена профилем
  (`2fa_setup_required`, белый список путей в `public/index.php`). TOTP не
  зависит от сети — им и снимается риск запереть себя без Telegram.
  **Шаг TOTP одноразовый** (`users.totp_last_step`, `repo_users.totp_last_step`,
  `Model::consumeTotpStep`): окно проверки ±1 шаг по 30 секунд, и без отметки
  подсмотренный код оставался бы рабочим полторы минуты. Проверка возвращает
  номер шага — `TOTP::matchStep()`, `verify()` поверх неё.
  **Подключение и отключение канала подтверждаются паролем** — иначе угнанная
  сессия привязывает к аккаунту свой аутентификатор и получает постоянный
  второй фактор.
  **Ролей ровно две** — те, что перечисляет `ENUM users.role`: `admin`
  (супер-админ) и `editor`. Имена живут в `RbacGuard::ROLE_*`; прежний
  `super_admin` был недостижим (ENUM его не принимал), но `Auth` считал его
  полным доступом, а `RbacGuard` — нет, и такая роль не могла бы ничего.
  **WebAuthn/Passkey нет.** Заглушка подтверждала вход одним `credential_id`
  без подписи и challenge; удалена вместе с таблицей `user_passkeys`
  (миграция `2026_08_23_drop_user_passkeys.sql`). Настоящий WebAuthn — это
  CBOR/COSE и проверка подписи, заводить его придётся с нуля.
- **Напоминания редактору** (`App\Core\ContentChecklist`): свёрнутая полоса
  над формой новости — нет обложки, анонса, рубрики, SEO-описания, хештегов,
  подписей к фото, перевода (у опубликованных). Ничего не блокирует: в
  `store/update` чек-лист не участвует, тест это стережёт.
- **Подписи к фотографиям**: у галереи новости и снимков альбома есть
  «Подпись» и «Автор/источник» (`news_images.caption/credit`,
  `photo_album_images.credit`) — свободный ввод, без переводов. Вывод — один
  компонент `.media-caption` (12px, акцентная грань слева, без капслока) на
  все три места: слайдер новости, фотолента, альбом. Обложка берёт подпись из
  своей записи галереи по совпадению пути. В rich-пост Telegram уходит
  `<figcaption>` с `<cite>`.
- **Формат постов в Telegram**: `App\Core\TelegramRichMessage` собирает
  rich-сообщение (Bot API 10.1+, `sendRichMessage`): заголовок, слайд-шоу,
  полный текст, второй язык под `<details>`, сноска с хештегами и подписью.
  Предел 32768 знаков против 1024 у подписи к фото. Снимки в разметке — только
  ссылками `tg://photo?id=…`, файлы уходят полем `media` (прямой https в `<img>`
  API не принимает); `reply_markup` метод принимает, поэтому кнопки есть и там.
  Настройка
  `social_telegram_format` (auto|rich|classic): «auto» пробует новый формат и
  при отказе Telegram молча откатывается на sendPhoto/sendMessage. В обычном
  формате длинный текст уходит отдельным сообщением, а не режется.
- **Telegram — один раздел `/admin/telegram`** (`TelegramController`): бот →
  привязка админа (коды входа) → канал → уведомления. Токен бота живёт в
  `telegram_bot_token`; `social_telegram_token` — необязательное
  переопределение (отдельный бот-публикатор), при пустом значении
  `SocialSettings::configFor('telegram')` берёт основной. Gateway
  (`telegram_gateway_token`) — другой платный сервис, к Bot API отношения не
  имеет. Ответ Bot API **`Not Found` = неверный токен** (токен — часть URL
  `/bot<токен>/`), `chat not found` — неверный chat_id, `not enough rights` —
  бот не админ канала; диагностика — `SocialPublisher::checkTelegram()`.
  **Не добавляй ключи Telegram в `SettingsController::TEXT_KEYS`**: их полей в
  той форме нет, и сохранение затрёт токены пустой строкой.
- **Сообщение админки обязано доехать до глаз.** Flash рисуется как `.alert`
  вверху `.admin-main`, а обработчики возвращают на якорь
  (`/admin/telegram#telegram-channel`) — браузер сразу уезжает к секции, и
  сообщение остаётся выше экрана. Поэтому `layout/footer.php` превращает flash
  в тост **любого типа**, а не только success: пока тостом дублировался один
  успех, ошибка «Определить ID канала» была не видна вообще и кнопка выглядела
  сломанной. Тост висит сверху по центру (внизу справа его теряют), ошибку по
  таймеру не гасим — в ней написано, что делать. Иконку для такого тоста берём
  **только из `Icon::RUNTIME_ICONS`**: символы для спрайта ищет регулярка по
  готовому HTML, а внутри JS-строки кавычки экранированы, и она их не находит —
  иконка молча выйдет пустой.
- **Файл, который PHP собрал сам, надо открыть на чтение явно.** Загрузка из
  формы приходит через `move_uploaded_file()` и получает права по umask, а
  файл из `tempnam()` — 0600. Статику отдаёт веб-сервер, и такой файл он не
  прочитает: картинка выходит битой и в админке, и на сайте, хотя запись в
  медиатеке есть и файл на диске лежит (так пропали все кадры-превью после
  первого импорта с YouTube). `Uploader::storeFromPath()` теперь делает
  `chmod 0644` сам; уже загруженное чинит `php scripts/fix_upload_permissions.php`
  (есть `--dry-run`, заодно показывает пустые файлы — по ним видно, что дело не
  в правах).
- **`lastInsertId()` после `bustPageCache()` = 0**: `bustPageCache()` делает запрос
  к settings (CDN/Cloudflare), обнуляющий last insert id при холодном кэше. В
  `create()` читай id **до** сброса кэша. (Исправлено в Project/News/TeamMember.)
- **Отступ якоря под шапкой объявлен один раз.** Плавная прокрутка к якорю у
  нас нативная (`html { scroll-behavior: smooth }` вне `prefers-reduced-motion`),
  а вот остановиться она должна ниже закреплённой шапки — иначе заголовок
  раздела оказывается прямо за ней. Держит это `scroll-padding-top` у `html`
  (`html:has(.site-header--sticky)`), высоту меряет `frontend.js` в
  `--scroll-offset`: макетов шапки четыре, константой их не покрыть. Раньше то
  же самое делали константы у каждого вида цели (`.cms-block[id]` — 64px,
  `.block-team__group` — 90px), и они складывались с общим отступом, а якоря
  вопроса или новости не покрывались вовсе. У `.cms-block[id]` остался только
  `--anchornav-top` — высота липкой полосы оглавления, которая стоит **под**
  шапкой. Второй константы сюда добавлять нельзя (стережёт тест 200).
- **Обработчик прокрутки не читает раскладку на каждом событии.** На инерционной
  прокрутке событий несколько за кадр, и чтение `scrollHeight` в каждом из них
  заставляет браузер пересчитывать раскладку — ход становится рваным. Полоса
  прогресса и страховка карточек считают раз в кадр (`requestAnimationFrame` с
  флагом «уже запланировано»), высота документа берётся на `resize`/`load`.
  **JS-«плавной прокрутки» (Lenis и подобные) в проекте нет и не будет:** она
  подменяет системную прокрутку своей инерцией, ломает скорость колеса,
  PageUp/PageDown, поиск по странице и жесты тачпада — на госсайте это дороже
  эффекта.
- **`width:100vw` даёт горизонтальный скролл** на ширину скроллбара. Лечится
  `html { overflow-x: clip }` (не `hidden` — не ломает sticky-шапку).
- **SVG-логотип схлопывается**, если у SVG нет пиксельных размеров (`width="100%"`).
  Нужна явная `height` на `img`, тогда ширина считается из viewBox.
- **Локальные сервисы не считаются постоянными**: перед smoke-проверкой убедиться,
  что БД и PHP-сервер запущены. Headless-браузер может использовать
  overlay-скроллбары (0px), поэтому scrollbar-баги в нём воспроизводятся не всегда.
- **Playwright**: зависимости фиксируются в `package-lock.json`. Локально:
  `npm ci`, затем при необходимости `npx playwright install chromium` и
  `npm run test:browser`. Для инъекции скриптов на страницы с CSP используется
  `bypassCSP: true`.
