# ArtStudio CMS — заметки для Claude

Цель файла: быстрый старт без перечитывания всей ветки. Здесь — карта проекта,
договорённости и команды. Обновляй при заметных изменениях архитектуры.

## Что это
Госсайт «Агентство стратегического развития…». Тестовый адрес — **artstudio.uz**
(прежний asr.artstudio.uz больше не существует).
Собственная CMS: **чистый PHP 8.2+ без runtime-зависимостей Composer**,
MySQL/MariaDB. Composer/PHPStan и npm/Playwright нужны только разработке и CI. Свой
автозагрузчик (`app/Core/bootstrap.php`), свой роутер (`public/index.php`),
свой тест-раннер. Деплой — shared-хостинг (cPanel), поэтому: никаких внешних
зависимостей времени выполнения, всё работает на голом PHP+cURL.

## Режим экономии (по умолчанию)
Владелец бережёт лимиты. Работать максимально экономно по токенам:
- Минимум лишних чтений: сначала `CLAUDE.md`, потом точечно нужный файл (Grep/Read
  диапазона), не «осматривать» всю ветку. Не перечитывать то, что уже видел.
- Не проверять то, что не менял. Верификация — соразмерно правке (мелкая CSS-правка
  не требует полного smoke). Для проверки сайта — `scripts/smoke.php`, а не ручные скрины.
- Ответы короткие и по делу, без длинных пересказов и списков опций. Не гонять
  тесты/сборки без причины. Батчить независимые вызовы инструментов в один шаг.

## Договорённости с владельцем (важно)
- Работать **автономно**, не переспрашивать по мелочам; решения объяснять кратко.
- **Не всё делать буквально**: если просьба спорна — сначала коротко объяснить,
  почему стоит/не стоит, потом делать.
- Перед изменениями синхронизировать `main`, работать в отдельной тематической
  ветке и публиковать через PR. Не коммитить напрямую в `main`, если владелец
  явно не попросил об этом.
- **Не переводить админку** (интерфейс админки — по-русски). Переводится только
  публичная часть (RU=ключ, UZ-словарь) и контент (per-language в БД).
- Коммиты — короткие и осмысленные; не добавлять служебные идентификаторы
  модели или сессии в коммиты, PR, код и артефакты.
- **Не хардкодить бренд-акцент** `--gov-teal` (он настраивается в админке через
  `--color-accent`). Для затемнений использовать `color-mix`, не фикс-цвет.

## Как запустить локально

Нужны PHP 8.2+ и MySQL/MariaDB. В Linux-контейнере БД при необходимости
поднимается отдельно; встроенный PHP-сервер запускается с router-файлом,
поскольку он не читает `.htaccess`.
```bash
sudo service mariadb start                     # или: mysqld_safe &
php -S 127.0.0.1:8000 -t public public/router.php
```
Базы: `asdr_cms` (демо-контент), `asdr_test` (для тестов — имя жёстко ждут
тесты и CI, `tests/load_schema.php asdr_test` заливает схему). Доступ
root@127.0.0.1 без пароля. Если админ-пароль неизвестен — сбросить в БД
(`users.password_hash`, `password_hash()`), логин `admin`.

## Проверки (вместо ручного клика)
```bash
# Полный прогон: 1152 сценария; без TEST_DB_* 181 DB-сценарий пропускается
TEST_DB_HOST=127.0.0.1 TEST_DB_DATABASE=asdr_test TEST_DB_USERNAME=root TEST_DB_PASSWORD= php tests/run.php

# Smoke-обход всего сайта (HTTP+PHP-фаталы), RU+UZ, публичка и вся админка.
# --totp обязателен, когда у админа включено приложение-аутентификатор:
# без него обход не проходит второй фактор и админку просто пропускает.
php scripts/smoke.php http://127.0.0.1:8000 --admin admin:ПАРОЛЬ --totp СЕКРЕТ
```
На боевом сервере к этому добавляются `scripts/release_check.php` (в т.ч. DNS
почты SPF/DKIM/DMARC, свежесть репетиции восстановления, наличие эталона
целостности) и `app/Console/integrity_check.php` — почасовая сверка SHA-256
файлов кода с эталоном, алерт в Telegram при подмене (`App\Core\Integrity`,
эталон пересобирает `scripts/release.php`).

После правок PHP: `php -l <файл>`. Сброс кэша страниц: `rm -rf storage/cache/page/*`
(в админке — кнопка «Сброс кэша» в шапке).

## Навык impeccable (дизайн-ревью)
Установлен в `.claude/skills/impeccable` (Apache 2.0, pbakaus/impeccable) — вызов
`/impeccable`, полезен как второй взгляд на публичную часть. В релизный архив не
попадает (`/.claude export-ignore`). Его предложения принимаются только в рамках
проекта: акцент берётся из админки (`--color-accent`), инлайн-стили в блоках
запрещены тестами (scoped CSS через `$templateCss`), анимации уважают
`prefers-reduced-motion` и настройку «остановка анимаций», контраст текста не
ниже 4.5:1, после правок CSS/JS — `npm run build:assets`. Админку не трогаем.

## Архитектура — где что лежит
- **Блоки страниц** (конструктор): `app/Core/BlockRenderer.php`
  (`DEFAULTS` = список типов и их поля; `enrichData()` = блоки-обёртки, которые
  тянут данные из БД), шаблоны — `templates/blocks/*.php`, редактор полей —
  `app/Views/admin/pages/block_form.php`, сохранение (whitelist полей) —
  `app/Controllers/Admin/BlockController.php::collectData()`.
- **Контейнеры** (`BlockTypeRegistry::CONTAINER_TYPES` = `columns`, `tabs`):
  содержимое — вложенные блоки (`blocks.parent_block_id` + `column_index` =
  номер колонки/вкладки), шаблона нет, рендер программный
  (`BlockRenderer::renderColumns/renderTabs`). Контейнер в контейнер не
  вкладывается. Вкладки без JS показывают все панели подряд; переключение
  надстраивает `public/assets/js/blocks/tabs.js`. Подробности — docs/BLOCKS.md.
- **Условия показа блока** — `App\Core\BlockVisibility` (ключи `_visible_from`,
  `_visible_to`, `_visible_device` в data блока). Расписание считается на
  сервере: блок вне окна вообще не попадает в HTML. Устройство — классами
  `.cms-block--only-mobile/desktop`, потому что кэш страницы общий для всех
  посетителей. `BlockRenderer::renderPage()` отдаёт `expires_at` (ближайшая
  граница расписания), `PageController` по ней пересобирает кэш — иначе баннер
  «до 30 июля» висел бы и 31-го.
- **Страница-раздел**: любую страницу можно назначить шапкой ленты `/news`
  или списка `/projects` (`pages.section` = `news|projects`, поле «Шапка
  раздела» в сайдбаре формы). Она отдаёт разделу заголовок, лид и SEO, а её
  блоки выводятся **под** списком (`App\Core\SectionPage`, `Page::forSection`).
  Роль одна на язык — назначение забирает её у прежней страницы; собственный
  адрес у страницы остаётся. Раздел не назначен — работают прежние строки из
  шаблона.
- **Проект — это страница с подтипом** (`pages.entity_type` = `page|project`).
  Отдельных таблиц у проектов нет: и чтение, и запись идут в `pages` с фильтром
  по типу (`App\Models\Project`). Обложка, «показать на главном» и ручной
  порядок — колонки `pages`; `pages.lead` у проекта это анонс для карточки, а
  тело собирается блоками тем же конструктором, что и у страниц (общий партиал
  `admin/pages/_block_editor.php`). Форма проекта: паспорт (название, адрес,
  анонс, обложка, статус, порядок, «на главном») плюс конструктор — второго
  места для содержимого нет.
  **Различаются записи по `entity_type`**: свой раздел админки и своя форма у
  каждого типа, форма страницы отдаёт 404 на проект (и наоборот, `Project::`
  не видит страниц), публичный адрес страницы — `/slug`, проекта —
  `/projects/slug`, slug уникален внутри типа. Любой новый список по `pages`
  обязан фильтровать тип.
  **Язык у проекта один механизм** — отдельная запись своего языка
  (`lang` + `translation_group_id`, кнопка «Создать перевод» в сайдбаре),
  slug у версий общий. Старых таблиц (`projects`, `project_translations`,
  `project_images`, `project_fields`) не осталось: миграция
  `2026_08_13_projects_into_pages.sql` переносит галерею и свободные поля в
  блоки и удаляет их, свежая установка их и не создаёт.
- **Модели** — `app/Models/*` (Project, News, PhotoAlbum, TeamMember, Page,
  MenuItem, Setting, …). Много `SELECT *`; статусы published/draft, мягкое удаление.
- **i18n публички**: `App\Core\Lang` + глобальный `t()` (`app/Core/helpers.php`),
  словарь `app/Core/lang/uz.php` (RU-строка → UZ). Контент — таблицы `*_translations`.
- **Тема/дизайн-токены**: `public/assets/css/frontend.css` (база) →
  `public/assets/css/gov-theme.css` (активная тема, идёт после базы;
  navy `--gov-navy`, teal `--gov-teal`, свет/тьма через `:root[data-theme]`).
  **Размеры шрифта берутся только из шкалы** `--step--4 … --step-12` в `:root`
  (`--step-0` = 1rem): статичных `rem` в `font-size` не осталось, новые
  подбирать заново нельзя — стережёт тест 236. Ступени намеренно неравномерны
  (~8 % у текста, до 25 % у заголовков) и статичны: `clamp`-версия замерена и
  отклонена, она уменьшала текст на телефонах на 20–38 %.
  a11y-слой — `a11y.css`. JS фронта — `public/assets/js/frontend.js`.
  Публичная страница загружает сгенерированные `public.min.css` и
  `public.min.js`; после изменения исходников выполнить `npm run build:assets`.
  CI проверяет актуальность и Brotli-бюджет командой `npm run check:assets`.
- **Точки перелома публички — общая шкала**: `480, 560, 640, 720, 900, 1000,
  1100, 1360` (парный `min-width` = граница + 1: 561, 721, 901, 1001, 1361).
  Других значений в публичном CSS быть не должно — стерегут тесты 232. Раньше
  их было 33 (680, 760, 820, 980, 1040, 1180…), и соседние правила
  переключались на разных ширинах. Исключение одно: пара **768/769** у
  `.cms-block--only-mobile/desktop` — это контракт условий показа блоков
  (`BlockVisibility`), а не оформление; сдвиг границы поменял бы, кому блок
  виден, поэтому её не трогаем и на неё не вешаем стили. Отдельно помни:
  `901px` — граница мобильной раскладки сеток (`GridBalance`), а схема
  оргструктуры складывается в столбец на `900px` (на 910px четыре колонки
  ещё держатся без переполнения).
- **Шапка/подвал**: `App\Core\HeaderConfig` / `FooterConfig` (JSON в settings),
  вьюхи `app/Views/site/_header.php`, `_footer.php`. Логотипы — общий + светлый
  (для тёмного фона) + по языкам (`logo_by_lang`, `logo_light_by_lang`). Поиск
  рендерится только в выбранном варианте; код футер-счётчиков хранится в
  `footer_counters` и получает CSP-nonce при выводе.
- **Переиспользуемые компоненты форм**: `App\Core\ImageField::resolve()`
  (пустое присланное поле = очистка!), `AdminUi::imageField()`, `AdminUi::colorField()`.
- **Миграции**: `database/migrations/*.sql`, применяет `database/migrate.php`
  (трекинг в таблице `migrations`). **`schema.sql` обязан совпадать**: при новой
  миграции добавь и колонки в CREATE TABLE, и файл в список
  `INSERT INTO migrations(...) VALUES` (иначе падает тест консистентности).
- **Ряды карточек без дыр**: `App\Core\GridBalance` считает дорожки сетки и
  ширину карточки (`--grid-track`/`--grid-span` в scoped CSS блока). Колонок
  берётся столько, чтобы в последнем ряду не осталась одинокая карточка
  (пятёрка ложится 3+2), а карточки хвоста растягиваются на всю ширину.
  Используют `advantages` и `docs_list`; мобильную раскладку задаёт тема,
  поэтому растяжение живёт в `@media (min-width:901px)`.
- **Появление при скролле** — только прогрессивное улучшение: `_reveal` с
  типом `stagger` (`data-reveal-items`) прячет карточки классом, который вешает
  JS, поэтому без JS всё видно. Обычный `data-reveal` прячет блок сразу в CSS —
  для ключевого контента (профиль руководителя) его не включаем, а страховка
  `@media (scripting: none)` возвращает видимость при отключённом JavaScript.
- **Иконки**: `App\Core\Icon::render()` отдаёт `<use href="#tabler-…">`, а
  `Icon::injectSprite()` (вызывается из `View::render`) вырезает нужные
  `<symbol>` из вендорного спрайта по индексу
  `app/Core/data/tabler-sprite-index.php` и встраивает их после `<body>`.
  Ключи берутся из готового HTML, а не из счётчика вызовов — блоки приходят
  из кэша. Иконки, которые вставляет JS уже после загрузки, перечислены в
  `Icon::RUNTIME_ICONS` (сверяется тестом с `frontend.js`). Индекс
  пересобирается `npm run build:vendor`. Полный спрайт (2 МБ) грузится только
  пикером иконок в админке.
- **CDN**: `App\Core\Asset` (версионирование `?v=hash` + префикс CDN),
  `Asset::rewriteMedia()` переписывает `/uploads/public` в HTML на CDN.
  Pull-zone CDN (BunnyCDN и т.п.) — без переноса домена. `App\Core\Cloudflare` —
  purge через API (только если домен проксируется через CF).
- **CI**: `.github/workflows/ci.yml` — 4 джобы: php -l + тесты на PHP 8.2/8.3/8.4
  с MariaDB; PHPStan **блокирующий** (`composer analyse`) + `composer audit`;
  проверка синтаксиса JS (`node --check`); browser smoke на Chromium (Playwright).

## Реализованные фичи (чтобы не изобретать заново)
- Конструктор шапки/футера (drag-and-drop зон), 4 макета, отдельный мобильный билдер.
- Hero (видео/фото/overlay, бесшовное loop-видео без кнопок), счётчики,
  направления, новости (лента + крупная), медиа-галерея, проекты, команда, FAQ и т.д.
- Блоки-обёртки, тянущие данные из БД: `news_latest/news_feature/news_docs`
  (новости), `projects_list` (проекты), `team_list` (команда).
- **Категории новостей** (`news_categories` + `news_category_translations`,
  модель `App\Models\NewsCategory`): рубрика — запись со slug и переводимым
  названием, `news.category_id` — ссылка. Slug один на все языки (это адрес и
  ключ выборки), переводится только название; механизм А. Раздел админки —
  `/admin/news-categories`, выбор — в сайдбаре формы новости, в списке новостей
  колонка «Категория» и фильтр (`?category=<id>|none`), у блоков новостей поле
  «Категория новостей», на публичке — рубрикатор `?category=<slug>`.
  **Метка (`news.badge`) — это не категория**: необязательная пометка
  («Важно», «Анонс») со своим цветом фона (`news.badge_color`); цвет текста
  считается по контрасту — `App\Core\NewsBadge` (он же рендерит разметку для
  всех трёх мест вывода). Старые бейджи-рубрики переносит разовый скрипт
  `php database/migrate_news_badges.php` (есть `--dry-run`).
- **«Показать на главном»** (`is_featured` у projects и photo_albums): блоки
  `image_cards` (источник «Проекты») и `media_gallery` (источники «Фотоальбомы»,
  «Видео» или «media» = оба сразу с вкладками Видео/Фото)
  собирают отмеченные записи автоматически; нет отмеченных → откат на последние.
- i18n публички, переводимые вводные тексты разделов, per-language логотипы.
- **Переводы контента (per-language) у всех текстовых сущностей**: новости
  (`news_translations`), страницы (`page_translations` + блоки), проекты
  (`project_translations`: title, description), команда
  (`team_member_translations`: name, position — переводится и имя!), альбомы
  (`photo_album_translations`), видео (`video_translations`), контент-записи
  (`content_entry_translations`). Паттерн един: RU=база, перевод накладывается
  `Model::localize()`/`localizeRows()` с graceful-fallback к основному языку
  при пустом поле; `Model::published/all/forHome/findPublishedBySlug` принимают
  `?string $lang`. В админ-списках — колонка «Языки» (partial
  `admin/layout/lang_badges`, данные из `Model::availableLangsForIds()`), в
  формах — вкладки перевода (`data-lang-tabs`). Одноязычны только служебные
  разделы (меню, формы, редиректы, пользователи).
- **Два механизма перевода — спрашивай `App\Core\Translations`.** Кроме полей
  в `*_translations` (механизм А) языковая версия бывает **отдельной связанной
  записью** (`lang` + `translation_group_id`, механизм Б) — у новостей, страниц
  и проектов, где у версии свой slug. Код, написанный под один механизм, второй
  не замечает молча: так двуязычная новость уходила в Telegram двумя постами, а
  hreflang вёл на адрес с редиректом. `Translations::rows/langs/paths/primaryId`
  отвечают с учётом обоих; новый код обязан спрашивать там, а не собирать свою
  логику по месту. `primaryId()` — запись, от имени которой действует группа
  (очереди и счётчики адресуются ей, иначе одна новость учитывается дважды).
- Лид/описание страниц, цвета фона/текста/кнопок у блоков.
- **Команда по подразделениям**: у сотрудника сектор (`department`, верхний
  уровень) и отдел/группа (`unit`), оба переводятся. Блок `team_list` умеет
  группировать (якорь секции `#team-<slug>`, slug считается от названия на
  основном языке — ссылка одна для всех языков) и фильтровать по сектору.
  Схема оргструктуры ссылается на состав сектора строкой `Название | /стр#team-…`;
  BlockHints предупредит, если группировка выключена или сектор не найден.
  Поиск по сайту ищет сотрудников и ведёт на страницу с блоком команды.
- **Ассеты, нужные не на каждой странице**, подключает `App\Core\AssetCollector`:
  `JS_MAP`/`CSS_MAP` — скрипты и стили самостоятельных блоков (выводятся после
  дизайн-CSS админки), `THEME_PART_MAP` — части общей темы, вынесенные из
  бандла (выводятся до него, чтобы настройки «Дизайна» продолжали действовать).
  Если ключ совпадает с типом блока, подключение происходит само: список типов
  страницы отдаёт `BlockRenderer::renderPage()`. Вынести новую часть темы —
  `node scripts/split-theme-part.mjs`, см. docs/PERFORMANCE_PLAN.md, раздел 2.1a.
- **Оргструктура** (`org_structure`): совет над руководителем, органы сбоку,
  ветки заместителей рядами по 2–4 колонки (ряды выравниваются: 5 веток при 4
  колонках дают 3+2), ветка без должности = подчинение руководителю напрямую.
  Построчная разметка списков разбирается `App\Core\OrgTree`: **отступ в
  начале строки = уровень вложенности** (до четырёх), `Название | /url` —
  ссылка, `* Название` — акцент (проектный офис), `- Название` — прежний
  способ вложить пункт в предыдущий (читается по-старому). Число колонок ряда
  уходит в scoped CSS (инлайн-стили в блоках запрещены тестами).
- **Фирменный слой**: эмблема-гирих — маска `--gov-emblem` (файл
  `public/assets/img/emblem.svg`, заменяется в «Дизайн сайта» → настройка
  `design_emblem`, принимается только свой путь). Используется водяным знаком
  на карточках актов, заглушками карточек без фото и знаком в шапке без лого.
  Маркеры списков (10px) — упрощённая звезда через `clip-path`: настоящая
  эмблема на таком размере превращается в кашу.
- **Карточки правовых актов** — вариант `acts` блока «Документы»: у документа
  появляются `number` и `date`, поиск по блоку учитывает реквизиты.
- **Оглавление страницы** — у `anchor_nav` галочки «авто» и «закреплять».
  В авторежиме разделы собираются из заголовков блоков (`BlockRenderer::
  pageSections()`, якорь = id секции); липкой делается вся секция, иначе
  `position: sticky` не работает. Подсветка раздела — `blocks/anchor_nav.js`.
- Telegram-публикация новостей, webpush, email-дайджест, формы, редиректы,
  открытые данные, календарь мероприятий, каталоги (`/catalog/{type}`),
  портал репозитория файлов (`/repo`: категории с подкатегориями, загрузка
  пользователями с премодерацией), 2FA, аудит входов, CSP через nonce.
- TinyMCE в админке: цитаты, верхний/нижний индекс и базовое форматирование.
  Демо-контент запускается только из «Настройки сайта» после ввода `DEMO`.
- **Реальный контент Агентства** — фикстура `database/content/agency_content.php`
  (страницы «Об Агентстве», «Руководство», профили руководителя и первого
  заместителя на RU/UZ/EN + записи «Команды»), применяется
  `php database/seed_agency_content.php` (есть `--dry-run`; вся логика —
  `App\Core\AgencyContentSeeder`, её гоняет DB-тест 230). Скрипт заменяет
  блоки этих страниц целиком, поэтому после выкладки контент правят в админке,
  а не повторным запуском. Ключи блоков в фикстуре обязаны совпадать с
  `BlockTypeRegistry::DEFAULTS` — иначе первое сохранение в админке их потеряет
  (стережёт тест 227). Эту же фикстуру накладывает `DemoSeeder` последним
  шагом, поэтому свежая установка сразу получает реальные страницы
  руководства, а не вымышленного директора (тест 229).
- **Настройки отображения** (`App\Core\A11ySettings`, панель `site/_a11y_panel.php`,
  `a11y.css` + `a11y.js`): выдвижная панель справа — размер текста 100–200 %,
  контраст (обычный/чёрно-белый/тёплый) плюс общий переключатель тёмной темы,
  шрифт, интервалы, режим чтения, скрытие картинок, остановка анимаций,
  подчёркивание ссылок. Состояние — cookie `a11y` в формате query-строки,
  применяется на сервере атрибутами `data-a11y-*` на `<html>` (без мигания).
  Тема живёт в своём переключателе (`window.asdrSetTheme`), в настройках не
  дублируется. Cookie прежней версии (`cw:l:on`) переносится автоматически.
- **Узбекская кириллица** (`App\Core\UzCyrillic`): переключатель письменности в
  той же панели (виден только на UZ) и отдельным пунктом «Ўзбекча» в
  переключателе языков; ссылки ведут на `/script/{latn|cyrl}?to=…`
  (`Site\ScriptController`, адрес возврата проверяется на открытый редирект). Перевод делается на готовой странице в
  `View::render` — в БД остаётся латиница, кэш блоков не множится. Не трогаются
  теги, атрибуты, script/style/code/pre, сущности, ссылки и почта, а также любой
  элемент с атрибутом `data-no-translit`.
- **«Меньше движения» — один признак на весь фронт**: `window.asdrReduceMotion()`
  (объявлен в `theme-init.js`) учитывает и системный `prefers-reduced-motion`,
  и тумблер «остановка анимаций» из панели (`data-a11y-motion="off"`). CSS гасит
  только `animation`/`transition`, поэтому фоновое видео обложки и таймеры
  автопрокрутки спрашивают помощник, а не медиазапрос, и не кэшируют ответ:
  настройку переключают на лету. Панель шлёт событие `asdr:motion-change`.
- Доступность: разметка содержит aria/skip-link и настройки контраста; автоматический
  axe-аудит пока не входит в CI и остаётся обязательной ручной проверкой перед релизом.

## Грабли (уже наступали)
- **Произвольный код — только супер-админ, и только внешними файлами.** Поля
  страницы `custom_css`/`custom_js` (`CustomAssetHelper`) публикуют свой код
  файлами через `GeneratedCss`/`GeneratedJs`, инлайна в HTML нет. Адрес с
  чужого домена сам по себе не заработает: публичная CSP разрешает только
  `'self'`, поэтому шапка/подвал докладывают origin в директиву через
  `SecurityHeaders::allowPageAssets()` (вьюхи рендерятся в буфер — заголовок
  ещё можно переслать; под `/admin` подмена запрещена, чтобы не ослаблять CSP
  панели). Роль `editor` эти поля и разметку блока «HTML» не меняет — сервер
  сохраняет прежнее значение, что бы ни пришло в форме.
- **Тесты, пишущие в `settings`, обязаны звать `reset_design_state()`** (tests/lib.php)
  в начале. Файлы кейсов сортируются **строкой**, поэтому `111_*` идёт раньше
  `33_*`: тест, оставивший `design_*` в БД, роняет соседей на чистой базе CI, а
  локально — только на следующем прогоне. Сброс удаляет строки, а не пишет '':
  для части ключей пустое значение и отсутствие — разное поведение.
- **Вход в админку — два вторых фактора**: приложение-аутентификатор (TOTP,
  `App\Core\TOTP`, секрет в `users.totp_secret` через `SecretBox`) и код в
  Telegram. Достаточно любого; без обоих сессия ограничена профилем
  (`2fa_setup_required`, белый список путей в `public/index.php`). TOTP не
  зависит от сети — им и снимается риск запереть себя без Telegram.
- **Напоминания редактору** (`App\Core\ContentChecklist`): свёрнутая полоса
  над формой новости — нет обложки, анонса, рубрики, SEO-описания, хештегов,
  подписей к фото, перевода (у опубликованных). Ничего не блокирует: в
  `store/update` чек-лист не участвует, тест это стережёт.
- **Подписи к фотографиям**: у галереи новости и снимков альбома есть
  «Подпись» и «Автор/источник» (`news_images.caption/credit`,
  `photo_album_images.credit`) — свободный ввод, без переводов. Вывод — один
  компонент `.media-caption` (12px, акцентная грань слева, без капслока) на
  все три места: слайдер новости, фотолента, альбом. Обложка берёт подпись из
  своей записи галереи по совпадению пути. В rich-пост Telegram уходит
  `<figcaption>` с `<cite>`.
- **Формат постов в Telegram**: `App\Core\TelegramRichMessage` собирает
  rich-сообщение (Bot API 10.1+, `sendRichMessage`): заголовок, слайд-шоу,
  полный текст, второй язык под `<details>`, сноска с хештегами и подписью.
  Предел 32768 знаков против 1024 у подписи к фото. Снимки в разметке — только
  ссылками `tg://photo?id=…`, файлы уходят полем `media` (прямой https в `<img>`
  API не принимает); `reply_markup` метод принимает, поэтому кнопки есть и там.
  Настройка
  `social_telegram_format` (auto|rich|classic): «auto» пробует новый формат и
  при отказе Telegram молча откатывается на sendPhoto/sendMessage. В обычном
  формате длинный текст уходит отдельным сообщением, а не режется.
- **Telegram — один раздел `/admin/telegram`** (`TelegramController`): бот →
  привязка админа (коды входа) → канал → уведомления. Токен бота живёт в
  `telegram_bot_token`; `social_telegram_token` — необязательное
  переопределение (отдельный бот-публикатор), при пустом значении
  `SocialSettings::configFor('telegram')` берёт основной. Gateway
  (`telegram_gateway_token`) — другой платный сервис, к Bot API отношения не
  имеет. Ответ Bot API **`Not Found` = неверный токен** (токен — часть URL
  `/bot<токен>/`), `chat not found` — неверный chat_id, `not enough rights` —
  бот не админ канала; диагностика — `SocialPublisher::checkTelegram()`.
  **Не добавляй ключи Telegram в `SettingsController::TEXT_KEYS`**: их полей в
  той форме нет, и сохранение затрёт токены пустой строкой.
- **`lastInsertId()` после `bustPageCache()` = 0**: `bustPageCache()` делает запрос
  к settings (CDN/Cloudflare), обнуляющий last insert id при холодном кэше. В
  `create()` читай id **до** сброса кэша. (Исправлено в Project/News/TeamMember.)
- **`width:100vw` даёт горизонтальный скролл** на ширину скроллбара. Лечится
  `html { overflow-x: clip }` (не `hidden` — не ломает sticky-шапку).
- **SVG-логотип схлопывается**, если у SVG нет пиксельных размеров (`width="100%"`).
  Нужна явная `height` на `img`, тогда ширина считается из viewBox.
- **Локальные сервисы не считаются постоянными**: перед smoke-проверкой убедиться,
  что БД и PHP-сервер запущены. Headless-браузер может использовать
  overlay-скроллбары (0px), поэтому scrollbar-баги в нём воспроизводятся не всегда.
- **Playwright**: зависимости фиксируются в `package-lock.json`. Локально:
  `npm ci`, затем при необходимости `npx playwright install chromium` и
  `npm run test:browser`. Для инъекции скриптов на страницы с CSP используется
  `bypassCSP: true`.
