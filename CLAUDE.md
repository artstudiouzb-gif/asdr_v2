# ArtStudio CMS — заметки для Claude

Цель файла: быстрый старт без перечитывания всей ветки. Здесь — карта проекта,
договорённости и команды. Обновляй при заметных изменениях архитектуры.

## Что это
Госсайт «Агентство стратегического развития…». Тестовый адрес — **artstudio.uz**
(прежний asr.artstudio.uz больше не существует).
Собственная CMS: **чистый PHP 8.4+ без runtime-зависимостей Composer**,
MySQL/MariaDB. Composer/PHPStan и npm/Playwright нужны только разработке и CI. Свой
автозагрузчик (`app/Core/bootstrap.php`), свой роутер (`public/index.php`),
свой тест-раннер. Деплой — shared-хостинг (cPanel), поэтому: никаких внешних
зависимостей времени выполнения, всё работает на голом PHP+cURL.

## Режим экономии (по умолчанию)
Владелец бережёт лимиты. Работать максимально экономно по токенам:
- Минимум лишних чтений: сначала `CLAUDE.md`, потом точечно нужный файл (Grep/Read
  диапазона), не «осматривать» всю ветку. Не перечитывать то, что уже видел.
- Не проверять то, что не менял. Верификация — соразмерно правке (мелкая CSS-правка
  не требует полного smoke). Для проверки сайта — `scripts/smoke.php`, а не ручные скрины.
- Ответы короткие и по делу, без длинных пересказов и списков опций. Не гонять
  тесты/сборки без причины. Батчить независимые вызовы инструментов в один шаг.

## Договорённости с владельцем (важно)
- Работать **автономно**, не переспрашивать по мелочам; решения объяснять кратко.
- **Не всё делать буквально**: если просьба спорна — сначала коротко объяснить,
  почему стоит/не стоит, потом делать.
- Перед изменениями синхронизировать `main`, работать в отдельной тематической
  ветке и доводить работу до `main` **только через PR — всегда, без
  исключений**. Прямой push в `main` запрещён: на репозитории включено правило
  «Changes must be made through a pull request», и push его обходит (GitHub
  пишет в журнал `Bypassed rule violations`).
  Полный цикл — не «создать PR и остановиться», а довести до конца:
  ветка → PR → **подписка на события PR** (`subscribe_pr_activity`) →
  чинить падения CI и отвечать на комментарии ревью → мерж по зелёному CI.
  Оставлять висящий PR и ждать, что его вольёт владелец, не нужно.
- Влитый PR закрыт и новые коммиты не отслеживает. Если работа продолжается
  после мержа — это новая ветка от свежего `main` и новый PR, а не push в
  старую ветку (иначе коммит уходит «в никуда»: именно так потерялся фикс
  контраста после PR #129).
- **Не переводить админку** (интерфейс админки — по-русски). Переводится только
  публичная часть (RU=ключ, UZ-словарь) и контент (per-language в БД).
- Коммиты — короткие и осмысленные; не добавлять служебные идентификаторы
  модели или сессии в коммиты, PR, код и артефакты.
- **Не хардкодить бренд-акцент** `--gov-teal` (он настраивается в админке через
  `--color-accent`). Для затемнений использовать `color-mix`, не фикс-цвет.

## Как запустить локально

Нужны PHP 8.4+ и MySQL/MariaDB. В Linux-контейнере БД при необходимости
поднимается отдельно; встроенный PHP-сервер запускается с router-файлом,
поскольку он не читает `.htaccess`.
```bash
sudo service mariadb start                     # или: mysqld_safe &
php -S 127.0.0.1:8000 -t public public/router.php
```
Базы: `asdr_cms` (демо-контент), `asdr_test` (для тестов — имя жёстко ждут
тесты и CI, `tests/load_schema.php asdr_test` заливает схему). Доступ
root@127.0.0.1 без пароля. Если админ-пароль неизвестен — сбросить в БД
(`users.password_hash`, `password_hash()`), логин `admin`.

## Проверки (вместо ручного клика)
```bash
# Полный прогон: 1293 сценария; без TEST_DB_* 199 DB-сценариев пропускается
TEST_DB_HOST=127.0.0.1 TEST_DB_DATABASE=asdr_test TEST_DB_USERNAME=root TEST_DB_PASSWORD= php tests/run.php

# Smoke-обход всего сайта (HTTP+PHP-фаталы), RU+UZ, публичка и вся админка.
# --totp обязателен, когда у админа включено приложение-аутентификатор:
# без него обход не проходит второй фактор и админку просто пропускает.
php scripts/smoke.php http://127.0.0.1:8000 --admin admin:ПАРОЛЬ --totp СЕКРЕТ
```
На боевом сервере к этому добавляются `scripts/release_check.php` (в т.ч. DNS
почты SPF/DKIM/DMARC, свежесть репетиции восстановления, наличие эталона
целостности) и `app/Console/integrity_check.php` — почасовая сверка SHA-256
файлов кода с эталоном, алерт в Telegram при подмене (`App\Core\Integrity`,
эталон пересобирает `scripts/release.php`).

После правок PHP: `php -l <файл>`. Сброс кэша страниц: `rm -rf storage/cache/page/*`
(в админке — кнопка «Сброс кэша» в шапке).

## Навык impeccable (дизайн-ревью)
Установлен в `.claude/skills/impeccable` (Apache 2.0, pbakaus/impeccable) — вызов
`/impeccable`, полезен как второй взгляд на публичную часть. В релизный архив не
попадает (`/.claude export-ignore`). Его предложения принимаются только в рамках
проекта: акцент берётся из админки (`--color-accent`), инлайн-стили в блоках
запрещены тестами (scoped CSS через `$templateCss`), анимации уважают
`prefers-reduced-motion` и настройку «остановка анимаций», контраст текста не
ниже 4.5:1, после правок CSS/JS — `npm run build:assets`. Админку не трогаем.

## Архитектура — где что лежит
- **Блоки страниц** (конструктор): `app/Core/BlockRenderer.php`
  (`defaults()` = список типов и их поля; `enrichData()` = блоки-обёртки, которые
  тянут данные из БД), шаблоны — `templates/blocks/*.php`, редактор полей —
  `app/Views/admin/pages/block_form.php`, сохранение (whitelist полей) —
  `app/Controllers/Admin/BlockController.php::collectData()`.
  **Настройка блока объявляется один раз — в схеме полей**
  (`App\Core\BlockData\BlockFieldSchema`, тип поля описывает `Field`). Из
  описания получаются умолчание, поле формы, нормализация присланного и
  приведение сохранённых данных на выводе (`apply()` зовёт `BlockRenderer`), так
  что шаблон читает `$data` как есть. Прежде то же самое лежало в четырёх
  местах — реестр, форма, `collectData()`, шаблон, — и списки значений
  расходились молча: форма отдавала значение, нормализатор принимал, шаблон о
  нём не знал и откатывался к умолчанию. Переезд типов постепенный: на схеме
  `columns`, `tabs`, `partners`, `advantages`, `testimonials`, `projects_list`,
  `faq`, `stages`, `docs_list`, `subscribe`, `slider`, `person_cards`,
  `contact_cards`, `icon_text`, `cta`, `counters`, `cards_grid`,
  `media_gallery`, `news_latest`, `news_feature`, `news_docs`, `map_point`,
  `text_image`, `anchor_nav`, `timeline`, `team_list`, `person_profile`,
  `leader_card`, `org_structure`, `bio_education` (у них в
  `BlockTypeRegistry::BASE_DEFAULTS`
  пустой массив — ключ остаётся ради порядка типов в редакторе), остальные
  по-старому. Число из закрытого набора — `Field::intChoice`, и значение вне
  набора заменяется умолчанием, а не ближайшим допустимым: в списке его нет,
  значит форма подделана. Картинка, иконка и цвет — тоже виды полей
  (`Field::media/icon/color`): их рисуют готовые виджеты `AdminUi`, поэтому
  условие показа вешается обёрткой снаружи, а соседние цвета схема сама
  собирает в `.colorfield-row`. `Field::mediaPosition` — единственное поле,
  владеющее двумя ключами (`image_position` и тот же ключ с `_mobile`): виджет
  рисует оба списка сразу, и разносить их по двум описаниям значило бы
  разложить один элемент управления на половины. Тесты, проверяющие «настройка доступна редактору»,
  обязаны читать `block_editor_markup()` (форма + поля схемы), а не один
  `block_form.php`. Мимо схемы идут репитеры (`items`) и значения, зависящие от
  соседнего поля (`ratio` зависит от числа колонок) — их умолчания в
  `BlockFieldSchema::EXTRA`. Стережёт тест 275.
- **Ритм ленты новостей** (`App\Core\NewsFeedRhythm`): каждая пятая карточка
  сетки `/news` — широкая, с анонсом и фотографией сбоку. Ширина ровно **две
  ячейки**, а не вся строка: группа «4 компактные + 1 широкая» даёт 6 ячеек, а
  шесть делится и на 4 колонки, и на 3, и на 2 — ряды остаются полными на любой
  ширине. Отсюда и размер страницы (`PAGE_SIZE` = 10, то есть 12 ячеек): менять
  его, не сверившись с этой арифметикой, — значит получить дыру посреди ленты.
  На узком экране растяжение снимается: `span 2` в одноколоночной сетке создаёт
  вторую колонку и горизонтальную прокрутку.
- **Контейнеры** (`BlockTypeRegistry::CONTAINER_TYPES` = `columns`, `tabs`):
  содержимое — вложенные блоки (`blocks.parent_block_id` + `column_index` =
  номер колонки/вкладки), шаблона нет, рендер программный
  (`BlockRenderer::renderColumns/renderTabs`). Контейнер в контейнер не
  вкладывается. Вкладки без JS показывают все панели подряд; переключение
  надстраивает `public/assets/js/blocks/tabs.js`. Подробности — docs/BLOCKS.md.
- **Условия показа блока** — `App\Core\BlockVisibility` (ключи `_visible_from`,
  `_visible_to`, `_visible_device` в data блока). Расписание считается на
  сервере: блок вне окна вообще не попадает в HTML. Устройство — классами
  `.cms-block--only-mobile/desktop`, потому что кэш страницы общий для всех
  посетителей. `BlockRenderer::renderPage()` отдаёт `expires_at` (ближайшая
  граница расписания), `PageController` по ней пересобирает кэш — иначе баннер
  «до 30 июля» висел бы и 31-го.
- **Обложка (Hero) — отдельный тип контента**, а не содержимое блока. Запись в
  `heroes` (общие настройки JSON + статус draft/published/scheduled с окном
  показа и приоритетом) плюс её слайды в `hero_slides` (`sort_order` —
  он же порядок показа, `is_active`, поля слайда JSON) и переводы текста в
  `hero_slide_translations` (механизм А: медиа и раскладка у слайда общие для
  всех языков, переводится только текст). Раздел админки — `/admin/heroes`:
  список слайдов с превью, перетаскиванием, дублированием и включением;
  сам слайд правится на своей странице (полей полсотни, в репитере они не
  помещаются). Блок страницы «Обложка» хранит только `hero_id` и ничего больше
  — одну обложку можно вывести на нескольких страницах. `hero_id = 0` —
  старая обложка, собранная прямо в блоке; такие страницы работают по-прежнему.
  Классы: `App\Core\Hero\HeroSettings` (контракт общих настроек),
  `HeroSlideData` (поля слайда; **пустое значение оформления = «как у
  обложки»**, явное «нет» — это `none`), `HeroPresets` (Editorial, Government,
  Navy, Full Image, Video, Minimal — разовое действие, ничего не блокирует),
  `HeroRenderer` (разметка и scoped CSS). Фронт — `blocks/hero.css` +
  `blocks/hero.js`, подключаются по ключу `hero_slides` (не по типу блока:
  старой обложке они не нужны).
  **У слайда осталось только то, что зависит от кадра.** Раскладка, размеры
  текста и палитра принадлежат обложке: переопределения у слайда удваивали
  настройку и молча расходились с ней. От кадра к кадру меняются фотография,
  наложение поверх неё и цвет текста (`content_scheme`) — они и остались.
  Настроек всего 79 (31 у обложки, 48 у слайда) — было 123.
  **Наложение — не «затемнение», а вуаль любого цвета:** тёмная затемняет кадр,
  светлая осветляет. От плотности 25 % оно решает за кадр: по светлоте вуали
  выбирается цвет текста (`HeroRenderer::veilIsLight`). Для прозрачной шапки в
  счёт идёт только **сплошное** наложение — градиент гуще там, где текст, и к
  другому краю сходит на нет, а шапка тянется во всю ширину.
  **Свой цвет текста главнее автоподбора:** классы `hero--content-light/dark`
  объявляют `--hero-fg` на `.hero__text`, то есть глубже схемы, и затирали
  выбранный цвет. Схема `custom` со своим цветом даёт `hero--content-custom`,
  под который правил нет. Явный выбор «светлый/тёмный» главнее и того, и
  другого — это решение редактора.
  **Отступ всего текста сверху** — `text_offset_top` у обложки, переменная
  `--hero-text-offset`. Отдельной настройки для телефона нет: на узком экране
  значение ограничивается `min(Npx,10vh)`, поэтому крупный отступ не выдавит
  текст за экран, а небольшой не изменится. Промежутки между частями текста
  (`--hero-gap-*` в `blocks/hero.css`) настройкой не являются — это
  типографика, и у первой части они сняты.
  **Поведение автопрокрутки не настраивается**: пауза при наведении и после
  действия посетителя, возобновление через 10 секунд и отсутствие
  автопрокрутки на телефоне зашиты в `blocks/hero.js`. Настройки — только
  «включить» и интервал (у слайда бывает своя `duration`).
  **Каждая настройка обязана что-то менять на выводе** — тест 269 рендерит
  обложку дважды (умолчание против изменённого значения) и требует различий;
  зависимые проверяются в контексте, где действуют. Новая настройка обязана
  получить там пробу, иначе тест падает.
  **Кадр-замена лежит под видео всегда.** Поэтому «видео не загрузилось»,
  «автовоспроизведение запрещено», «выключено на телефоне» и «меньше движения»
  — это один сценарий, а не четыре: скрыть видео, под ним уже готовый кадр.
  Iframe YouTube сервер не отдаёт вовсе — его создаёт скрипт и оставляет
  прозрачным, пока плеер не ответит на `{"event":"listening"}`; не ответил за
  4 секунды — iframe убирается. Пустой обложки не бывает ни при каком отказе.
  **Цвет разведён на два уровня:** схема обложки (`scheme`: light/dark/navy/
  custom) красит фон и её собственный текст, `content_scheme` (auto/light/dark)
  — только текст. Цвет объявлен переменной `--hero-fg` на `.hero__text`, а не
  каскадом `color`, поэтому вложенный компонент со своей поверхностью
  (`.hero__surface`) переопределяет её у себя и остаётся тёмным на светлом.
  **Навигация не перекрывает контент:** она лежит отдельной полосой, а
  `.hero__inner` резервирует под неё `--hero-nav-space`. Но соседний блок
  перекрыть её может: тема надвигает «Счётчики» на низ обложки
  (`margin-top` объявлен в gov-theme дважды, действует последний —
  `clamp(-100px,-7vw,-60px)`, и на телефоне тоже). Поэтому полоса поднимается
  на `--hero-nav-bottom`; величину сверяет тест — разъедется с темой, и стрелки
  снова пропадут.
  **«Во всю ширину» — это фон, а не контент:** `.hero--w-full` выходит из
  контейнера страницы (`margin-inline: calc(50% - 50vw)`), а `.hero__inner`
  держит текст в колонке сайта и выравнивает его по остальным блокам
  (`--hero-gutter` = боковой отступ `.site-content`).
  **Фоновая надпись** (`watermark`) — крупное слово за контентом. Это
  декорация из текста, поэтому обязательств три: переводится наравне с
  заголовком (колонка в `hero_slide_translations`), `aria-hidden` — иначе
  диктор читает её посреди заголовка, — и `pointer-events:none`, иначе слово
  шириной в экран накрывает кнопки. Настроек пять и они одинаковы у слайда и
  у секции: текст, `watermark_size` (**числом**, в % ширины экрана: нужный
  кегль зависит от длины слова, пресетом «крупная / средняя» его не угадать),
  привязка `watermark_x/y` и `watermark_opacity`. Смещений по осям, контура с
  толщиной, своего цвета и выбора семейства нет — слово рисуется цветом текста
  секции или обложки и потому видно на любой схеме. Размер намеренно **не из
  шкалы `--step-*`** — шкала для читаемого текста, а декорация растёт вместе с
  экраном (стережёт тест 249, он же сверяет наборы обеих поверхностей).
  Та же надпись есть у любой секции (`_watermark*` в data блока,
  `.cms-block__watermark`); там текст перевода не требует — блоки у каждого
  языка свои.
  **Свой CSS-класс слайда** (`css_class`) — аварийный выход для оформления,
  которого нет в полях: класс вешается на слайд, стили пишутся в «Свой CSS»
  страницы (супер-админ). Значение чистится жёстко (имя класса с буквы,
  до пяти штук) — оно уходит в атрибут.
  **Длительность показа бывает своя у слайда** (`duration`, 0 = как у обложки):
  таймер и полоса прогресса считают по ней, а не по общему интервалу.
  «Меньше движения» гасится множителем `--hero-motion` (0/1), а не `!important`.
- **Страница-раздел**: любую страницу можно назначить шапкой ленты `/news`
  или списка `/projects` (`pages.section` = `news|projects`, поле «Шапка
  раздела» в сайдбаре формы). Она отдаёт разделу заголовок, лид и SEO, а её
  блоки выводятся **под** списком (`App\Core\SectionPage`, `Page::forSection`).
  Раздел не назначен — работают прежние строки из шаблона.
  **Устроено как главная, и это не аналогия ради красоты.** Язык разрешается
  тем же порядком, что в `findHome`: запись нужного языка с ролью → запись
  нужного языка **из группы перевода** → и только потом `page_translations`.
  Без второго шага роль, назначенная русской странице, давала на `/uz/news`
  русский заголовок при живой узбекской версии: страницы переводятся отдельной
  записью (механизм Б), а откат шёл на механизм А. Отсюда следствие для
  редактора: назначать роль на каждом языке не нужно, достаточно одного раза.

  целиком — мёртвая копия читается как действующая, и правка в ней «не
  срабатывает». Именно так требование `.carousel-nav__btn {44px}` (touch-цель)
  жило рядом с работающими 40px. Повтор внутри `@media` законен — контекст
  входит в ключ. Число `!important` в публичных файлах ограничено сверху и
  может только уменьшаться: каждый из них делает следующую правку
  непредсказуемой.

  Заголовок уровня секции обязан брать `var(--section-title-fg)`, а не
  `var(--gov-title)`: умолчание у переменной то же самое, но настройка секции
  тогда работает. Заголовки карточек, наоборот, остаются на `--gov-title`.
  На тёмной секции стеклянные (полупрозрачные) карточки темы делаются
  непрозрачными — иначе сквозь них просвечивает фон и тёмный текст карточки
  теряет контраст. Прежний флажок `_bg_light_text` читается как схема `light`.
- **Прозрачная шапка лежит на кадре обложки.** Светлый набор — белое лого,
  белое меню, белые иконки — читается только на тёмном кадре, поэтому под
  шапкой и верхней полосой всегда есть затемняющая подложка (`--hdr-scrim`):
  она работает без JS и на любой картинке. Весь набор идёт через переменные
  (`--hdr-fg`, `--hdr-veil`, `--hdr-icon-border`, `--hdr-ink-shadow`) — раньше
  цвет был белым литералом в десятке правил, и переключить его было нечем.
  На светлом кадре `blocks/hero.js` ставит `body.is-hero-light` по атрибуту
  слайда `data-hero-scheme`, и набор переключается целиком. Признак даётся
  только слайду, о кадре которого что-то известно: заливка или сплошное
  наложение; под фотографией без вуали работает подложка. Смена набора
  приходится на середину перехода между слайдами — сразу по клику она давала
  тёмное лого поверх ещё не ушедшего тёмного кадра.
- **Меню раздела в сайдбаре** — виджет `section_menu` (`App\Core\SectionMenu`):
  находит пункт основного меню, внутри которого лежит открытая страница, и
  показывает его подпункты. Своего дерева разделов нет — это те же `menu_items`,
  что и в шапке, и правило подсветки текущего пункта тоже одно на оба места
  (`SectionMenu::isUrlActive`, шапка зовёт его же). Страница вне разделов
  оставляет виджет **без вывода вовсе**: `WidgetRenderer::render()` не печатает
  `<aside>`, если шаблон ничего не вернул, — рамка с одним заголовком читается
  как поломка.
- **Шапка/подвал**: `App\Core\HeaderConfig` / `FooterConfig` (JSON в settings),
  вьюхи `app/Views/site/_header.php`, `_footer.php`. Логотипы — общий + светлый
  (для тёмного фона) + по языкам (`logo_by_lang`, `logo_light_by_lang`). Поиск
  рендерится только в выбранном варианте; код футер-счётчиков хранится в
  `footer_counters` и получает CSP-nonce при выводе.
- **Иконка раздела админки задаётся картой** `AdminUi::navigationIcon()`: ключ
  раздела и имя иконки Tabler совпадают редко, а неизвестный ключ `Icon::render`
  отдаёт пустой строкой — пункт меню молча остаётся без иконки (так было у 19
  разделов из 30). Новый раздел обязан получить строку в карте, иначе падает
  тест 248.
- **Переиспользуемые компоненты форм**: `App\Core\ImageField::resolve()`
  (пустое присланное поле = очистка!), `AdminUi::imageField()`, `AdminUi::colorField()`.
- **Миграции**: `database/migrations/*.sql`, применяет `database/migrate.php`
  (трекинг в таблице `migrations`). **`schema.sql` обязан совпадать**: при новой
  миграции добавь и колонки в CREATE TABLE, и файл в список
  `INSERT INTO migrations(...) VALUES` (иначе падает тест консистентности).
- **Полоса страниц** — `App\Core\Pager` + партиал `site/_pager.php`, общий для
  ленты новостей и каталогов: края, окно вокруг текущей страницы, многоточия на
  разрывах и стрелки с подписями для диктора. Соседние страницы вью кладёт в
  `$pagerPrev/$pagerNext`, шапка выводит их как `<link rel="prev|next">`.
- **Ряды карточек без дыр**: `App\Core\GridBalance` считает дорожки сетки и
  ширину карточки (`--grid-track`/`--grid-span` в scoped CSS блока). Колонок
  берётся столько, чтобы в последнем ряду не осталась одинокая карточка
  (пятёрка ложится 3+2), а карточки хвоста растягиваются на всю ширину.
  Используют `advantages` и `docs_list`; мобильную раскладку задаёт тема,
  поэтому растяжение живёт в `@media (min-width:901px)`.
- **Появление при скролле** — только прогрессивное улучшение: `_reveal` с
  типом `stagger` (`data-reveal-items`) прячет карточки классом, который вешает
  JS, поэтому без JS всё видно. Обычный `data-reveal` прячет блок сразу в CSS —
  для ключевого контента (профиль руководителя) его не включаем, а страховка
  `@media (scripting: none)` возвращает видимость при отключённом JavaScript.
- **Иконки**: `App\Core\Icon::render()` отдаёт `<use href="#tabler-…">`, а
  `Icon::injectSprite()` (вызывается из `View::render`) вырезает нужные
  `<symbol>` из вендорного спрайта по индексу
  `app/Core/data/tabler-sprite-index.php` и встраивает их после `<body>`.
  Ключи берутся из готового HTML, а не из счётчика вызовов — блоки приходят
  из кэша. Иконки, которые вставляет JS уже после загрузки, перечислены в
  `Icon::RUNTIME_ICONS` (сверяется тестом с `frontend.js`). Индекс
  пересобирается `npm run build:vendor`. Полный спрайт (2 МБ) грузится только
  пикером иконок в админке.
- **CDN**: `App\Core\Asset` (версионирование `?v=hash` + префикс CDN),
  `Asset::rewriteMedia()` переписывает `/uploads/public` в HTML на CDN.
  Pull-zone CDN (BunnyCDN и т.п.) — без переноса домена. `App\Core\Cloudflare` —
  purge через API (только если домен проксируется через CF).
- **CI**: `.github/workflows/ci.yml` — 4 джобы: php -l + тесты на PHP 8.4/8.5
  с MariaDB; PHPStan **блокирующий** (`composer analyse`) + `composer audit`;
  проверка синтаксиса JS (`node --check`); browser smoke на Chromium (Playwright).
  Отдельный сторож против тихого устаревания: прогон тестов пишет уведомления
  PHP в `storage/logs/ci-php.log`, обход сайта — в свои журналы, и шаги
  «Прогон без устаревших вызовов» / «Устаревшие вызовы на боевой версии PHP»
  роняют сборку, если в них появилось `Deprecated`. Смоук идёт на 8.5 — версии
  боевого сервера.

## Реализованные фичи (чтобы не изобретать заново)
- Конструктор шапки/футера (drag-and-drop зон), 4 макета, отдельный мобильный билдер.
- **Шаблон страницы — файл** (`App\Core\PageTemplateFile`, docs/PAGE_TEMPLATES.md):
  библиотека шаблонов (`block_snippets`) умеет выгружаться JSON'ом и
  загружаться обратно — кнопки в секции «Шаблоны страницы» редактора.
  Конверт помечен `kind: artstudio.page-template`: без пометки об ошибке
  узнают только после импорта, когда собралось не то. **Присланный файл — не
  свои данные:** тип сверяется с реестром, поля `data` — с умолчаниями типа
  (лишний ключ всё равно потерялся бы при первом сохранении), блок «HTML» и
  `custom_css` принимает только супер-админ. Ключи оформления (`_*`)
  перечислять руками нельзя — они прогоняются через тот же
  `BlockPresentationNormalizer`, что и форма блока: свой список молча
  разъезжается с нормализатором и начинает либо терять оформление, либо
  пропускать непроверенное значение. Загрузка только пополняет библиотеку и
  ничего не заменяет — применение к странице остаётся отдельным действием.
- **«Цели» (Maqsadlar)** — название, описание и набор снимков (`goals` +
  `goal_images` + `goal_translations`, модель `App\Models\Goal`); на сайте цель
  видна каруселью в виджете: текст над кадрами. Текст виден посетителю, поэтому
  **переводится** (механизм А, `Goal::localize`) — набор снимков без единого
  слова не сообщает, что за объект показан. Публичного адреса, slug'а и SEO у
  цели нет: держать стабильным нечего, поэтому языковая версия остаётся
  переводом строки, а не отдельной записью. Раздел админки `/admin/goals`
  постраничный, с поиском по названию и колонкой «Языки» — записей сотни.
  Порядок кадров внутри цели авторский: **случайной бывает сама цель, а не её
  слайды**.
  **Название — не заголовок разметки** (`p.goal-carousel__name`): виджет встаёт
  в любое место страницы, и уровень заголовка там не предсказать; диктор
  получает имя цели подписью карусели (`aria-label`).
  **Случайность переживает кэш только на своём адресе.** Страница кэшируется
  ключом `page:<id>:<lang>`, поэтому цель, выбранная при сборке, стала бы общей
  для всех до сброса кэша. Виджет отдаёт такую цель как запасную (без JS видна
  она), а свежую запрашивает `blocks/slider.js` у `/goals/random`
  (`Site\GoalController`, `Cache-Control: no-store`, `X-Robots-Tag: noindex`).
  Не ответил сервер — остаётся запасная: пустой карусели не бывает.
  **Ответ — JSON из двух кусков разметки** (`text` + `slides` + `label`): текст
  ложится над каруселью, кадры — в дорожку, склейкой одной строкой их не
  развести. **Адрес приезжает из разметки** (`data-goal-slider="/uz/goals/random"`,
  `Locale::url`): скрипт про текущий язык не знает, и жёсткий `/goals/random`
  приносил на узбекскую страницу русскую цель.
- **Пропорции кадра карусели — один список** (`App\Core\SliderRatio`) на блок
  «Слайдер» и виджет «Фотокарусель»: разметка и стили у них общие, поэтому и
  набор пропорций обязан быть общим — раздельные списки разъезжались молча.
  Ключ пропорции это имя класса (`.block-slider--ratio-9-16`), поэтому пишется
  через дефис. Кроме широких форматов есть вертикальные (1:1, 4:5, 9:16):
  карточки для соцсетей приходят именно такими, а при широкой пропорции
  `object-fit: cover` срезает у них верх и низ. Плитка «Медиагалереи» — не
  карусель: у неё свой набор (16-9, 4-3, 1-1) и свои правила, сводить их
  вместе незачем. Новая пропорция обязана получить правило в `frontend.css`,
  иначе настройка ничего не меняет (стережёт тест 273).
- **Виджет «Фотокарусель»** (`photo_slider`, `templates/widgets/photo_slider.php`):
  набор снимков без подписей и ссылок, с необязательной автопрокруткой и
  случайным порядком. Разметка и стили общие с блоком «Слайдер»
  (`.block-slider` в `frontend.css`) — поведение у них одно, и второй набор
  правил разъехался бы с первым. **Перемешивает браузер, а не сервер**
  (`data-slider-shuffle` → `blocks/slider.js`): страницы кэшируются общим
  ключом `page:<id>:<lang>`, и порядок, выбранный при сборке, застыл бы для
  всех посетителей до сброса кэша. Без JS карусель работает в порядке
  редактора. Скрипт просит сам шаблон (`AssetCollector::requireJs('slider')`)
  — этого хватает виджету сайдбара, который собирается на каждый запрос; для
  виджета **внутри блока** ключ добавляется по готовому HTML в
  `BlockRenderer::renderPage()` (`widget--photo_slider`), потому что на
  попадании в кэш шаблон не выполняется. Источник кадров — свои снимки или
  «случайная цель» (`source`, см. «Цели»).
- Обложка как тип контента: слайды с DnD-порядком, стрелки, свайп, клавиатура,
  индикаторы (точки / `01 / 05` / полоса / миниатюры), автопрокрутка (пауза по
  наведению и по действию зашиты), переходы Fade/Slide/Fade+Slide/Ken Burns,
  фон Image/MP4/YouTube с кадром-заменой, пресеты и расписание публикации.
- Hero (видео/фото/overlay, бесшовное loop-видео без кнопок), счётчики,
  направления, новости (лента + крупная), медиа-галерея, проекты, команда, FAQ и т.д.
- Блоки-обёртки, тянущие данные из БД: `news_latest/news_feature/news_docs`
  (новости), `projects_list` (проекты), `team_list` (команда).
- **Категории новостей** (`news_categories` + `news_category_translations`,
  модель `App\Models\NewsCategory`): рубрика — запись со slug и переводимым
  названием, `news.category_id` — ссылка. Slug один на все языки (это адрес и
  ключ выборки), переводится только название; механизм А. Раздел админки —
  `/admin/news-categories`, выбор — в сайдбаре формы новости, в списке новостей
  колонка «Категория» и фильтр (`?category=<id>|none`), у блоков новостей поле
  «Категория новостей», на публичке — рубрикатор `?category=<slug>`.
  **Метка (`news.badge`) — это не категория**: необязательная пометка
  («Важно», «Анонс») со своим цветом фона (`news.badge_color`); цвет текста
  считается по контрасту — `App\Core\NewsBadge` (он же рендерит разметку для
  всех трёх мест вывода). Старые бейджи-рубрики переносит разовый скрипт
  `php database/migrate_news_badges.php` (есть `--dry-run`).
- **Автозагрузка видео с YouTube-канала** (`App\Core\YoutubeChannel` — чтение
  канала, `App\Core\YoutubeImport` — импорт; панель в `/admin/videos`, cron —
  `app/Console/youtube_worker.php`). Забирается **карточка** ролика: название,
  описание, ссылка и кадр-превью; **само видео не скачивается** — оно остаётся
  на YouTube, сайт хранит только `videos.video_url`.
  По умолчанию источник — открытая RSS-лента канала (`/feeds/videos.xml`):
  никаких ключей и лимитов квоты, но только последние 15 роликов и без
  длительности. Ключ Data API (`youtube_api_key`, шифруется как секрет) —
  необязательное усиление: больше 15 записей за проход и длительность ролика.
  По @псевдониму лента не строится, нужен UC-id: он ищется один раз по странице
  канала и запоминается в `youtube_channel_id` (смена канала его обнуляет).
  **Ключ повторного прохода — `videos.youtube_id`**, поэтому импорт идемпотентен
  и его можно вешать на cron. Ролик, заведённый вручную, не дублируется: запись
  узнаётся по ссылке (`Core\Video::youtubeId`) и просто привязывается к каналу.
  **Правка редактора важнее источника**: название и описание переписываются
  только при включённой настройке «обновлять» — иначе ночной проход затирал бы
  ручные заголовки и переводы. Кадр-превью по умолчанию скачивается в медиатеку
  (`maxresdefault` с откатом на кадр из ленты): в админке CSP запрещает внешние
  картинки, и ссылка на `i.ytimg.com` дала бы пустую обложку в списке.
  Список видео умеет **массовые действия** (`/admin/videos/bulk`): публикация,
  снятие, «на главной» и удаление — импорт приносит записи десятками и
  черновиками, открывать их по одной незачем. Разметка та же, что у новостей
  (`data-bulk-form` + `data-bulk-item`), удаление подтверждается — корзины у
  раздела нет.
- **Постраничный вывод блока «Медиа»** (`App\Core\BlockPager`, галочка
  «Постраничный вывод» у `media_gallery`). Выключена по умолчанию: на главной
  блок остаётся витриной отмеченных «на главной» записей. Включённая галочка
  меняет смысл блока — он показывает **весь опубликованный список** страницами
  по `limit`, и «сколько показывать» становится размером страницы. Для видео
  это единственный способ дойти до старых роликов: публичного раздела «Видео»
  на сайте нет.
  **Номер страницы — свой параметр `?mpage=`**, не общий `page`: страница может
  быть назначена шапкой ленты новостей, и два пейджера подрались бы за один
  параметр. Ссылка ведёт на якорь блока (`#block-<id>`) — иначе переход
  выбрасывает читателя в начало длинной страницы.
  **Вторая и дальше страницы не кэшируются** (`PageBlocks::compile`): ключ кэша
  `page:<id>:<lang>` не знает про параметры адреса, и записанная под ним вторая
  страница галереи уехала бы всем посетителям главной. Номер ограничен сверху
  (`BlockPager::MAX_PAGE`), чтобы `?mpage=999999` не превращался в работу.
  Смешанный источник (видео + фото) листает оба списка вместе: у каждой вкладки
  своя порция на странице, страниц столько, сколько нужно длинному списку.
- **«Показать на главном»** (`is_featured` у projects и photo_albums): блоки
  `image_cards` (источник «Проекты») и `media_gallery` (источники «Фотоальбомы»,
  «Видео» или «media» = оба сразу с вкладками Видео/Фото)
  собирают отмеченные записи автоматически; нет отмеченных → откат на последние.
- i18n публички, переводимые вводные тексты разделов, per-language логотипы.
- **Переводы контента (per-language) у всех текстовых сущностей**: новости
  (`news_translations`), страницы (`page_translations` + блоки), проекты
  (`project_translations`: title, description), команда
  (`team_member_translations`: name, position — переводится и имя!), альбомы
  (`photo_album_translations`), видео (`video_translations`), контент-записи
  (`content_entry_translations`). Паттерн един: RU=база, перевод накладывается
  `Model::localize()`/`localizeRows()` с graceful-fallback к основному языку
  при пустом поле; `Model::published/all/forHome/findPublishedBySlug` принимают
  `?string $lang`. В админ-списках — колонка «Языки» (partial
  `admin/layout/lang_badges`, данные из `Model::availableLangsForIds()`), в
  формах — вкладки перевода (`data-lang-tabs`). Одноязычны только служебные
  разделы (меню, формы, редиректы, пользователи).
- **Два механизма перевода — спрашивай `App\Core\Translations`.** Кроме полей
  в `*_translations` (механизм А) языковая версия бывает **отдельной связанной
  записью** (`lang` + `translation_group_id`, механизм Б) — у новостей, страниц
  и проектов, где у версии свой slug. Код, написанный под один механизм, второй
  не замечает молча: так двуязычная новость уходила в Telegram двумя постами, а
  hreflang вёл на адрес с редиректом. `Translations::rows/langs/paths/primaryId`
  отвечают с учётом обоих; новый код обязан спрашивать там, а не собирать свою
  логику по месту. `primaryId()` — запись, от имени которой действует группа
  (очереди и счётчики адресуются ей, иначе одна новость учитывается дважды).

- **Фирменный слой**: эмблема-гирих — маска `--gov-emblem` (файл

  дублируется. Cookie прежней версии (`cw:l:on`) переносится автоматически.

  страницы. Пусто — берутся первые буквы названия (`Language::shortLabel()`).
- **Узбекская кириллица** (`App\Core\UzCyrillic`): переключатель письменности в
  той же панели (виден только на UZ) и отдельным пунктом «Ўзбекча» в
  переключателе языков; ссылки ведут на `/script/{latn|cyrl}?to=…`
  (`Site\ScriptController`, адрес возврата проверяется на открытый редирект). Перевод делается на готовой странице в
  `View::render` — в БД остаётся латиница, кэш блоков не множится. Не трогаются
  теги, атрибуты, script/style/code/pre, сущности, ссылки и почта, а также любой

- **«Меньше движения» — один признак на весь фронт**: `window.asdrReduceMotion()`
  (объявлен в `theme-init.js`) учитывает и системный `prefers-reduced-motion`,
  и тумблер «остановка анимаций» из панели (`data-a11y-motion="off"`). CSS гасит
  только `animation`/`transition`, поэтому фоновое видео обложки и таймеры
  автопрокрутки спрашивают помощник, а не медиазапрос, и не кэшируют ответ:
  настройку переключают на лету. Панель шлёт событие `asdr:motion-change`.

  идёт в CI — `tests/browser/a11y.spec.js` проверяет главную, ленту новостей, поиск
  и узбекскую версию в светлой и тёмной темах (WCAG 2.0/2.1/2.2 A и AA), на десктопе
  и на мобильном; кроме них — детальная новость, проект, каталог и страница с
  формой (там нарушений больше всего). Ручная проверка остаётся за тем, что axe
  не умеет: порядок табуляции, осмысленность alt и формулировок для диктора.

## Грабли (уже наступали)
- **Сокращённый `transition` с CSS-переменной минификатор выбрасывает.**
  `transition: --hdr-scrim .3s ease` в исходнике выглядит правильно, а в
  `public.min.css` объявления просто нет — анимации не будет, и ошибку видно
  только замером вычисленных стилей. Пишем longhand:
  `transition-property` / `transition-duration` / `transition-timing-function`.
  Сама переменная анимируема, только если объявлена через `@property` с
  `syntax: '<number>'`.
- **Новая версия PHP выключала сайт целиком.** `ErrorHandler` превращает любую
  ошибку в исключение, а PHP 8.5 пометил устаревшим то, что вчера работало
  молча: `PDO::MYSQL_ATTR_*`, `curl_close()`, `imagedestroy()`,
  `$http_response_header`. Драйверная константа читается при каждом соединении
  с БД, поэтому 500 отдавала любая страница. Теперь `E_DEPRECATED` и
  `E_USER_DEPRECATED` уходят в `storage/logs/error.log` (уровень `DEPRECATED`,
  одинаковое сообщение за запрос пишется один раз), остальные ошибки
  по-прежнему становятся исключением — молчаливое предупреждение это потерянные
  данные. Драйверные атрибуты PDO берутся из подкласса драйвера
  (`Pdo\Mysql::ATTR_*`), а список устаревших вызовов стережёт тест 263.
- **Минимум — PHP 8.4, боевой сервер на 8.5.** Планка стоит там же в четырёх
  местах: `EnvironmentCheck` (установщик), `scripts/release_check.php`,
  `composer.json` и матрица CI. Поднимать её ради самого подъёма незачем —
  версия сервера от этого не меняется; 8.4 выбран как первая версия с
  подклассами драйверов PDO, из-за которых исчез класс-помощник, и оставляет
  один шаг запаса вниз, если хостинг откатит версию.
- **Произвольный код — только супер-админ, и только внешними файлами.** Поля
  страницы `custom_css`/`custom_js` (`CustomAssetHelper`) публикуют свой код
  файлами через `GeneratedCss`/`GeneratedJs`, инлайна в HTML нет. Адрес с
  чужого домена сам по себе не заработает: публичная CSP разрешает только
  `'self'`, поэтому шапка/подвал докладывают origin в директиву через
  `SecurityHeaders::allowPageAssets()` (вьюхи рендерятся в буфер — заголовок
  ещё можно переслать; под `/admin` подмена запрещена, чтобы не ослаблять CSP
  панели). Роль `editor` эти поля и разметку блока «HTML» не меняет — сервер
  сохраняет прежнее значение, что бы ни пришло в форме.
- **Тесты, пишущие в `settings`, обязаны звать `reset_design_state()`** (tests/lib.php)
  в начале. Файлы кейсов сортируются **строкой**, поэтому `111_*` идёт раньше
  `33_*`: тест, оставивший `design_*` в БД, роняет соседей на чистой базе CI, а
  локально — только на следующем прогоне. Сброс удаляет строки, а не пишет '':
  для части ключей пустое значение и отсутствие — разное поведение.
- **Вход в админку — два вторых фактора**: приложение-аутентификатор (TOTP,
  `App\Core\TOTP`, секрет в `users.totp_secret` через `SecretBox`) и код в
  Telegram. Достаточно любого; без обоих сессия ограничена профилем
  (`2fa_setup_required`, белый список путей в `public/index.php`). TOTP не
  зависит от сети — им и снимается риск запереть себя без Telegram.
  **Шаг TOTP одноразовый** (`users.totp_last_step`, `repo_users.totp_last_step`,
  `Model::consumeTotpStep`): окно проверки ±1 шаг по 30 секунд, и без отметки
  подсмотренный код оставался бы рабочим полторы минуты. Проверка возвращает
  номер шага — `TOTP::matchStep()`, `verify()` поверх неё.
  **Подключение и отключение канала подтверждаются паролем** — иначе угнанная
  сессия привязывает к аккаунту свой аутентификатор и получает постоянный
  второй фактор.
  **Ролей ровно две** — те, что перечисляет `ENUM users.role`: `admin`
  (супер-админ) и `editor`. Имена живут в `RbacGuard::ROLE_*`; прежний
  `super_admin` был недостижим (ENUM его не принимал), но `Auth` считал его
  полным доступом, а `RbacGuard` — нет, и такая роль не могла бы ничего.
  **WebAuthn/Passkey нет.** Заглушка подтверждала вход одним `credential_id`
  без подписи и challenge; удалена вместе с таблицей `user_passkeys`
  (миграция `2026_08_23_drop_user_passkeys.sql`). Настоящий WebAuthn — это
  CBOR/COSE и проверка подписи, заводить его придётся с нуля.
- **Напоминания редактору** (`App\Core\ContentChecklist`): свёрнутая полоса
  над формой новости — нет обложки, анонса, рубрики, SEO-описания, хештегов,
  подписей к фото, перевода (у опубликованных). Ничего не блокирует: в
  `store/update` чек-лист не участвует, тест это стережёт.
- **Подписи к фотографиям**: у галереи новости и снимков альбома есть
  «Подпись» и «Автор/источник» (`news_images.caption/credit`,
  `photo_album_images.credit`) — свободный ввод, без переводов. Вывод — один
  компонент `.media-caption` (12px, акцентная грань слева, без капслока) на
  все три места: слайдер новости, фотолента, альбом. Обложка берёт подпись из
  своей записи галереи по совпадению пути. В rich-пост Telegram уходит
  `<figcaption>` с `<cite>`.
- **Формат постов в Telegram**: `App\Core\TelegramRichMessage` собирает
  rich-сообщение (Bot API 10.1+, `sendRichMessage`): заголовок, слайд-шоу,
  полный текст, второй язык под `<details>`, сноска с хештегами и подписью.
  Предел 32768 знаков против 1024 у подписи к фото. Снимки в разметке — только
  ссылками `tg://photo?id=…`, файлы уходят полем `media` (прямой https в `<img>`
  API не принимает); `reply_markup` метод принимает, поэтому кнопки есть и там.
  Настройка
  `social_telegram_format` (auto|rich|classic): «auto» пробует новый формат и
  при отказе Telegram молча откатывается на sendPhoto/sendMessage. В обычном
  формате длинный текст уходит отдельным сообщением, а не режется.
- **Telegram — один раздел `/admin/telegram`** (`TelegramController`): бот →
  привязка админа (коды входа) → канал → уведомления. Токен бота живёт в
  `telegram_bot_token`; `social_telegram_token` — необязательное
  переопределение (отдельный бот-публикатор), при пустом значении
  `SocialSettings::configFor('telegram')` берёт основной. Gateway
  (`telegram_gateway_token`) — другой платный сервис, к Bot API отношения не
  имеет. Ответ Bot API **`Not Found` = неверный токен** (токен — часть URL
  `/bot<токен>/`), `chat not found` — неверный chat_id, `not enough rights` —
  бот не админ канала; диагностика — `SocialPublisher::checkTelegram()`.
  **Не добавляй ключи Telegram в `SettingsController::TEXT_KEYS`**: их полей в
  той форме нет, и сохранение затрёт токены пустой строкой.
- **Сообщение админки обязано доехать до глаз.** Flash рисуется как `.alert`
  вверху `.admin-main`, а обработчики возвращают на якорь
  (`/admin/telegram#telegram-channel`) — браузер сразу уезжает к секции, и
  сообщение остаётся выше экрана. Поэтому `layout/footer.php` превращает flash
  в тост **любого типа**, а не только success: пока тостом дублировался один
  успех, ошибка «Определить ID канала» была не видна вообще и кнопка выглядела
  сломанной. Тост висит сверху по центру (внизу справа его теряют), ошибку по
  таймеру не гасим — в ней написано, что делать. Иконку для такого тоста берём
  **только из `Icon::RUNTIME_ICONS`**: символы для спрайта ищет регулярка по
  готовому HTML, а внутри JS-строки кавычки экранированы, и она их не находит —
  иконка молча выйдет пустой.
- **Файл, который PHP собрал сам, надо открыть на чтение явно.** Загрузка из
  формы приходит через `move_uploaded_file()` и получает права по umask, а
  файл из `tempnam()` — 0600. Статику отдаёт веб-сервер, и такой файл он не
  прочитает: картинка выходит битой и в админке, и на сайте, хотя запись в
  медиатеке есть и файл на диске лежит (так пропали все кадры-превью после
  первого импорта с YouTube). `Uploader::storeFromPath()` теперь делает
  `chmod 0644` сам; уже загруженное чинит `php scripts/fix_upload_permissions.php`
  (есть `--dry-run`, заодно показывает пустые файлы — по ним видно, что дело не
  в правах).
- **`lastInsertId()` после `bustPageCache()` = 0**: `bustPageCache()` делает запрос
  к settings (CDN/Cloudflare), обнуляющий last insert id при холодном кэше. В
  `create()` читай id **до** сброса кэша. (Исправлено в Project/News/TeamMember.)
- **`width:100vw` даёт горизонтальный скролл** на ширину скроллбара. Лечится
  `html { overflow-x: clip }` (не `hidden` — не ломает sticky-шапку).
- **SVG-логотип схлопывается**, если у SVG нет пиксельных размеров (`width="100%"`).
  Нужна явная `height` на `img`, тогда ширина считается из viewBox.
- **Локальные сервисы не считаются постоянными**: перед smoke-проверкой убедиться,
  что БД и PHP-сервер запущены. Headless-браузер может использовать
  overlay-скроллбары (0px), поэтому scrollbar-баги в нём воспроизводятся не всегда.
- **Playwright**: зависимости фиксируются в `package-lock.json`. Локально:
  `npm ci`, затем при необходимости `npx playwright install chromium` и
  `npm run test:browser`. Для инъекции скриптов на страницы с CSP используется
  `bypassCSP: true`.
