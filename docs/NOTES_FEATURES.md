# Реализованные фичи

Заметки о проекте, вынесенные из `CLAUDE.md`: там — карта и ключевые правила,
здесь — подробности и причины решений. Читать при работе над темой.

### Реализованные фичи (чтобы не изобретать заново)
- Конструктор шапки/футера (drag-and-drop зон), 4 макета, отдельный мобильный билдер.
- **Шаблон страницы — файл** (`App\Core\PageTemplateFile`, docs/PAGE_TEMPLATES.md):
  библиотека шаблонов (`block_snippets`) умеет выгружаться JSON'ом и
  загружаться обратно — кнопки в секции «Шаблоны страницы» редактора.
  Конверт помечен `kind: artstudio.page-template`: без пометки об ошибке
  узнают только после импорта, когда собралось не то. **Присланный файл — не
  свои данные:** тип сверяется с реестром, поля `data` — с умолчаниями типа
  (лишний ключ всё равно потерялся бы при первом сохранении), блок «HTML» и
  `custom_css` принимает только супер-админ. Ключи оформления (`_*`)
  перечислять руками нельзя — они прогоняются через тот же
  `BlockPresentationNormalizer`, что и форма блока: свой список молча
  разъезжается с нормализатором и начинает либо терять оформление, либо
  пропускать непроверенное значение. Загрузка только пополняет библиотеку и
  ничего не заменяет — применение к странице остаётся отдельным действием.
- **«Цели» (Maqsadlar)** — название, описание и набор снимков (`goals` +
  `goal_images` + `goal_translations`, модель `App\Models\Goal`); на сайте цель
  видна каруселью в виджете: текст над кадрами. Текст виден посетителю, поэтому
  **переводится** (механизм А, `Goal::localize`) — набор снимков без единого
  слова не сообщает, что за объект показан. Публичного адреса, slug'а и SEO у
  цели нет: держать стабильным нечего, поэтому языковая версия остаётся
  переводом строки, а не отдельной записью. Раздел админки `/admin/goals`
  постраничный, с поиском по названию и колонкой «Языки» — записей сотни.
  Порядок кадров внутри цели авторский: **случайной бывает сама цель, а не её
  слайды**.
  **Название — не заголовок разметки** (`p.goal-carousel__name`): виджет встаёт
  в любое место страницы, и уровень заголовка там не предсказать; диктор
  получает имя цели подписью карусели (`aria-label`).
  **Случайность переживает кэш только на своём адресе.** Страница кэшируется
  ключом `page:<id>:<lang>`, поэтому цель, выбранная при сборке, стала бы общей
  для всех до сброса кэша. Виджет отдаёт такую цель как запасную (без JS видна
  она), а свежую запрашивает `blocks/slider.js` у `/goals/random`
  (`Site\GoalController`, `Cache-Control: no-store`, `X-Robots-Tag: noindex`).
  Не ответил сервер — остаётся запасная: пустой карусели не бывает.
  **Ответ — JSON из двух кусков разметки** (`text` + `slides` + `label`): текст
  ложится над каруселью, кадры — в дорожку, склейкой одной строкой их не
  развести. **Адрес приезжает из разметки** (`data-goal-slider="/uz/goals/random"`,
  `Locale::url`): скрипт про текущий язык не знает, и жёсткий `/goals/random`
  приносил на узбекскую страницу русскую цель.
- **Пропорции кадра карусели — один список** (`App\Core\SliderRatio`) на блок
  «Слайдер» и виджет «Фотокарусель»: разметка и стили у них общие, поэтому и
  набор пропорций обязан быть общим — раздельные списки разъезжались молча.
  Ключ пропорции это имя класса (`.block-slider--ratio-9-16`), поэтому пишется
  через дефис. Кроме широких форматов есть вертикальные (1:1, 4:5, 9:16):
  карточки для соцсетей приходят именно такими, а при широкой пропорции
  `object-fit: cover` срезает у них верх и низ. Плитка «Медиагалереи» — не
  карусель: у неё свой набор (16-9, 4-3, 1-1) и свои правила, сводить их
  вместе незачем. Новая пропорция обязана получить правило в `frontend.css`,
  иначе настройка ничего не меняет (стережёт тест 273).
- **Виджет «Фотокарусель»** (`photo_slider`, `templates/widgets/photo_slider.php`):
  набор снимков без подписей и ссылок, с необязательной автопрокруткой и
  случайным порядком. Разметка и стили общие с блоком «Слайдер»
  (`.block-slider` в `frontend.css`) — поведение у них одно, и второй набор
  правил разъехался бы с первым. **Перемешивает браузер, а не сервер**
  (`data-slider-shuffle` → `blocks/slider.js`): страницы кэшируются общим
  ключом `page:<id>:<lang>`, и порядок, выбранный при сборке, застыл бы для
  всех посетителей до сброса кэша. Без JS карусель работает в порядке
  редактора. Скрипт просит сам шаблон (`AssetCollector::requireJs('slider')`)
  — этого хватает виджету сайдбара, который собирается на каждый запрос; для
  виджета **внутри блока** ключ добавляется по готовому HTML в
  `BlockRenderer::renderPage()` (`widget--photo_slider`), потому что на
  попадании в кэш шаблон не выполняется. Источник кадров — свои снимки или
  «случайная цель» (`source`, см. «Цели»).
- Обложка как тип контента: слайды с DnD-порядком, стрелки, свайп, клавиатура,
  индикаторы (точки / `01 / 05` / полоса / миниатюры), автопрокрутка (пауза по
  наведению и по действию зашиты), переходы Fade/Slide/Fade+Slide/Ken Burns,
  фон Image/MP4/YouTube с кадром-заменой, пресеты и расписание публикации.
- Hero (видео/фото/overlay, бесшовное loop-видео без кнопок), счётчики,
  направления, новости (лента + крупная), медиа-галерея, проекты, команда, FAQ и т.д.
- Блоки-обёртки, тянущие данные из БД: `news_latest/news_feature/news_docs`
  (новости), `projects_list` (проекты), `team_list` (команда).
- **Адрес раздела каталога — один метод** (`ContentType::path/entryPath`).
  По умолчанию каталог живёт на `/catalog/<type>`: по адресу видно, что открыт
  раздел, и слаг типа не спорит с адресами страниц. Настройка «Адрес без
  префикса /catalog» (`content_types.root_url`) выносит раздел в корень —
  `/documenty` вместо `/catalog/documenty`.
  **Прежний адрес остаётся рабочим**: он отвечает 301 на новый (и список, и
  запись), иначе печатные ссылки и закладки обрывались бы, а два живых адреса
  с одним содержимым — это дубль.
  **Занять чужой корневой адрес нельзя.** Маршрут `/{slug}` обслуживает
  страницы и объявлен раньше, поэтому тип с занятым слагом просто не открылся
  бы, а редактор видел бы сохранённую настройку — самый тихий вид отказа.
  Сторожит `ContentType::rootUrlConflict()`: служебные разделы
  (`RESERVED_ROOT`), коды языков и слаги страниц. Проверка нужна только при
  включённой настройке.
  **Запись раздела в корне** — маршрут `/{type}/{slug}`, объявленный
  **последним** в `public/index.php`: это шаблон из двух произвольных
  сегментов, и выше он перехватывал бы `/news/…`, `/projects/…`, `/albums/…`.
  Новый двухсегментный маршрут добавляется перед ним. Менеджер редиректов и
  журнал 404 при этом не обходятся: редиректы разбираются до сопоставления
  маршрутов, а 404 пишет сама вьюха.
  **Переключение уводит за собой пункты меню** (`MenuItem::retargetCustomUrl`):
  старый адрес работает редиректом, но пункт, оставшийся на нём, перестал бы
  подсвечиваться — посетитель приходит уже на новый адрес. Сравнение точное,
  соседний раздел с похожим началом не трогается. Стережёт тест 353.
- **Категории новостей** (`news_categories` + `news_category_translations`,
  модель `App\Models\NewsCategory`): рубрика — запись со slug и переводимым
  названием, `news.category_id` — ссылка. Slug один на все языки (это адрес и
  ключ выборки), переводится только название; механизм А. Раздел админки —
  `/admin/news-categories`, выбор — в сайдбаре формы новости, в списке новостей
  колонка «Категория» и фильтр (`?category=<id>|none`), у блоков новостей поле
  «Категория новостей», на публичке — рубрикатор `?category=<slug>`.
  **Метка (`news.badge`) — это не категория**: необязательная пометка
  («Важно», «Анонс») со своим цветом фона (`news.badge_color`); цвет текста
  считается по контрасту — `App\Core\NewsBadge` (он же рендерит разметку для
  всех трёх мест вывода). Старые бейджи-рубрики переносит разовый скрипт
  `php database/migrate_news_badges.php` (есть `--dry-run`).
- **Автозагрузка видео с YouTube-канала** (`App\Core\YoutubeChannel` — чтение
  канала, `App\Core\YoutubeImport` — импорт; панель в `/admin/videos`, cron —
  `app/Console/youtube_worker.php`). Забирается **карточка** ролика: название,
  описание, ссылка и кадр-превью; **само видео не скачивается** — оно остаётся
  на YouTube, сайт хранит только `videos.video_url`.
  По умолчанию источник — открытая RSS-лента канала (`/feeds/videos.xml`):
  никаких ключей и лимитов квоты, но только последние 15 роликов и без
  длительности. Ключ Data API (`youtube_api_key`, шифруется как секрет) —
  необязательное усиление: больше 15 записей за проход и длительность ролика.
  По @псевдониму лента не строится, нужен UC-id: он ищется один раз по странице
  канала и запоминается в `youtube_channel_id` (смена канала его обнуляет).
  **Ключ повторного прохода — `videos.youtube_id`**, поэтому импорт идемпотентен
  и его можно вешать на cron. Ролик, заведённый вручную, не дублируется: запись
  узнаётся по ссылке (`Core\Video::youtubeId`) и просто привязывается к каналу.
  **Правка редактора важнее источника**: название и описание переписываются
  только при включённой настройке «обновлять» — иначе ночной проход затирал бы
  ручные заголовки и переводы. Кадр-превью по умолчанию скачивается в медиатеку
  (`maxresdefault` с откатом на кадр из ленты): в админке CSP запрещает внешние
  картинки, и ссылка на `i.ytimg.com` дала бы пустую обложку в списке.
  Список видео умеет **массовые действия** (`/admin/videos/bulk`): публикация,
  снятие, «на главной» и удаление — импорт приносит записи десятками и
  черновиками, открывать их по одной незачем. Разметка та же, что у новостей
  (`data-bulk-form` + `data-bulk-item`), удаление подтверждается — корзины у
  раздела нет.
- **Постраничный вывод блока «Медиа»** (`App\Core\BlockPager`, галочка
  «Постраничный вывод» у `media_gallery`). Выключена по умолчанию: на главной
  блок остаётся витриной отмеченных «на главной» записей. Включённая галочка
  меняет смысл блока — он показывает **весь опубликованный список** страницами
  по `limit`, и «сколько показывать» становится размером страницы. Для видео
  это единственный способ дойти до старых роликов: публичного раздела «Видео»
  на сайте нет.
  **Номер страницы — свой параметр `?mpage=`**, не общий `page`: страница может
  быть назначена шапкой ленты новостей, и два пейджера подрались бы за один
  параметр. Ссылка ведёт на якорь блока (`#block-<id>`) — иначе переход
  выбрасывает читателя в начало длинной страницы.
  **Вторая и дальше страницы не кэшируются** (`PageBlocks::compile`): ключ кэша
  `page:<id>:<lang>` не знает про параметры адреса, и записанная под ним вторая
  страница галереи уехала бы всем посетителям главной. Номер ограничен сверху
  (`BlockPager::MAX_PAGE`), чтобы `?mpage=999999` не превращался в работу.
  **У каждой вкладки смешанного источника своя полоса страниц.** Общая на оба
  списка показывала неправду: списки разной длины (роликов сотни, альбомов
  единицы), и на вкладке «Фото» стояли страницы видео — переход по ним не менял
  ни одной карточки. Номер страницы принадлежит вкладке, поэтому в адресе
  вместе с ним едет её имя (`?mtab=photo&mpage=2`, `BlockPager::TAB_PARAM`), а
  неактивная вкладка показывает **своё начало** — иначе переключение открывало
  бы её пустой серединой. Открытую вкладку выбирает сервер
  (`data-media-active`), а не скрипт: раньше `frontend.js` на загрузке жёстко
  включал «Видео», и переход по полосе страниц «Фото» возвращал посетителя не
  туда. Запрос с `?mtab=` мимо общего кэша страницы идёт по той же причине, что
  и вторая страница: ответ отличается уже на первой. Стережёт тест 307.
- **«Показать на главном»** (`is_featured` у projects и photo_albums): блоки
  `image_cards` (источник «Проекты») и `media_gallery` (источники «Фотоальбомы»,
  «Видео» или «media» = оба сразу с вкладками Видео/Фото)
  собирают отмеченные записи автоматически; нет отмеченных → откат на последние.
- **У карточки проекта (`.imgcard`) нет «Подробнее».** Карточка сама является
  ссылкой, поэтому надпись повторяла очевидное глазу и добавляла диктору
  «Подробнее →» после каждого названия — та же причина, по которой её нет в
  ленте новостей. Убрана во всех трёх местах вывода `.imgcard` (блок
  «Карточки» с фото, список `/projects`, «Другие проекты») — компонент один,
  и оставленная копия разъехалась бы с остальными.
  **Кадр карточки — 16:9.** Прежде высоту задавали `min-height: 240px` и
  содержимое, то есть пропорция снимка зависела от числа колонок и длины
  заголовка. У варианта «текст под фото» пропорция принадлежит **кадру**, а не
  карточке (`aspect-ratio: auto` у самой карточки): под снимком есть подпись,
  и карточка растёт по ней.
- i18n публички, переводимые вводные тексты разделов, per-language логотипы.
- **Переводы контента (per-language) у всех текстовых сущностей**: новости
  (`news_translations`), страницы (`page_translations` + блоки), проекты
  (`project_translations`: title, description), команда
  (`team_member_translations`: name, position — переводится и имя!), альбомы
  (`photo_album_translations`), видео (`video_translations`), контент-записи
  (`content_entry_translations`). Паттерн един: RU=база, перевод накладывается
  `Model::localize()`/`localizeRows()` с graceful-fallback к основному языку
  при пустом поле; `Model::published/all/forHome/findPublishedBySlug` принимают
  `?string $lang`. В админ-списках — колонка «Языки» (partial
  `admin/layout/lang_badges`, данные из `Model::availableLangsForIds()`), в
  формах — вкладки перевода (`data-lang-tabs`). Одноязычны только служебные
  разделы (меню, формы, редиректы, пользователи).
- **Правило наложения перевода — одно на проект** (`Translations::overlayFields`):
  непустое переведённое значение побеждает, пустое уступает базовому языку.
  Оно было записано по разу в каждой модели (`applyTranslation`) плюс внутри
  самого `Translations`, различаясь только тем, откуда берётся список полей —
  семь копий одного правила, которые разошлись бы молча: у одной сущности
  «пусто» значило бы строку из пробелов, у другой — отсутствие ключа. Модель
  теперь называет только свои поля. `News` передаёт `trimBlank: false`: её поля
  несут HTML и JSON, и смена правила на них — это смена поведения, а не уборка.
  Разбор языков для колонки «Языки» тоже общий (`Translations::availableLangs`):
  полсотни строк с двумя `try/catch` повторялись в трёх моделях дословно, имя
  таблицы переводов берётся из `TRANSLATION_TABLES`, то есть оттуда же, откуда
  остальные ответы класса. **`Goal` намеренно осталась своей**: у неё основной
  язык добавляется всегда, без проверки заполненности базовой записи, и свести
  её с остальными значило бы поменять поведение под видом рефакторинга.
  Стережёт тест 183: он проверяет не текст запроса, а само условие — каждая
  названная колонка существует и в базовой таблице, и в таблице переводов, —
  поэтому под проверку попадает и новый вызывающий.
- **Два механизма перевода — спрашивай `App\Core\Translations`.** Кроме полей
  в `*_translations` (механизм А) языковая версия бывает **отдельной связанной
  записью** (`lang` + `translation_group_id`, механизм Б) — у новостей, страниц
  и проектов, где у версии свой slug. Код, написанный под один механизм, второй
  не замечает молча: так двуязычная новость уходила в Telegram двумя постами, а
  hreflang вёл на адрес с редиректом. `Translations::rows/langs/paths/primaryId`
  отвечают с учётом обоих; новый код обязан спрашивать там, а не собирать свою
  логику по месту. `primaryId()` — запись, от имени которой действует группа
  (очереди и счётчики адресуются ей, иначе одна новость учитывается дважды).
- Лид/описание страниц, цвета фона/текста/кнопок у блоков.
- **Команда по подразделениям**: у сотрудника сектор (`department`, верхний
  уровень) и отдел/группа (`unit`), оба переводятся. Блок `team_list` умеет
  группировать (якорь секции `#team-<slug>`, slug считается от названия на
  основном языке — ссылка одна для всех языков) и фильтровать по сектору.
  Схема оргструктуры ссылается на состав сектора строкой `Название | /стр#team-…`
  (готовую строку подставляет выбор сектора в форме блока — `App\Core\TeamAnchors`
  собирает адрес по данным команды);
  BlockHints предупредит, если группировка выключена или сектор не найден.
  Поиск по сайту ищет сотрудников и ведёт на страницу с блоком команды.
- **Ассеты, нужные не на каждой странице**, подключает `App\Core\AssetCollector`:
  `JS_MAP`/`CSS_MAP` — скрипты и стили самостоятельных блоков (выводятся после
  дизайн-CSS админки), `THEME_PART_MAP` — части общей темы, вынесенные из
  бандла (выводятся до него, чтобы настройки «Дизайна» продолжали действовать).
  Если ключ совпадает с типом блока, подключение происходит само: список типов
  страницы отдаёт `BlockRenderer::renderPage()`. Вынести новую часть темы —
  `node scripts/split-theme-part.mjs`, см. docs/PERFORMANCE_PLAN.md, раздел 2.1a.
- **Разделитель** (`divider`) — линия, короткая черта, знак-эмблема или пустое
  место. Элемент один — `<hr>`: тематический разрыв это ровно его роль, а
  обычный `<div>` без текста и картинки считался бы пустым блоком и на страницу
  не попал бы (`hr` поэтому и добавлен в список самодостаточных элементов в
  `BlockRenderer::isVisuallyEmpty`). Расстояние вокруг линии задают отступы
  секции — второй настройки того же не заводим; своя высота есть только у
  пустого места. Маска знака приезжает из scoped CSS абсолютным адресом
  (`BlockBackground::emblemUrl`): `var(--gov-emblem)` объявлена относительным
  url и из другого файла разрешается не туда — знак молча не рисуется.
- **Кнопки** (`buttons`) — до трёх действий в ряд, без карточки и заголовка (в
  отличие от «Призыва к действию» с его подложкой и одной кнопкой). Четвёртой
  нет намеренно: это уже меню, и главное действие теряется среди равных.
  **Класса `.btn` в разметке нет**: общее правило темы красит его в navy через
  `!important` и при этом не задаёт отступов — «контурная» и «ссылкой»
  превратились бы в ту же заливку с прижатым к краям текстом. Вид «основная»
  повторяет ту же кнопку своими правилами и теми же токенами. Внешняя вкладка
  получает `rel="noopener noreferrer"` и подпись для диктора.
- **Аккордеона и «Цитаты» отдельными блоками нет** — это FAQ и «Отзывы»:
  разметка (`details/summary`), скрипт и стили у них те же, и блоки-близнецы
  разъехались бы с ними при первой правке. Названия в списке добавления
  блока поэтому упоминают оба применения (стережёт тест 285).
- **Акцентная цитата** — вариант `spotlight` блока «Текст»: колонка текста и
  карточка цитаты рядом. Оформление карточки — настройки блока (фон, цвет
  текста, знак кавычки), а не константы в CSS. Пустой цвет и нулевой размер
  означают «как в теме»: у блоков, собранных раньше, вид не меняется, и своего
  scoped CSS у них не появляется вовсе.
  **Цвет текста при своём фоне считается по контрасту** (`AccentContrast::
  onFill`), а не остаётся белым: белым по светлой заливке цитаты не видно
  вовсе — 1.1:1. Явно выбранный цвет главнее подбора.
  **Знак кавычки — настоящий элемент разметки**, а не `content` у `::before`:
  псевдоэлемент умеет показать только строку, и значок из спрайта в него не
  вставить. Поэтому знаком бывает и символ из документа (« „ ❝ — любой, кегль
  под него пресетом не угадать, отсюда размер числом), и значок Tabler; у него
  свой цвет и одно из пяти положений. Диктору знак не адресован (`aria-hidden`).
  **Оформление лежит в теме, а не в `public-editorial-pages.css`.** Пока оно
  жило там под селектором `.editorial-page__content`, вариант предлагался
  редактору на любой странице, но на главной и на странице с обложкой не давал
  ничего — обычный текст и голый `blockquote`. Стережёт тест 351.
- **Диаграмма** (`chart`) — сравнение величин (полосы), доли целого (одна
  полоса из сегментов) и показатель к цели (шкала). Рисуется разметкой и CSS:
  библиотеку публичная CSP не пропустит, а картинка не переводится, не
  читается диктором и мылится на плотном экране. Данные — построчно
  «Подпись | Значение» (`App\Core\ChartData`), значение принимается как в
  документе: «5,6» и «12 400».
  **Круга и кольца нет намеренно**: доли на круге сравниваются глазом хуже,
  чем на одной полосе, а сегмент меньше пяти процентов там не читается.
  **Подпись и значение — настоящий текст рядом с полосой**, а не подсказка при
  наведении: диктор читает «Транспорт — 24 %», отдельного текстового описания
  диаграмме не нужно, а сама полоса скрыта `aria-hidden`.
  **Палитра долей — шесть фиксированных оттенков в проверенном порядке**
  (`blocks/chart.css`): соседние слоты разведены по различимости при
  дальтонизме (protan ΔE 9.1, tritan 27.0 на светлой поверхности; 8.4 и 23.8 на
  тёмной — считает `scripts/validate_palette.js` навыка dataviz), поэтому
  переставлять их нельзя. Седьмого оттенка нет: он был бы неотличим от
  занятого, и хвост сворачивается в «Прочее» (`ChartData::MAX_SERIES`). Тёмный
  набор — та же шестёрка, пересчитанная под тёмную поверхность, а не
  осветлённая автоматически. Полосы и шкала берут один тон из `--color-accent`.
  Стережёт тест 284.
- **Внешняя врезка** (`embed`) — ролик YouTube, пост Telegram или форма
  Google. Прежде вставить это мог только супер-админ блоком «HTML».
  **Источник опознаётся по ссылке** (`App\Core\EmbedSource`), а не выбирается
  полем: дубликат того, что видно в адресе, редактор рано или поздно поставит
  не тот. **Набор источников закрытый, и это главное решение**: `frame-src
  https:` в CSP пропустил бы любой домен, но произвольный iframe — это чужой
  код на странице (реклама, счётчики, перехват клика), а произвольный код у
  нас доступен только супер-админу, и в обход эта дверь не открывается. Новый
  источник добавляется в `EmbedSource::PROVIDERS` вместе с решением, что ему
  можно доверять. Пост Telegram берётся как `t.me/…?embed=1`, а не официальным
  виджетом: виджету нужен их скрипт на странице. YouTube — на домене без кук.
  **Неопознанная ссылка не выводится вовсе**: посетителю сообщение редактору не
  адресовано, а пустая рамка выглядит поломкой — причину называет подсказка
  `BlockHints` в форме. Своя высота уходит переменной в scoped CSS. Стережёт
  тест 283.
- **Изображение** (`image`) — один снимок с подписью. Прежде одиночной
  картинки было нечем поставить: «Текст с фото» требует текста,
  «Медиагалерея» — сетка, «Слайдер» — карусель. Подпись и источник рисует
  общий компонент `.media-caption`, тот же, что у галереи новости и альбома.
  **Клик делает что-то одно**: заданная ссылка отключает увеличение — два
  действия на один клик редактор не разведёт, а посетитель не угадает.
  Увеличение — это ссылка на сам файл: общий лайтбокс ищет её внутри
  известного контейнера, и блок попадает в `PHOTO_SCOPES` отдельным классом
  `.block-image--zoomable`, поэтому обычный снимок остаётся обычным. Ширины
  две — как у блоков и колонка чтения (`--editorial-reading`); «во всю ширину»
  не дублируется, это настройка секции. Стережёт тест 282.
- **Таблица** (`table`) — реквизиты, тарифы, график приёма, сравнение
  показателей. Ряды набираются **построчно**, ячейки через `|`
  (`App\Core\TableRows`): репитер «ряд с вложенным репитером ячеек» нечитаем —
  чтобы поправить одно число в таблице 6×8, редактор разворачивал бы сорок
  восемь полей. Тот же приём, что у оргструктуры и «Иконки и текста»: таблицу
  видно целиком, её можно вставить из документа и править как текст. Короткий
  ряд добивается пустыми ячейками, лишняя ячейка в длинном **не отбрасывается**
  — набранные данные молча теряться не должны. Шапка размечается
  `th scope="col|row"`, иначе диктор читает набор чисел без смысла. Широкая
  таблица прокручивается **внутри своей рамки** (`role="region"` + `tabindex`):
  горизонтальная прокрутка всей страницы ломает шапку и якорную навигацию, а
  без tabindex до прокрутки не добраться с клавиатуры. Ячейка — простой текст,
  HTML в неё не допускается. Стережёт тест 281.
- **Коллаж** (`collage`) — композиция из разнотипных элементов на общей сетке:
  фотография, плитка с числом, круглая печать и узор. Размещение хранится
  **номерами ячеек** (колонка + ширина, строка + высота), а не координатами:
  свободные X/Y нечем сложить в столбец на телефоне, и проверить их тоже
  нечем. Наложение получается тем, что два элемента занимают одни и те же
  ячейки; кто ниже в репитере — тот сверху, отдельной настройки `z-index`
  нет. Элемент, вылезающий за край полотна, **обрезается до края, а не
  переносится**: перенос сдвинул бы соседей. Правила размещения уходят в
  scoped CSS (инлайн-стили в блоках запрещены тестами), точка фокуса кадра —
  аргументом в `Media::picture`, а не своим `object-position`: рендерер
  печатает её инлайновой переменной у `<img>`, и своё правило либо проиграло
  бы ей, либо затёрло точку из медиатеки. Узоры берутся из
  `BlockBackground::PATTERNS` — второй список тех же градиентов разъехался бы
  с фоном секции. Печать всегда круглая, и диаметр считается по **меньшей**
  стороне ячейки (`min(100cqw,100cqh)`): при `aspect-ratio` с ограничением по
  высоте браузер режет только высоту, и круг становится эллипсом (замерено:
  ячейка 190×170 давала печать 190×170). Надпись по кругу собирает
  `App\Core\CollageBadge` — шаблонам запрещено носить свою геометрию в
  `<svg>`, а кегль там задан **атрибутом**: это доля диаметра в единицах
  viewBox, шкале `--step-*` она не принадлежит. На телефоне сетка складывается
  в столбец, размещение снимается `!important` (у scoped CSS вес по id).
  Стережёт тест 280.
- **Оргструктура** (`org_structure`): совет над руководителем, органы сбоку,
  ветки заместителей рядами по 2–4 колонки (ряды выравниваются: 5 веток при 4
  колонках дают 3+2), ветка без должности = подчинение руководителю напрямую.
  Есть поиск по схеме (галочка в блоке): поле приходит скрытым, открывает и
  фильтрует его `blocks/org_structure.js` — без JS схема остаётся обычным списком.
  Построчная разметка списков разбирается `App\Core\OrgTree`: **отступ в
  начале строки = уровень вложенности** (до четырёх), `Название | /url` —
  ссылка, `* Название` — акцент (проектный офис), `- Название` — прежний
  способ вложить пункт в предыдущий (читается по-старому). Число колонок ряда
  уходит в scoped CSS (инлайн-стили в блоках запрещены тестами).
- **Фирменный слой**: эмблема-гирих — маска `--gov-emblem` (файл
  `public/assets/img/emblem.svg`, заменяется в «Дизайн сайта» → настройка
  `design_emblem`, принимается только свой путь). Используется водяным знаком
  на карточках актов, заглушками карточек без фото и знаком в шапке без лого.
  Маркеры списков (10px) — упрощённая звезда через `clip-path`: настоящая
  эмблема на таком размере превращается в кашу.
  **Маске нужен viewBox.** SVG без него нечем масштабировать — знак не
  рисуется вовсе, хотя файл загружен и настройка сохранена; так же выглядит
  файл, не разобравшийся при загрузке (`Uploader::sanitizeSvgString` кладёт
  вместо него заглушку 1×1). Оба случая ловит `App\Core\Emblem::check()`:
  негодный файл не сохраняется молча, а форма «Дизайна» пишет причину.
  Загрузка достраивает viewBox по `width`/`height`, если он не задан;
  уже лежащий файл чинит `php scripts/check_emblem.php --fix`.
- **Карточки правовых актов** — вариант `acts` блока «Документы»: у документа
  появляются `number` и `date`, поиск по блоку учитывает реквизиты.
- **Оглавление страницы** — у `anchor_nav` галочки «авто» и «закреплять».
  В авторежиме разделы собираются из заголовков блоков (`BlockRenderer::
  pageSections()`, якорь = id секции); липкой делается вся секция, иначе
  `position: sticky` не работает. Подсветка раздела — `blocks/anchor_nav.js`.
- Telegram-публикация новостей, webpush, email-дайджест, формы, редиректы,
  открытые данные, календарь мероприятий, каталоги (см. ниже),
  портал репозитория файлов (`/repo`: категории с подкатегориями, загрузка

- TinyMCE в админке: цитаты, верхний/нижний индекс и базовое форматирование.
  Демо-контент запускается только из «Настройки сайта» после ввода `DEMO`.
- **Реальный контент Агентства** — фикстура `database/content/agency_content.php`
  (страницы «Об Агентстве», «Руководство», профили руководителя и первого
  заместителя на RU/UZ/EN + записи «Команды»), применяется

  руководства, а не вымышленного директора (тест 229).
- **Панель «Настройки отображения» показывает выбор одним признаком.**
  Рамка есть только у выбранной плитки (в покое она прозрачная — цвет
  добавляет выбор, а не толщину, иначе плитки съезжают на полтора пикселя),
  кольца-свечения нет, под иконкой тумблера нет плашки, а сами тумблеры —
  строки списка, а не карточки. Прежде тринадцать кнопок носили рамку
  одновременно, и выделенная среди них не читалась; панель при этом стояла на
  сером фоне страницы (`--bg-primary`), отчего белые элементы внутри выглядели
  заплатками — теперь на поверхности. Акцент в панели значит ровно одно:
  «это выбрано», поэтому иконки групп серые. Дорожки сеток объявлены
  `minmax(0, 1fr)`: у `1fr` минимум — `min-content`, и на 320px плитки уезжали
  за правый край; там же шрифт и интервалы становятся строками во всю ширину —
  «Максимальные» в колонку 74px не помещается, а разрывать слово по буквам
  хуже, чем сменить раскладку. Стережёт тест 308.
- **Настройки отображения** (`App\Core\A11ySettings`, панель `site/_a11y_panel.php`,
  `a11y.css` + `a11y.js`): выдвижная панель справа — размер текста 100–200 %,
  контраст (обычный/чёрно-белый/тёплый) плюс общий переключатель тёмной темы,
  шрифт, интервалы, режим чтения, скрытие картинок, остановка анимаций,
  подчёркивание ссылок. Состояние — cookie `a11y` в формате query-строки,
  применяется на сервере атрибутами `data-a11y-*` на `<html>` (без мигания).
  Тема живёт в своём переключателе (`window.asdrSetTheme`), в настройках не
  дублируется. Cookie прежней версии (`cw:l:on`) переносится автоматически.
  **Панель одна на сайт и портал `/repo`.** У портала была своя копия, судя по
  всему перенесённая из первой версии сайта: разбор cookie через
  `explode(':')`, атрибуты `data-a11y-scheme` и `data-a11y-size="m|l|xl"`.
  Совместимой она не была ни дня — портал и нынешний раздел доступности
  приехали одним squash-мержем (#299), и формата `cw:l:on` к тому моменту уже
  не существовало. Условие показа не срабатывало никогда —
  панель не выводилась вовсе, а кнопка «для слабовидящих» в шапке оставалась
  видимой и не делала ничего (у неё не было `data-a11y-open`, по которому
  `a11y.js` и открывает панель). Сами настройки при этом применялись — их
  доставлял `a11y.js` уже после загрузки, — то есть страница успевала
  нарисоваться обычной и прыгала в высокий контраст на глазах у того, кому он
  нужен. Экраны входа портала (`repo/login.php`, `login_2fa.php`) идут мимо
  общего макета, поэтому атрибуты и `a11y.css` им проставлены отдельно.
  Стережёт тест 348.
  **Ответ с непустыми настройками не попадает в общий кеш.** Атрибуты печатает
  сервер, значит такой ответ отличается от обычного, а `PublicResponseCache`
  выдавал `public, s-maxage` — на CDN страница посетителя с высоким контрастом
  уехала бы следующему. Видно это только без JS (`a11y.js` переставляет
  атрибуты из своей cookie), но в вопросе доступности на включённый JS
  полагаться нельзя. `Vary: Cookie` тут не годится — он фрагментирует общий
  кеш по любому значению любой cookie, включая метки аналитики: попадания
  стали бы единичными. Поэтому из общего кеша выпадает только сам такой ответ
  (`A11ySettings::isActive` → `Cache-Control: private`), а браузеру посетителя
  кешировать его по-прежнему можно.
- **Короткое название языка** (`languages.short_name`, поле «Короткое» в
  разделе «Языки»): компактный переключатель показывает «Рус»/«Oʻzb», а не код
  страницы. Пусто — берутся первые буквы названия (`Language::shortLabel()`).
- **Узбекская кириллица** (`App\Core\UzCyrillic`): переключатель письменности в
  той же панели (виден только на UZ) и отдельным пунктом «Ўзбекча» в
  переключателе языков; ссылки ведут на `/script/{latn|cyrl}?to=…`
  (`Site\ScriptController`, адрес возврата проверяется на открытый редирект). Перевод делается на готовой странице в
  `View::render` — в БД остаётся латиница, кэш блоков не множится. Не трогаются
  теги, атрибуты, script/style/code/pre, сущности, ссылки и почта, а также любой
  элемент с атрибутом `data-no-translit`.
- **«Меньше движения» — один признак на весь фронт**: `window.asdrReduceMotion()`
  (объявлен в `theme-init.js`) учитывает и системный `prefers-reduced-motion`,
  и тумблер «остановка анимаций» из панели (`data-a11y-motion="off"`). CSS гасит
  только `animation`/`transition`, поэтому фоновое видео обложки и таймеры
  автопрокрутки спрашивают помощник, а не медиазапрос, и не кэшируют ответ:
  настройку переключают на лету. Панель шлёт событие `asdr:motion-change`.
- Доступность: разметка содержит aria/skip-link и настройки контраста, а axe-аудит
  идёт в CI — `tests/browser/a11y.spec.js` проверяет главную, ленту новостей, поиск
  и узбекскую версию в светлой и тёмной темах (WCAG 2.0/2.1/2.2 A и AA), на десктопе
  и на мобильном; кроме них — детальная новость, проект, каталог и страница с
  формой (там нарушений больше всего). Ручная проверка остаётся за тем, что axe
  не умеет: порядок табуляции, осмысленность alt и формулировок для диктора.
