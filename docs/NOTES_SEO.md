# SEO: исходный код, микроразметка, индексация

Заметки о проекте, вынесенные из `CLAUDE.md`: там — карта и ключевые правила,
здесь — подробности и причины решений. Читать при работе над темой.

### Исходный код публичной страницы (`App\Core\HtmlFormatter`)
«Просмотр кода страницы» — публичное лицо сайта не меньше самой страницы: в
разметку смотрят ведомственные проверки и интеграторы. Собирают её три
источника с разными привычками — шаблоны с ручными отступами, PHP-конкатенация
(шапка, меню, блоки: целый узел в одну строку) и кэш блоков, — поэтому рядом с
аккуратным `<head>` лежала строка меню длиной в несколько экранов.
Форматтер **не переписывает разметку** — он двигает только пробелы, и только
там, где их не видно: перевод строки вставляется, лишь когда с одной из сторон
стоит тег **блочного** элемента (пробел рядом с блочным боксом браузер
убирает, а во flex/grid пробельный узел вообще не рождает бокса). Между
строчными элементами нового пробела не появляется никогда: `</a><a>` осталось
бы склеенным, а вставленный перенос — это видимый зазор в меню. Уже
существующий пробел нормализуется свободно (в обычном тексте любой набор
схлопывается в один), содержимое `script`, `style`, `pre`, `textarea` и `svg`
не трогается вовсе. Отсюда инвариант, который проверяет тест 306: вывод
отличается от входа **только** пробелами у блочных границ (плюс фаззинг
случайных деревьев при разработке). Замерено: разметка тяжелеет на ~17 %
сырой и на ~2.6 % после сжатия, время — 1.5 мс на 70 КБ. Спрайт иконок
`Icon::injectSprite` раскладывает `<symbol>` по строкам (в SVG этот пробел
незначим) — одной строкой он и был главной простынёй. Аварийный выключатель —
«Производительность» → «Форматировать исходный код публичных страниц»
(`perf_pretty_html`): преобразование трогает каждый публичный ответ, и снимать
его владелец должен без правки кода.

### Микроразметка (`App\Core\SchemaOrg`)
Уже есть: `GovernmentOrganization` в шапке каждой страницы
(`SeoHelper::organizationSchema`), `BreadcrumbList` в крошках, `NewsArticle` на
странице новости, `Event` у мероприятия, Open Graph и Twitter Card
(`OpenGraphHelper`), полный `hreflang` с `x-default`. Отдельного метода
`SchemaOrg::organization()` в бою нет — его место занял `SeoHelper`
(сверяет тест 171).
**Описание страницы не бывает пустым.** `<meta name="description">` печатался
только при заполненном поле, и главная годами уходила в поиск без него — при
написанном лиде. Цепочка теперь: своё поле → лид → первый содержательный
абзац содержимого (`SeoHelper::autoDescription`, обрезка по границе слова) →
`default_meta_description`. Пустое описание — это не «ничего»: поиск всё равно
соберёт сниппет, но из случайного куска страницы.
**`og:locale:alternate`** объявляет те же языки, что и `hreflang` (список уже
отфильтрован по наличию перевода): `hreflang` читает поиск, `og:locale:alternate`
— соцсети и мессенджеры, собирающие карточку ссылки. **`article:published_time`
и `article:modified_time`** ставит страница новости; разметка для них была
написана давно, но `$publishedAt` никто не задавал, и обе даты не выводились
ни разу. Даты считает `DateFormatter` (ташкентское время; `date(strtotime())`
роняла бы страницу на неразобранной дате). **`sameAs`** в схеме организации
берётся из соцкнопок конструкторов шапки и подвала — второй список ссылок
разъехался бы с ними при первой правке. **`WebSite` с `SearchAction`**
(`SeoHelper::websiteSchema`) выводится **только на главной**: разметка
описывает сайт целиком, на каждой странице она повторяла бы одно и то же.
Стережёт тест 306.
**`FAQPage` выводит блок «Вопросы и ответы»**, и на страницу он допускается
ровно один: два таких блока дали бы две разметки, а поисковик отбрасывает обе.
Право забирает первый блок (`SchemaOrg::claimFaqPage`), флаг сбрасывает
`BlockRenderer::renderPage` вместе со счётчиком h1 — иначе вторая страница в
одном процессе осталась бы без разметки. Ответ кладётся **текстом**: HTML в
JSON-LD не допускается, а тег между словами заменяется пробелом, иначе
«форму&lt;br&gt;или» склеивается в одно слово. Пара без вопроса или без ответа
пропускается: неполную разметку поисковик отбрасывает целиком.

**Canonical — путь плюс закрытый список параметров** (`SeoHelper::canonicalUrl`,
`CANONICAL_PARAMS` = `category`, `page`, `mtab`, `mpage`, `m`). Прежде в него
шёл только путь, и каждый адрес с параметром объявлял себя дублем: `/news?page=7`
вело на `/news`, а у рубрикатора новостей (`?category=<slug>`) не было в выдаче
ни одного индексируемого адреса вовсе. Ссылки `rel="prev|next"` это не
компенсируют — как сигнал индексации поиск их больше не использует. Обратное
тоже неверно: пускать в canonical всю query-строку значит плодить адрес на
каждую метку кампании (`utm_*`, `fbclid`) и на каждый порядок сортировки,
поэтому список закрытый. Чего в нём нет намеренно: `sort` (те же записи в
другом порядке — это и есть дубль), `q` (свободный ввод, значений бесконечно),
`token`/`to`/`format` (служебные). Первая страница списка приводится к голому
адресу (`page=1` и `mpage=1` снимаются): `/news` и `/news?page=1` — побайтно
одна страница. Порядок параметров нормализуется по списку, а не по приходу:
иначе `?page=2&category=x` и `?category=x&page=2` получили бы два разных
canonical и один набор записей сам стал бы дублем. Стережёт тест 347.

### Проверка индексации (раздел «Поиск и индексация»)
`App\Core\Seo\SeoAudit` отвечает на вопрос «почему страница может не попасть в
поиск» — и это не отчёт поисковой системы, а причина, по которой отчёт будет
плохим: Google и Яндекс показывают следствие с задержкой в сутки-трое, здесь
причина видна сразу и **без единого ключа доступа**. Часть проверок считается
по базе (карта сайта, описания, дубли заголовков, редирект поверх живой
страницы), часть требует HTTP-обхода своего сайта — и таких ровно столько,
сколько нужно: `robots.txt`, `sitemap.xml` и выборка из
`SeoAudit::SAMPLE_SIZE` живых адресов. **Полного обхода тут нет намеренно**:
noindex и чужой canonical — системные ошибки, они либо есть у всех страниц
типа, либо нет ни у одной, а полный обход на каждый запуск cron — это часы
работы ради тех же выводов (обходом занимается `scripts/smoke.php`).
`SeoAudit::SITEMAP_NEWS_LIMIT` обязан совпадать с `LIMIT` в
`SitemapController`: карта обрезает новости молча, без ошибки, и проверка
существует ровно ради этого случая (стережёт тест 286). Снимки ложатся в
`seo_audits` (модель `App\Models\SeoAudit`, хранение 90 дней) — история
отвечает на первый вопрос по любой находке: «это новое или так было всегда».
Запуск — `app/Console/seo_worker.php` по cron (ненулевой код возврата при
ошибках) и кнопкой в `/admin/seo` (только супер-админ: проверка ходит по сети
от имени сайта).
