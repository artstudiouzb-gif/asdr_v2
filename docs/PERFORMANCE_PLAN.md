## Приоритет 1 — критичное, отдача за часы

### 1.1. Глобальный `transition` на `div` и `span`

`public/assets/css/gov-theme.css:62`

```css
body, header, aside, section, div, footer, input, select, textarea, button, a, span {
    transition: background-color 0.35s ease, color 0.35s ease, border-color 0.35s ease, box-shadow 0.35s ease;
}
```

Правило доезжает до собранного `public.min.css` (проверено). Это самый дорогой
селектор на сайте: браузер заводит четыре анимируемых свойства **на каждый
`div` и `span` документа** — на типовой странице это тысячи элементов. Следствия:

- любое переключение класса (`is-scrolled` у шапки при скролле, `is-open` у меню,
  смена темы, открытие a11y-панели) запускает переходы по всему поддереву;
- `box-shadow` в списке — анимация тени всегда идёт через перерисовку, а не
  композитор; на больших контейнерах это перекраска целого экрана;
- смена темы вместо мгновенной становится 350-мс перекраской всего документа —
  это и есть «подтормаживание» тумблера темы.

**Что сделать.** Убрать правило. Плавность смены темы вернуть временным классом
на `<html>` (`theme-init.js` / `asdrSetTheme` вешает `.is-theme-switching` на
350 мс), а точечные переходы оставить там, где они осмысленны — кнопки,
карточки, ссылки, поля ввода:

```css
:root.is-theme-switching, :root.is-theme-switching * {
    transition: background-color .3s ease, color .3s ease, border-color .3s ease;
}
a, button, .btn, [class*="-card"], input, select, textarea {
    transition: background-color .2s ease, color .2s ease, border-color .2s ease, box-shadow .2s ease;
}
```

**Ожидаемый эффект.** Оценочно: главный вклад в INP и в стоимость скролла;
самая дешёвая правка с самым заметным результатом. Мерить `INP` и «Avoid
non-composited animations» в Lighthouse.

**Риск.** Средний: часть плавностей визуально пропадёт. Пройти smoke + глазами
проверить шапку, меню, карточки, тумблер темы, a11y-панель.

### 1.2. `Vary: Cookie` убивает общий CDN-кэш

`app/Core/PublicResponseCache.php:71`

```php
header('Vary: Accept-Encoding, Cookie');
```

Публичная часть ставит cookie `a11y` — это `http_build_query()` от нормализованных
настроек (`A11ySettings::COOKIE`, `:127`): размер текста, контраст, шрифт,
интервалы, режим чтения, скрытие картинок, остановка анимаций, подчёркивание
ссылок. Плюс `site_lang`, плюс возможная сессия. При `Vary: Cookie` каждое
уникальное сочетание cookie — **отдельная запись в CDN**. Практически это
означает, что `s-maxage=300` почти не работает: разогретого кэша нет ни у кого.

Комментарий в коде объясняет `Vary: Cookie` необходимостью не отдавать
закэшированную языковую копию мимо редиректа в `Router::resolveLocale()`. Задача
настоящая, но решается точнее.

**Что сделать (варианты, по возрастанию сложности):**

1. Сузить ключ до языка. На BunnyCDN/Cloudflare — cache key по cookie `site_lang`,
   а `Vary` оставить `Accept-Encoding`. Настройка на стороне CDN, кода не трогает.
2. Убрать язык из cookie-зависимости ответа: язык уже в URL (`/ru/…`, `/uz/…`),
   а `site_lang` влияет только на редирект с «голого» пути. Тогда кэшируемым
   делать только локализованные URL, а `/` (где происходит выбор языка) отдавать
   `private, no-store`. Это правильный по существу вариант.
3. a11y-настройки перевести с cookie на `localStorage` + применение классов
   в `theme-init.js` (он уже синхронный в `<head>`, мигания не будет). Тогда
   cookie на публичке остаётся только языковой. Требует переноса
   `A11ySettings::htmlAttributes()` с сервера на клиент — самый большой объём.

Рекомендация: сделать (2), настроить (1) на CDN, (3) вынести в отдельную задачу.

**Ожидаемый эффект.** TTFB для повторных посетителей и для краулеров падает до
времени отдачи с edge вместо полного PHP-цикла. Это самая большая цифра во всём
плане для реального боевого трафика.

### 1.3. 280 КБ неминифицированных ассетов у блока «Мониторинг 2030»

`public/assets/css/blocks/u30-report.css` (160 КБ, средняя длина строки 22
символа — исходное форматирование) и `public/assets/js/blocks/u30_report.js`
(120 КБ). В `scripts/build-assets.mjs` они не упоминаются вообще
(`grep -c u30` = 0), в `asset-manifest.json` их нет.

**Что сделать.** Расширить `build-assets.mjs` вторым, «поблочным» проходом:
каждый файл из `AssetCollector::CSS_MAP`/`JS_MAP` минифицируется в
`*.min.css`/`*.min.js`, хэши уходят в манифест, `AssetCollector` отдаёт
минифицированный путь, когда `FrontendAssets::enabled()`. Заодно это чинит
`npm run check:assets`: сейчас проверка актуальности этих файлов не покрывает.

**Ожидаемый эффект.** ~35–40 % от raw и ~20 % от gzip — на странице отчёта
минус ~10 КБ по сети и заметно меньше времени парсинга CSS/JS.

**Риск.** Низкий. u30-блок уже изолирован в `#uz2030-report`.

### 1.4. Тело статьи рендерится дважды на каждой новости

`app/Views/site/news_show.php:689` — оверлей режима чтения выводится
**безусловно** (только с атрибутом `hidden`), и внутри него на `:731` повторно
печатается `$contentHtml`, на `:719` — обложка, на `:710` — второй `<h1>`.

Следствия: удвоенный HTML и удвоенное число DOM-узлов на всех новостях (а это
самые посещаемые страницы) плюс лишний `<img>` без `width/height` и без
`loading="lazy"`.

Второй `<h1>` при этом **не** является ошибкой доступности: пока оверлей
закрыт, он под атрибутом `hidden` и в дерево доступности не попадает, а когда
открыт — соседние узлы получают `inert` (`setReaderIsolation`), и из дерева
уходит основной заголовок. В каждый момент экспонирован ровно один `h1`. Это
сделано аккуратно, трогать не нужно.

**Что сделать.** Тело статьи (основная масса разметки) из оверлея убрать и
клонировать из основной статьи при первом открытии — `frontend.js:1778` уже
держит ссылку на оверлей. Заголовок, подзаголовок и лид оставить в разметке:
это несколько сотен байт, а клонирование их усложнило бы код без выигрыша.
Обложку внутри оверлея пропустить через `Media::picture()` с `lazy`.

**Ожидаемый эффект.** HTML новости примерно вдвое меньше; меньше DOM →
дешевле стиль и layout. Без JS режим чтения и так не работает, так что
прогрессивное улучшение не нарушается.

## Приоритет 2 — структурное, отдача за дни

### 2.1. Разрезать общий CSS-бандл

Точная разметка `gov-theme.css` по верхнеуровневым правилам (1834 правила, 331 КБ):

42 КБ стилей детальной новости приезжают на главную, где ни одного из этих
классов нет. Механизм для исправления в проекте уже есть и работает —

**Что сделать поэтапно:**

1. Вынести `newsdetail`/`relnews` в `blocks/news-detail.css` и подключать из

2. Тем же способом вынести `team/person/bio`, `альбом/галерея`, календарь,

3. Целевой «ядровой» бандл: токены + типографика + шапка/подвал + сетки +
   базовые карточки. Ориентир — **не более 30 КБ brotli**.

**Ожидаемая цель.** 53,6 → ~30 КБ brotli на типовой странице, и, что важнее,
419 КБ → ~200 КБ несжатого CSS для парсинга и построения CSSOM. На слабых
Android-устройствах парсинг CSS — заметная доля времени до первой отрисовки.

**Риск.** Средний: легко потерять правило, которое кто-то использует вне
ожидаемого контекста. Обязательно — `scripts/smoke.php` по всем публичным

### 2.2. Бюджет CSS в CI, чтобы бандл не отрастал обратно

`scripts/build-assets.mjs:36` — бюджет `cssBrotli: 80 * 1024`, и превышение
печатается предупреждением, а не падает. Комментарий рядом честно объясняет,

**Что сделать.** Вернуть жёсткий порог, но не для всего бандла, а для ядра
(после разреза по 2.1): ядро — блокирующий бюджет, блочные файлы — отдельные
мягкие бюджеты. Порог опускать по мере чистки, а не задирать под факт.

### 2.3. Индексы для публичных выборок

Проверено по `database/schema.sql`:

- `projects` — есть только `uq_projects_slug_lang` и `idx_projects_lang_group`.
  Публичные выборки (`Project.php:267,291,301`) идут по
  `status = 'published' AND deleted_at IS NULL ORDER BY sort_order, created_at, id`
  → полный скан + filesort.
- `photo_albums` — только `uniq_albums_slug`; листинг сортируется по
  `created_at DESC, id DESC`.
- `videos` — то же, сортировка `sort_order, created_at, id`.
- `news` — `idx_news_status_published (status, published_at)` есть, но
  `deleted_at IS NULL` вне индекса.

Миграция:

```sql
ALTER TABLE projects     ADD KEY idx_projects_listing (status, deleted_at, sort_order, created_at);
ALTER TABLE photo_albums ADD KEY idx_albums_listing   (status, created_at);
ALTER TABLE videos       ADD KEY idx_videos_listing   (status, sort_order, created_at);
ALTER TABLE news         DROP KEY idx_news_status_published,
                         ADD KEY idx_news_listing     (status, deleted_at, published_at);
```

Не забыть: колонки и файл миграции добавить в `database/schema.sql` (и в
`INSERT INTO migrations`), иначе падает тест консистентности.

**Честная оценка эффекта.** При нынешних объёмах контента — единицы миллисекунд.
Делать стоит как страховку на вырост: сейчас это одна дешёвая миграция, через
год при тысячах записей — уже инцидент.

### 2.4. `content-visibility` для длинных страниц

В публичном CSS нет ни одного `content-visibility`/`contain`. Страницы отчёта
2030, оргструктуры, ленты новостей и альбомов — длинные, и браузер считает
layout и paint для всего, что ниже экрана.

```css
.cms-block { content-visibility: auto; contain-intrinsic-size: auto 600px; }
```

Важно: **не вешать** на первый блок страницы (LCP-кандидат) и на элементы,
участвующие в якорной навигации без `contain-intrinsic-size` — иначе поедет
позиция скролла и подсветка разделов в `blocks/anchor_nav.js`. Проверить работу
оглавления и якорей `#team-<slug>` после включения.

### 2.5. Разгрузить композитор

- 34 `backdrop-filter` и 32 `filter: blur()`. Дороже всего — размытие на
  **липкой** шапке, и оно там есть: `gov-theme.css:449, 458` —
  `backdrop-filter: blur(20px) saturate(180%) !important` у
  `.site-header--container-floating` в обеих темах. Пока шапка на экране,
  браузер на каждом кадре скролла заново размывает всё, что под ней. Это
  самый дорогой отдельный эффект на сайте после правила 1.1.
  Заменить на полупрозрачный фон через `color-mix` (бренд-акцент не
  хардкодить — правило проекта) либо оставить размытие, но снизить радиус до
  8–10 px и убрать `saturate()`, который удваивает стоимость фильтра.
  Если размытие решено сохранить — обязательно проверить на реальном
  Android-устройстве, а не в headless-Chromium.
- `public/assets/css/gov-theme.css:5303–5310` — `moon-star-twinkle` у
  `.site-theme-toggle .theme-star--1/2` идёт **постоянно**, не под `:hover`
  (в отличие от соседних `sun-rays-spin` и `eye-pupil-pulse`, которые
  корректно ограничены наведением). Элемент виден в шапке всегда → композитор
  никогда не простаивает. Ограничить `:hover`, как у соседей.
- `will-change` встречается ровно 1 раз — это правильно, наращивать не нужно.

### 2.6. `theme-init.js` в `<head>` — ОТКЛОНЕНО

Первоначально предлагалось инлайнить этот скрипт с CSP-nonce, чтобы убрать
один запрос из `<head>`. **Реализовано и откачено.**

Тест 171 (`tests/cases/171_inline_script_semantics_test.php`) явно требует
`assert_not_contains('<script nonce=', $header)`: публичная шапка не держит
исполняемых инлайн-скриптов даже с nonce. Это осознанное решение по
безопасности — нонс в `<head>`, где выводятся `site_name`, meta и OG-значения,
делает инъекцию в шапку заметно опаснее.

Цена отказа мала: файл отдаётся с `Cache-Control: immutable`, идёт первым в
`<head>` по уже открытому HTTP/2-соединению, весит 1227 байт. Выигрыш не
стоит ослабления CSP. В коде оставлен комментарий, объясняющий, почему скрипт
обязан быть одновременно синхронным и внешним, — чтобы это не «оптимизировали»
повторно.

### 2.7. Условный `304` для HTML

Дисковый кэш страниц уже есть (`Cache`, ключ `page:<id>:<lang>`), у файла есть
`mtime`. Отдавать `Last-Modified`/`ETag` и отвечать `304` на `If-None-Match`
дёшево и полностью снимает передачу тела при повторных заходах. Аккуратно:
CSRF-токен и `hp_ts` подставляются в HTML на каждый запрос
(`PageController.php:98–108`), поэтому ETag можно считать только по странице
**без форм** — иначе второй посетитель получит чужой токен. Проще всего:
включать условный ответ только когда в HTML нет `name="csrf_token"`.

## Приоритет 3 — дизайн-система и UI/UX

Это раздел про качество, а не про килобайты, но именно он определяет, почему
дальнейшие правки CSS будут дешёвыми или дорогими.

### 3.1. Шкалы нет — отсюда 473 `!important`

Измеренная картина: **196** разных `font-size`, **307** разных значений
отступов, **171** тень, **58** радиусов — при том что `--radius: 12px` в
`:root` объявлен. В списке размеров рядом стоят `.93rem`, `.95rem`, `.96rem`,
`.98rem`, `1.02rem`, `1.025rem`, `1.05rem` — это не решения, а следы ручной
подгонки отдельных компонентов.

Прямое следствие — 473 `!important` в `gov-theme.css`: когда у компонентов нет
общего словаря, единственный способ «победить» соседнее правило — повысить
приоритет. Дальше каждая новая правка требует ещё одного `!important`.

**Что сделать.**

1. Ввести токены в `:root` рядом с существующими:

```css
:root {
  --step--1: clamp(0.83rem, 0.80rem + 0.15vw, 0.89rem);
  --step-0:  clamp(1.00rem, 0.96rem + 0.20vw, 1.13rem);
  --step-1:  clamp(1.20rem, 1.13rem + 0.35vw, 1.42rem);
  --step-2:  clamp(1.44rem, 1.32rem + 0.60vw, 1.80rem);
  --step-3:  clamp(1.73rem, 1.54rem + 0.95vw, 2.27rem);
  --step-4:  clamp(2.07rem, 1.78rem + 1.45vw, 2.86rem);

  --space-3xs: 0.25rem; --space-2xs: 0.5rem; --space-xs: 0.75rem;
  --space-s: 1rem;      --space-m: 1.5rem;   --space-l: 2rem;
  --space-xl: 3rem;     --space-2xl: 4rem;   --space-3xl: 6rem;

  --radius-s: 8px; --radius-m: 12px; --radius-l: 20px; --radius-full: 999px;
  --shadow-1: 0 1px 2px rgb(15 23 42 / .06), 0 1px 3px rgb(15 23 42 / .10);
  --shadow-2: 0 4px 12px rgb(15 23 42 / .08);
  --shadow-3: 0 12px 32px rgb(15 23 42 / .12);
}
```

Значения `clamp()` в проекте уже применяются (164 вхождения) — это продолжение
существующей практики, а не новая парадигма.

2. Переводить на токены **по одному компоненту за коммит**, начиная с самых
   заметных: карточки → шапка/подвал → карточки новостей → страницы персон.
   Каждый такой коммит обязан уменьшать счётчик `!important`, а не увеличивать.
3. Завести тест-сторож по образцу существующего теста 232 (он уже стережёт
   шкалу брейкпоинтов): считать в публичном CSS количество `!important` и
   уникальных `font-size`, падать при росте. Порог опускать по факту чистки.
   Это ровно тот приём, которым в проекте уже удержали брейкпоинты после
   схлопывания 33 значений в 8.

### 3.2. CLS от подмены шрифта

Шрифты подключены грамотно (`font-display: swap`, `unicode-range`, preload
только выбранных семейств), но метрики фолбэка не подогнаны:
`size-adjust`/`ascent-override` в публичном CSS отсутствуют полностью
(есть только в `admin.css`, одно вхождение). При `swap` это гарантированный
сдвиг макета в момент подмены — на кириллице с PT Sans/Serif он заметен.

**Что сделать.** Для каждого дефолтного семейства добавить fallback-фейс с
подогнанными метриками:

```css
@font-face {
  font-family: 'PT Sans Fallback';
  src: local('Arial');
  size-adjust: 97%;      /* подобрать замером */
  ascent-override: 92%;
  descent-override: 24%;
  line-gap-override: 0%;
}
```

и подставлять его первым фолбэком в `--font-family` / `--font-heading`.
Проценты подбирать по факту, а не переносить из примера.

### 3.3. Тач-цели и фокус

- `min-height/min-width: 44px|48px` встречается **16 раз** на весь публичный
  CSS. Для госсайта — мало. Пройти мобильную вёрстку: переключатель языков,
  тумблер темы, кнопка a11y, бургер, пагинация, ссылки в подвале, вкладки
  «Видео/Фото» в медиа-галерее. Норма WCAG 2.2 (2.5.8, AA) — 24×24 CSS-px
  минимум; практический ориентир для госсайта — 44×44.
- `outline: none` / `outline: 0` встречается в 8 местах, часть — с
  `!important` (`gov-theme.css:1014, 1032`). В каждом случае проверить, что
  фокус заменён видимой альтернативой (`box-shadow`-кольцо), а не убран.
  `:focus-visible` в теме используется (45 вхождений в `gov-theme.css`), но
  в `public-layout-polish.css` и `public-editorial-pages.css` — ноль.
- В `frontend.css` четыре `outline: none` (строки 490, 917, 1211, 1485) —
  проверить прицельно.

### 3.4. Уважение к `prefers-reduced-motion`

`prefers-reduced-motion` учтён 36 раз, но неравномерно: `gov-theme.css` — 22,
`frontend.css` — 13, а в `public-layout-polish.css` и
`public-editorial-pages.css` — **0** при 22 и 23 `clamp()`-анимациях
соответственно. Проверить, что новые эффекты из свежих дизайн-коммитов
(`#106`, `#107`, `#111`) отключаются и по системной настройке, и по тумблеру
«остановка анимаций» в панели отображения.

### 3.5. Разметка и семантика

- `templates/blocks/partners.php:32` — `<img src="">`. Пустой `src` заставляет
  браузер повторно запрашивать текущую страницу. Убрать или отдавать заглушку.
- Изображения без `width/height` вне `Media::picture()`:
  `app/Views/site/_header.php:74, 82, 825` (логотипы),
  `_footer.php:60`, `news_show.php:290, 325, 719`,
  `templates/widgets/latest_news.php:18`, `_search_suggest.php:20`,
  `templates/blocks/u30_report.php:47`. Логотип в шапке — участник первого
  экрана, его сдвиг попадает прямо в CLS. Плюс отдельные грабли проекта:
  SVG-логотип без пиксельных размеров схлопывается, явная `height` обязательна.
- Обложка режима чтения переведена на `Media::picture()` в рамках правки 1.4;
  остальные из списка выше — открытая работа.

### 3.6. UX-проверки, которые стоит пройти руками

Аудит кода их не закрывает, но для госсайта они обязательны перед релизом:

- Мобильное меню: доступность с клавиатуры, ловушка фокуса, закрытие по `Esc`,
  возврат фокуса на бургер.
- Панель отображения (a11y): все 8 настроек в комбинациях с UZ-кириллицей и
  тёмной темой; проверить, что текст не обрезается при 200 %.
- Формы: видимость ошибок без цвета, `aria-describedby` у полей с ошибкой,
  поведение капчи при отключённом JS.
- Поиск: состояние «ничего не найдено», подсказки с клавиатуры.
- Печать: `public-content-modes.css` — прогнать печать новости и страницы.
- axe-аудит: сейчас он вне CI и остаётся ручным. Подключить `@axe-core/playwright`
  к существующему browser-smoke — это одна зависимость и один шаг в джобе,
  которая уже поднимает Chromium.

## 4. Что осознанно **не** делаю

- **Замена статических начертаний на вариативные шрифты.** Manrope сейчас —
  4 веса × 2 подмножества (~150 КБ), вариативный дал бы ~40 КБ. Но семейство
  выбирается в админке, а `LocalGoogleFonts` рассчитан на статические файлы:
  выигрыш есть, объём работы непропорционален. Отдельная задача.
- **AVIF в дополнение к WebP.** Экономия ~20–30 % к WebP, но требует расширения
  `ImageBatchOptimizer`, третьего `<source>` в `Media::picture()` и
  перегенерации всей медиатеки. Стоит делать после раздела 1–2.
- **Service Worker для офлайн-кэша.** `push.js` уже есть, но кэширующий SW на
  госсайте с частым обновлением контента — источник инцидентов «пользователь
  видит вчерашнюю новость». Не рекомендую.
- **Отказ от `SELECT *`** (124 вхождения в моделях). Косметика: строки узкие,
  выигрыш в пределах шума, а риск задеть `localize()` реальный.

## 6. Как мерить

Без этого раздела остальные — вера, а не инженерия.

**Перед началом** зафиксировать базу на боевом `asr.artstudio.uz`:

```bash
# Размеры бандлов (уже считает сборка)
npm run build:assets            # печатает raw/gzip/brotli и бюджеты

# Что реально приезжает на конкретную страницу
npx lighthouse https://asr.artstudio.uz/ru \
    --preset=desktop --output=json --output-path=baseline-desktop.json
npx lighthouse https://asr.artstudio.uz/ru \
    --form-factor=mobile --throttling-method=simulate \
    --output=json --output-path=baseline-mobile.json
```

Ключевые числа для протокола: **LCP, INP, CLS, TBT**, «Unused CSS» (покажет
эффект разреза бандла), «Avoid non-composited animations» (покажет эффект 1.1),
TTFB на повторном заходе (покажет эффект 1.2).

**Полевые данные важнее лабораторных.** У сайта уже есть `Analytics` — добавить
отправку `web-vitals` (2 КБ) в существующий эндпоинт и смотреть 75-й перцентиль
по реальным посетителям. Без этого мобильный сегмент — вслепую.

**После каждой правки** — обязательный минимум проекта:

```bash
TEST_DB_HOST=127.0.0.1 TEST_DB_DATABASE=asdr_test TEST_DB_USERNAME=root \
  TEST_DB_PASSWORD= php tests/run.php
php scripts/smoke.php http://127.0.0.1:8000 --admin admin:ПАРОЛЬ --totp СЕКРЕТ
npm run check:assets
rm -rf storage/cache/page/*
```

Для правок 1.1, 2.1 и 2.4 к этому добавляется визуальная сверка: главная,
детальная новость, лента новостей, альбом, страница команды, оргструктура,
отчёт 2030 — в светлой и тёмной теме, RU и UZ, на 375 / 768 / 1440 px.
